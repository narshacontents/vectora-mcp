# 발표 화면 위 발언 네이티브 실행

발표자 한 명의 발언이 화면 위에 있고 자료판이 아래에 오는 화면형 발표에만 적용한다. 지원되는 경우 `layout:"presentation"`, `mode` 또는 `presentationMode:"screen"`, `presentationOptions.layout:"speech-above-board"`를 사용한다. 실제 문구를 먼저 실측하고 말풍선·자료판의 폭을 정한 뒤, 검수한 발표자 원화와 자료를 포함해 컴포넌트를 생성한다. `speechWidthMm`·`boardWidthMm`과 간격 옵션은 전체 구도에 맞춰 계획하고 실시간 스키마의 허용 범위를 따른다. 이 배치에는 흉상 또는 전신과 바깥쪽 이름을 사용한다. 얼굴 단품·아래 이름·연단 병용은 다른 지원 배치를 선택한다. 화면 내용은 `screenText`·`screenGraph`·`screenComponent` 중 하나로 지정한다. `screenComponent`가 공개된 앱에서는 칠판의 제목·본문·내부 표를 소유하는 네이티브 컴포넌트를 이 필드에 넣는다. 해당 자식의 외피가 자료판 전체이므로 가는 사각형이나 별도 흰 덮개를 겹쳐 추가하지 않는다. `boardWidthMm`는 자식 외곽의 폭이며, 사용자가 내부 폭을 고정하지 않았다면 자식 폭은 슬롯에서 상속한다.

사용 전 현재 `vectora://production/dialogue/schema`와 `vectora://production/dialogue`에서 이 필드와 화면 배치 지원을 확인한다. 추가 필드 허용이나 앱 소스만으로 지원을 판단하지 않는다. 공개되지 않은 옵션은 보내지 않고 지원되는 화면형 발표 경로를 사용하며, 지원되지 않는 구도나 편집 제약은 구별해 기록한다.

`awaiting-approved-artwork` 계획의 높이는 실제 원화 배치 결과가 아니다. 등록 원화를 사용한 생성 결과에서 자료판과 가시 인물의 상·하단, 바깥 이름을 포함한 폭을 첫 내보내기 전에 대조한다. 원화 재사용 시에도 임의의 머리 폭 하나로 크기를 확정하지 않고, 실제 가시 종횡비와 제목·단위·범례까지 포함한 자료 높이를 함께 계산한다. 자료가 주인 장면에서는 인물의 비중을 보조로 유지하며 자료판 폭·그래프 높이·비례 인물 크기를 함께 조정한다. 한쪽 아래만 크게 비면 자료의 불필요한 제목/축 설명·여백, 판과 인물의 폭 배분을 소유 spec에서 재계획한다. 필수 내용·수치를 빼거나 인체를 늘여 맞추지 않는다. 승인 원화로 해당 공간 관계를 만족시킬 수 없으면 다른 신체 범위의 원화가 필요한 상태로 구별한다.

자료판의 목표 높이는 **실제 제목·본문·내부 자료와 필요한 안쪽 여백**으로 먼저 구한다. **원화 생성 전에** 이 높이와 인물 슬롯을 확정한다. 짧은 자료판에는 허리 위/흉상을 먼저 검토하고, 미리 생성한 긴 전신을 판 높이에 축소해 얼굴까지 작아지게 하지 않는다. 단독 한 줄 발언은 할당된 글상자 폭이 아니라 실제 글의 진행 폭과 안쪽 여백으로 말풍선 폭을 정한다. 자료판 기준 구도는 판 높이에 맞는 신체 범위·가시 종횡비로 원화를 요청한다. `portraitHeightMm`을 지원하면 목표 가시 높이를 사용하고, 더 우선하는 `headWidthMm`을 동시에 넣지 않는다. 읽을 내용이 끝난 뒤 판 아래가 넓게 남으면 인물의 고정 머리 폭 때문에 판 높이가 늘었는지 확인한다. 인물과 판의 하단이 같다는 이유만으로 빈 판을 채택하지 말고, 흉상/허리 위 등 자연스러운 신체 범위와 폭 배분을 다시 계획한다.

단독 한 줄 말풍선과 읽을 수 있는 큰 발표자, 자료판 장식 위 겹침이 동시에 필요하면 실행 경로의 실제 제약을 먼저 확인한다. 말풍선 높이에 인물 높이를 강제로 맞추는 경로나 판과 말풍선의 분리를 강제하는 경로에 맞추려고 구도를 훼손하지 않는다. 지원되는 독립 자료판·발언 컴포넌트를 조합할 수 있으며, 내부 내용은 각각 편집 가능하게 보존한다. 이 경우 바깥 이름·꼬리·인물/판 하단 정렬까지 계획하고 자료를 가리지 않는 범위만 겹친다. 컴포넌트 사이 배치가 자동 연동되지 않으면 그 범위를 명시하고 내용 변경 뒤 다시 검수한다.

발언이나 화면 본문·표 셀을 바꾸면 같은 네이티브 소유 관계 안에서 갱신한다. 자료판 높이가 달라질 때 명시된 `portraitHeightMm`은 자동 높이 연결이 아니므로, 새 자식 plan으로 가시 높이를 다시 구하고 필요하면 같은 소유 spec에서 비례 크기를 함께 갱신한다. 인물·바깥 이름의 폭도 다시 확인하며, 판만 커진 상태나 인체를 늘인 결과를 완료로 받지 않는다. `screenComponent` 안의 표·본문도 독립된 수동 위치 개체로 꺼내지 않는다. 글 수정 시 줄바꿈·외피 높이·말풍선 경계를 함께 갱신하고, 개별 요소를 따로 밀어 맞추지 않는다. 갱신 뒤 실제 말풍선·자료판 폭, 이름의 글자 획, 흰 내용 면의 잘림·가림과 발표자/자료판의 정렬을 확인한다.

가리키는 인물은 원화의 손끝과 판 가장자리 간격을 별도로 확인한다. 지원되는 `portraitGapMm`과 `boardWidthMm`를 실제 가시 외곽에 맞춰 계획하고 큰 고정 인물 칸을 남기지 않는다. `screenComponent`의 명시 간격을 실제 칠판 외곽과 인물 영역 사이에 적용하는 앱에서는 그 간격으로 배치하고, 손끝까지 남는 원화 내부 여백은 따로 확인한다. 해당 계약이 없는 화면형에서는 옵션 숫자만 믿지 말고 실제 생성 간격을 대조한다. 인물과 판의 겹침을 현재 owner가 금지하면 음수 간격이나 비공개 옵션을 만들지 않는다. 거의 닿는 지원 배치부터 사용하며, 꼭 필요한 배경 겹침은 별도 편집 구성으로 보완하고 그 부분의 비연동 범위를 밝힌다. 원화가 판을 향해 손을 뻗지 않으면 단순 위치 조정으로 해결했다고 하지 않는다.
