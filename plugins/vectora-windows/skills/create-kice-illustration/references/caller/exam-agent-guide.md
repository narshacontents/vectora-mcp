# 통합사회 출제 에이전트의 일러스트 스킬 연동 가이드

통합사회 문항을 만드는 AI가 그림 제작을 의뢰하고 결과를 문항에 반영하기 위한 지침이다. 그림이 필요하면 **「통합사회 평가원 스타일 일러스트 만들기」(`create-kice-illustration`)** 스킬을 사용한다.

이 설치본의 호출자 참고 자료는 제작자의 공통→유형→하위유형 세 문서 제한에 추가되는 지침이 아니다. 제작자는 SKILL.md의 입력·완료 계약만으로도 실행할 수 있다.

이 문서를 출제 에이전트에 첨부하거나, 아래의 「출제 스킬에 넣을 호출 규칙」을 출제 스킬의 작업 절차에 추가한다. 실제 제작 세부 규칙은 실행 환경에 설치된 최신 일러스트 스킬 문서를 읽어 적용한다.

## 1. 역할과 호출 시점

| 담당 | 책임 |
|---|---|
| 출제 에이전트 | 교육과정·평가 요소, 발문·선지·정답·해설, 자료의 타당성, 그림이 전달해야 할 정보와 숨겨야 할 정보를 결정한다. 완성 그림을 넣은 문항의 정답과 선지 타당성을 다시 검토한다. |
| 일러스트 스킬을 실행하는 에이전트 | 전달받은 내용과 관계를 그림으로 제작한다. 유형 분류, 조판, 원화 생성, 편집 가능한 Vectora 문서 구성, 저장·재열기·JPEG 검수까지 수행한다. |

그림 속 자료를 읽거나 비교·추론해야 하는 문항, 인물의 발언을 구분해야 하는 문항, 장면·공간·관계가 필요한 문항, 사용자가 그림을 요구한 문항에서 호출한다. 이 스킬의 범위에는 인물 삽화뿐 아니라 표·차트·그래프·지도·도식·대화·문서·학습 활동 자료도 포함된다.

출제 에이전트는 그림에 들어갈 내용과 평가상 중요한 관계를 먼저 정한다. 그림 제작자에게 정답 결정, 선지 작성, 설명되지 않은 수치·관계의 보충을 맡기지 않는다. 자료 조사 자체를 맡기는 경우에는 조사 대상·범위·기준을 따로 지정한다.

### 출제 스킬에 넣을 호출 규칙

아래 블록을 출제 스킬의 제작 절차에 추가해 사용할 수 있다.

```text
통합사회 문항에 시각 자료가 필요하거나 사용자가 그림을 요구하면,
「통합사회 평가원 스타일 일러스트 만들기」 스킬을 실행한다.
실제 스킬 식별자는 create-kice-illustration이다.

1. 문항의 평가 요소와 그림의 역할을 정하고, 그림에 표시할 원문·수치·기호·관계·빈칸을 확정한다.
2. 그림에 표시할 내용과 제작자에게만 전달할 맥락을 분리한 제작 의뢰서를 작성한다.
3. 현재 환경에서 해당 스킬을 로드한다. 별도 제작 에이전트를 쓰면 그 에이전트가
   실제 스킬 문서, Vectora MCP, 필요한 자료·파일과 이미지 생성 도구에 접근할 수 있는지 확인한다.
4. 의뢰서와 필요한 원자료를 전달하고, 설치된 최신 스킬의 공통→유형→하위유형 지침을 따르게 한다.
5. 같은 이름의 편집 가능한 .vectora 원본과 .jpeg, 실제 저장·재열기·이미지 검수 결과를 받는다.
6. 출제 에이전트가 실제 JPEG를 보고 문항 본문·선지·정답과 대조한다.
   그림이 답을 추가로 드러내거나 자료의 의미를 바꿨으면 수정 의뢰 후 다시 검토한다.
7. 검수된 JPEG를 문항에 배치하고 Vectora 원본을 연결한다.
   미완료 결과를 완성 그림으로 삽입하거나 존재하지 않는 파일 경로를 만들어 보고하지 않는다.

일러스트 스킬에 문항 출제나 정답 풀이를 맡기지 않는다.
값·관계·원문·빈칸을 임의로 변경하지 않는다.
필수 도구 또는 자료가 없으면 필요한 항목과 진행 가능한 범위를 보고한다.
```

## 2. 실제 스킬을 실행하는 방법

| 환경 | 호출 방법 |
|---|---|
| Codex | 프롬프트에서 `$create-kice-illustration`을 명시한다. 설치된 스킬 목록과 실제 인식 여부를 확인한다. |
| Claude Code의 Vectora 플러그인 | `/vectora:create-kice-illustration`을 사용한다. 다른 Claude 로컬 세션에서는 현재 제공되는 스킬 선택·호출 방식을 확인한다. |
| 그 밖의 에이전트 환경 | 해당 환경의 스킬 로딩·실행 또는 작업 위임 기능으로 `create-kice-illustration`을 선택하고 의뢰서를 전달한다. |

스킬은 지침 묶음이다. `create-kice-illustration`이라는 MCP 함수가 있다고 가정하거나, 스킬 이름을 임의의 MCP 도구명으로 호출하지 않는다. Vectora MCP는 문서 생성·편집·저장 등에 별도로 사용한다. 실제로 노출된 도구 이름과 입력 스키마를 확인한다.

호출 전 다음 조건을 확인한다.

- GitHub 마켓플레이스의 Vectora 플러그인이 설치되어 있고, 이 스킬이 현재 세션에 로드되어 있어야 한다. 표시 이름이 한국어로 바뀌었어도 식별자는 `create-kice-illustration`이다.
- 설치된 Vectora 앱에 연결되는 MCP가 필요하다. `vectora_status`로 연결과 버전을 확인한다. 기본 회색조 JPEG 내보내기는 앱 1.2.0 이상과 이를 지원하는 실제 도구 스키마가 필요하다.
- 새 compact/legacy graph schema·자동 충돌 배치, 지도 지물 catalog·명시 위치·물리 파선·재열기 binding, 표 세로 정렬·108mm fit, 혼합 문자 ink·명시 굵기·예약 외곽, 두루마리 variant는 앱 **1.4.2 이상**에서만 사용한다. 기존 네이티브 표·복합 조판·검사·평가원 납품(1.4.0), 진행 상태·체크포인트(1.3.0), JPEG/PNG 회색조(1.2.0)의 명시된 최소 버전은 유지한다. 기존 1.3.0 연결본도 앱 기능을 보장하지 않는다. 새 기능은 버전 숫자만으로 추정하지 않는다. 현재 tools/list·resources/list·`vectora://capabilities`를 확인하고 필요한 `vectora://production/<kind>` 문서/schema와 명령별 live input schema만 읽는다. 그래프/지도 프로필·옵션, DEM·지물 요청, 이중 밑줄, 표시 잉크 맞춤, delivery inspect view는 실제 schema에 있을 때만 사용한다. 빠진 기능은 지원되는 기존 편집·저장·재열기·JPEG export로 처리한다.
- KICE 최종 출력 지원 연결본은 사용자 지정 파일명·형식을 정확히 지원할 때 profile:"kice"로 동일 본체 .vectora/.jpeg 한 쌍을 만든다. .jpg 명시나 프로필이 지원하지 않는 형식은 지정 이름을 보존하여 검증된 save→재열기→export 수동 경로를 사용한다. 사용자 지정 확장자를 .jpeg로 바꾸지 않는다. 기술적 `success`/`technicalChecks`, 자동 audit의 `complete|review-required|blocked`, 실제 JPEG 시각 검수는 서로 다른 결과로 보고한다. `visualReview.pending`은 최종 검수가 남았다는 뜻이다. 실제 JPEG 직접 열람 전에는 완료로 응답하지 않는다. legacy 패키지의 추가 파일을 기본 납품에 섞지 않는다.
- 원화 생성 전 가능한 dialogue plan을 통해 측정 발언과 화자별 허용 영역을 확인한다. 지원되는 asset.rasterPath로 앱 머신의 실제 승인 PNG/JPEG를 등록한다. base64·크기·visibleBounds는 직접 왕복하지 않으며 실제 headBounds/crop/facing을 직접 검수한다. KICE 출력은 별도 준비 복사본에서 반응형 바인딩을 현재 폭에 고정하고 원본 작업 문서를 유지한다. 승인 원화를 재사용하고 전체 조판을 래스터로 평탄화하지 않는다. 표·자료·글·말풍선은 독립 편집 구조를 유지한다.
- 새 인물·사물·장면 원화를 만들려면 현재 세션에서 사용할 수 있는 이미지 생성 도구가 필요하다. **Vectora MCP 자체에는 원화 생성 모델이 포함되어 있지 않다.** 표·차트 등 새 원화가 필요 없는 작업에는 이 조건을 일괄 요구하지 않는다.
- 의뢰받는 에이전트가 첨부 자료와 저장 위치에 접근할 수 있어야 한다. 다른 머신의 로컬 경로 문자열만 전달하면 파일이 공유되는 것은 아니다. 필요한 파일을 실제로 전달하거나 접근 가능한 위치로 연결한다.
- Claude의 로컬 Vectora MCP 사용은 Claude Code·Cowork 로컬 세션을 기준으로 한다. 일반 웹 채팅에서 동일한 실행이 가능하다고 가정하지 않는다.

실행 에이전트는 비복합 그림마다 설치된 스킬의 `SKILL.md` → `references/types/<type>.md` 하나 → `references/subtypes/<type>/<subtype>.md` 하나를 읽는다. 생성 작업에 `use-vectora` 등 다른 제작 지침을 무조건 추가하지 않는다. 복합 그림은 독립 자료 단위마다 이 경로를 적용한다. 이 문서는 출제 측 의뢰서 작성용이며, 제작 규격은 해당 세 문서에서 확인한다.

## 3. 잘 만드는 데 필요한 입력

### 반드시 전달할 정보

| 정보 | 어떻게 작성하는가 |
|---|---|
| 문항·그림 식별자 | 예: `문항 07 / 그림 1 / 의뢰 v1`. 수정본이 어느 문항에 속하는지 구분한다. 그림에 이 식별자를 인쇄할지는 별도로 지정한다. |
| 그림의 역할 | 무엇을 읽고 비교해야 하는지 한두 문장으로 설명한다. 예: “두 화자의 분배 기준 차이를 읽게 하는 대화 자료.” |
| 표시할 내용 | 그림 속 문장, 화자 이름, (가)·(나), ㄱ·ㄴ, 밑줄, 빈칸, 제목, 주석을 원문 그대로 준다. 제목·화자 이름이 불필요하면 “없음”이라고 적는다. |
| 대상과 대응 관계 | 누가 무엇을 말하는지, 화살표가 어디에서 어디로 향하는지, 어떤 표식·범례가 어떤 대상에 대응하는지 명시한다. |
| 자료의 성격 | 실제 자료, 출제자가 정한 가상 자료, 정성 개념도 중 무엇인지 구분한다. 실제 자료면 원자료 또는 구체적인 조사 지시를 준다. |
| 바꾸면 안 되는 사항 | 수치, 순서, 상대적 크기, 포함 관계, 빈칸, 강조 위치 등 문항 성립에 필요한 조건을 적는다. |
| 표시 금지 내용 | 정답·해설·개념명·실명 등 그림에 추가하면 안 되는 정보를 명시한다. |

정답과 해설은 기본적으로 출제 에이전트가 보관한다. 그림의 의미 검증에 필요해 전달할 때는 **「제작자 참고용 — 그림에 표시 금지」**에 따로 둔다. 그림에 표시할 내용과 같은 목록에 섞지 않는다. 제작 의도, 검수 메모, 파일명도 자동으로 그림 속 글이 되지 않는다.

### 조건에 따라 추가할 정보

| 상황 | 추가 입력 |
|---|---|
| 수치 자료 | 모든 범주·시점·계열·값, 단위, 비율의 분모, 소수 자릿수, 결측, 축 범위·생략 조건, 범례 대응. 결측을 0으로 쓰지 않는다. |
| 실제 통계 조사 | 조사할 지표의 정의, 지역, 기간·기준 시점, 단위, 생산 기관·직접 출처 URL 또는 원표. 단순히 “최신 통계로”라고 맡기지 않는다. 조사 후 확인되지 않은 값은 채워 넣지 않는다. |
| 연속 개념 그래프 | 축의 의미, 곡선·영역·경계 관계, 교점·이동 방향, 표시할 점·구간, 숫자 눈금의 필요 여부. 정성 개형을 임의 수치로 확정하지 않는다. |
| 지도 | 지리 범위, 필요한 위치·영역·이동 방향, 지명 표기 여부, 실제/가상 여부, 행정 경계의 기준 시점, 통계의 공간 단위. 승인된 지도 바탕을 선택하고 실제 위치를 확인하게 한다. |
| 대화 | 화자별 고유 ID·표시 이름·발언 원문·발언 순서, 강조 구간, 빈칸, 반복 등장 여부. 화자 수와 발언 수를 구분한다. |
| 새 인물·장면·사물 | 대상, 행동, 장소, 시점·시선, 얼굴/흉상/전신 등 신체 범위, 필수 소품, 장면에서 읽혀야 하는 행동, 생략할 배경. |
| 특정 실제 인물·유물 | 정확한 이름과 식별 대상, 신뢰할 수 있는 참조 URL·이미지, 유지할 특징. 제작자가 생성 전 실제 이미지를 확인하게 한다. 일반 인물에 임의의 실명을 붙이지 않는다. |
| 기존 원화·사진·수정본 | 실제 파일, 용도, 수정 범위, 반드시 유지할 요소. “같은 사람”이라고만 하지 말고 재사용할 원화와 대상 ID를 준다. 원본 사진 보존과 선화 재작화를 구별한다. |
| 문항 지면 제한 | 목표 그림 폭(mm), 꼭 필요한 경우의 높이 제한, 내용 상자 치수, 주변 본문과의 관계. 치수가 그림 전체인지 내부 내용 영역인지 구분한다. |
| 저장·납품 | 실제 접근 가능한 저장 폴더, 확장자를 제외한 파일명, 추가 형식이 필요한지, 기존 파일 수정 또는 덮어쓰기 범위. |

레이아웃·시점·장식처럼 평가 의미를 바꾸지 않는 선택은 제작자에게 맡길 수 있다. **정답·자료 해석을 바꾸는 누락이나 모순은 확인한 뒤 진행**한다. 선택 사항이 비어 있다는 이유로 모든 작업을 중단할 필요는 없다.

## 4. 그림 유형을 전달하는 요령

유형은 외형보다 정보 역할로 정한다. 출제자는 후보를 제시할 수 있고, 제작자는 스킬의 분류 기준에 따라 최종 유형·하위유형을 선택한다.

| 원하는 자료 | 유형 후보 |
|---|---|
| 행·열로 비교하는 값·응답·조건 | `table` |
| 연도별 값, 범주별 막대, 구성비, 관측점 | `chart` — 유한한 시계열을 선으로 연결해도 여기에 해당 |
| 연속 함수·이론 관계·가능 영역·분포 면적 | `graph` |
| 위계·절차·인과 관계·집합·연표·공간 구조 | `diagram` |
| 실제 사진·스캔·기존 작품 원본 복제 | `photo` |
| 새로 그리는 인물·사물·행동 장면 | `illustration` |
| 지리적 위치·영역·분포·이동 | `map` |
| 화자와 말풍선 발언의 대응 | `dialogue` |
| 신문·웹·문서 등의 외피 안 기사·자료 글 | `document` — 발화 말풍선과 구별 |
| 학습지·활동 보드·슬라이드 | `activity` |

한 그림 안에 독립된 표와 지도 등이 있으면 각 자료를 빠짐없이 나누어 의뢰하고, 공유하는 기호·시점·값을 연결한다. 신문 테두리나 작은 장식 때문에 독립 자료를 추가한 것으로 취급하지 않는다. 하나의 복합 완성 그림은 기본적으로 한 쌍의 파일로 납품한다.

## 5. 기본 제작·납품 조건

사용자의 명시적 지시가 우선이다. 다음은 현재 스킬의 기본값이며 평가원의 공식 규정이라고 설명하지 않는다.

- 그림 전체의 **실제 외곽 폭은 108mm 이하**다. 지정 폭에 맞추려고 글자와 선을 통째로 축소하지 않는다. 줄바꿈·영역·간격으로 조판하며, 본문과 치수가 충돌하면 그 조건을 보고한다.
- 새 문자는 **UND v3.0, 8pt, 자간 -6% (`tracking/charSpacing: -60`)**를 기준으로 한다. 긴 산문의 영어 범위는 스킬의 UND v3.0 Body 규칙을 따른다. 실제 글꼴·지원 글리프를 확인하며 조용히 대체하지 않는다.
- 문자·말풍선·수치·범례·도형은 따로 편집 가능하게 둔다. 생성 원화에 글자를 구워 넣지 않는다. 그림 전체를 한 장의 이미지로 만든 것을 편집 가능한 원본이라고 납품하지 않는다.
- 원화는 포함 이미지로 배치할 수 있다. 편집 가능한 Vectora 문서가 곧 원화까지 순수 벡터라는 뜻은 아니다. 순수 벡터 원화가 꼭 필요하면 의뢰서에 별도로 명시한다.
- 새 원화는 스킬의 명시된 화풍 계약을 이미지 생성 도구에 전달한다. “평가원 느낌”이라는 말만으로 원화 지시를 끝내지 않는다. 과거 기출·완성 템플릿을 찾아 복사하는 방식으로 새 그림을 만들지 않는다. 사용자가 제공한 재현 대상·동일 인물 원화와 승인된 지도 바탕은 스킬의 허용 범위에서 참고한다.
- 기본 납품은 **같은 이름의 `.vectora` 한 개와 `.jpeg` 한 개**다. JPEG는 기본 4배·회색조·불투명 배경이다. 컬러나 다른 배율을 명시하면 사용자 지시를 따른다.
- 저장 폴더를 지정하지 않으면 현재 작업 공간 바로 안에 저장한다. 임의의 날짜·output 폴더를 만들지 않는다. 무관한 기존 파일을 덮어쓰거나 파일 수를 맞추기 위해 삭제하지 않는다.
- 납품 개체의 실제 외곽에 대지를 맞추고 추가 외부 여백은 0으로 한다. 본문의 의도된 빈칸이나 장면 안 공간까지 제거하지 않는다.
- 저장한 `.vectora`를 다시 열어 편집 요소·크기·포함 이미지를 확인하고, 그 최종 문서에서 내보낸 **실제 JPEG를 직접 열어** 최종 사용 크기와 확대 상태로 검수한다. 검사 도구의 성공 응답만으로 시각 검수를 대신하지 않는다.

## 6. 복사해서 쓰는 제작 의뢰서

아래는 **에이전트 간 의뢰서**다. MCP 함수의 JSON 인자 스키마가 아니다. `<...>`를 실제 내용으로 바꾸고 해당하지 않는 항목은 삭제하거나 “없음”으로 쓴다. 실행 에이전트가 현재 도구 스키마에 맞게 실제 명령을 구성한다.

```text
「통합사회 평가원 스타일 일러스트 만들기」(create-kice-illustration) 스킬을 사용해 제작해줘.
설치된 최신 공통→유형→하위유형 지침을 읽고 실행해줘.

[작업 식별]
문항/그림/의뢰 버전: <문항 07 / 그림 1 / v1>
작업: <신규 제작 또는 기존 그림의 지정 부분 수정>

[출제 맥락 — 그림에 자동으로 표시하지 않음]
학년·과목·단원/평가 요소: <...>
그림을 보고 학생이 읽어야 할 정보: <...>
그림에서 직접 드러내면 안 되는 정보: <정답 개념명, 해설 등>

[그림에 표시할 내용 — 아래 원문을 유지]
자료 식별 기호: <(가), (나) 등. 없으면 없음>
제목: <원문 또는 없음>
본문/화자별 발언/이름: <원문 전체와 화자·대상의 대응>
밑줄·빈칸·강조: <정확한 대상 문자열과 위치>
축·단위·범례·주석·출처 표기: <표시할 문자열 또는 없음>

[자료·관계]
자료 성격: <실제 제공 자료 / 실제 자료 조사 / 가상 자료 / 정성 개념도>
자료/첨부/직접 URL 또는 조사 범위: <...>
대상과 관계: <방향, 순서, 포함 관계, 상대 크기, 위치, 화자 ID 등>
수치 자료: <계열·범주·시점·값·단위·분모·결측. 해당 시 원표 첨부>
자료 처리: <정확한 값 유지, 허용한 단위 환산·반올림 등>

[표현]
유형 후보: <dialogue, chart, illustration 등 또는 제작자가 선택>
구도·대상·행동·시점·신체 범위: <필요한 조건>
참조/재사용할 파일과 적용 범위: <실제 접근 가능한 파일 또는 없음>
반드시 유지: <...>
제작자가 조정해도 되는 것: <줄바꿈, 인물의 세부 외형, 여백 등>
추가하면 안 되는 것: <답, 임의 제목·이름·수치·상징 등>

[크기·납품]
그림 전체 목표 외곽 폭: <예: 96mm. 미지정이면 108mm 이내에서 조판>
높이 제한/내용 상자 예약: <없음 또는 범위·치수·적용 대상>
저장 폴더: <현재 작업 공간 또는 실제 접근 가능한 지정 폴더>
파일명 본체: <예: 07_그림1>
형식: 같은 이름의 .vectora + .jpeg, 기본 회색조 JPEG 4배
기타 사용자 지정: <없음 또는 컬러·배율·추가 형식 등>

[완료 조건]
원문·값·좌표·기호·빈칸·관계와 요청한 서식이 보존되어야 한다.
기술 저장/재열기/출력 상태와 자동 audit/review 상태를 따로 알려줘.
저장된 JPEG를 직접 열어 최종 크기와 확대 화면을 검수해줘.
두 파일의 실제 경로, 유형/하위유형, 실측 외곽 크기, 검수 결과,
원화의 래스터 포함 여부, 남은 문제를 응답으로 알려줘.
미충족 조건이나 도구·자료 부족이 있으면 성공으로 보고하지 말고 구체적으로 알려줘.
```

## 7. 의뢰 예시

### 예시 A — 두 관점을 비교하는 대화 자료

Codex에서는 첫 줄에 `$create-kice-illustration`을 붙인다. 다른 환경에서는 그 환경의 실제 스킬 호출 방식으로 동일한 의뢰 내용을 전달한다.

```text
$create-kice-illustration
문항 07의 그림 1을 새로 제작해줘.

제작자 참고: 사회 정의와 분배 기준에 관한 두 관점을 읽게 하는 자료야.
관점의 이름이나 정답·해설은 그림에 쓰지 마.

유형 후보는 dialogue/horizontal. 가상의 화자 2명이며, 표시 이름은 갑과 을이야.
왼쪽 갑의 발언: 사회적 약자에게 더 많은 자원을 배분해야 해.
오른쪽 을의 발언: 모두에게 동일한 기회를 보장하는 것이 중요해.
두 문장은 원문 그대로 각각 한 말풍선에 넣고, 이름은 해당 인물과 대응시켜줘.
추가 제목·자료 기호·밑줄·빈칸은 없어.

흉상 2명은 서로 다른 얼굴로 그리고, 상대를 향한 자연스러운 시선과 비슷한 머리 크기로 배치해줘.
두 입장을 특정 성별·나이·외모와 연결하지 마. 말풍선 꼬리는 각 화자를 가리켜야 해.
기존 원화는 없으므로 현재 연결된 이미지 생성 도구로 새 원화를 만들어줘.
인물 세부 외형과 의미를 바꾸지 않는 줄바꿈은 조정해도 돼.

실제 외곽 폭 100mm, 높이 제한 없음. 스킬의 기본 문자·선·회색조 규격을 적용해줘.
현재 작업 공간에 07_그림1.vectora와 07_그림1.jpeg로 저장하고,
저장본 재열기와 실제 JPEG 시각 검수 후 파일 경로와 검수 결과를 알려줘.
```

### 예시 B — 가상 통계를 비교하는 차트

### 예시 C — 인물 행동이 필요한 장면 삽화

“문화 다양성 삽화”처럼 주제만 주기보다 다음처럼 **관찰 가능한 행동과 표시 내용을 지정**한다.

```text
create-kice-illustration 스킬로 문항 18의 장면 삽화를 새로 제작해줘.

유형 후보는 illustration/scene. 눈높이의 사선 시점, 인물의 상반신과 데스크가 보이는 구도야.

배경은 도서관임을 알 수 있는 최소한의 책장만 두고, 실제 기관을 재현하지 마.

실제 외곽 폭 100mm, 높이 제한 없음. 스킬의 새 원화 화풍 계약을 적용해줘.
현재 작업 공간에 18_그림1.vectora와 18_그림1.jpeg를 저장하고 재열기·시각 검수해줘.
원화가 포함 이미지이면 그 사실과 실제 파일 경로를 알려줘.
```

## 8. 결과를 받는 형식과 문항 반영

제작자에게 다음 항목을 **응답 본문**으로 받는다. 별도의 검수 파일을 기본 납품에 추가할 필요는 없다.

```text
문항/그림/의뢰 버전:
상태: 완료 / 일부 미완료 / 입력 또는 도구 필요
최종 유형/하위유형:
Vectora 원본의 실제 경로:
JPEG의 실제 경로:
실측 외곽 크기(mm):
저장·재열기 확인:
실제 JPEG 직접 열람·검수:
원문·값·대응 관계 검사:
순수 벡터 / 원화 포함 이미지 혼합:
사용한 실제 자료 출처·변환 요약(해당 시):
남은 문제·승인 필요한 변경(없으면 없음):
```

출제 에이전트는 완료 응답을 받은 뒤에도 실제 그림을 문항과 대조한다.

- 발문·선지에서 가리키는 인물, (가)·(나), ㄱ·ㄴ, 축, 영역, 자료 기호가 그림과 정확히 대응하는가?
- 의도한 정보가 최종 지면 크기에서 읽히며, 답을 추론하는 데 필요한 차이·순서·관계가 보존되었는가?
- 정답·개념명·해설·불필요한 강조가 추가되어 문항의 난이도나 정답 근거를 바꾸지 않았는가?
- 빈칸이 임의로 채워지지 않았으며, 실제 자료와 가상 자료가 혼동되지 않는가?
- 그림 수정 후에도 정답의 유일성과 오답 선지의 타당성이 유지되는가?
- 원본과 JPEG가 같은 최종 상태인가? 문항 편집 과정에서 비율을 늘이거나 지나치게 축소하여 글자 규격을 훼손하지 않았는가?

JPEG는 문항의 표시용 그림으로, `.vectora`는 수정 가능한 원본으로 연결한다. 재작성할 때 두 파일을 같은 최종 상태로 함께 갱신한다.

## 9. 수정 요청과 막힘 처리

수정할 때는 **기존 `.vectora` 파일 + 의뢰 버전 + 변경 항목 + 유지 항목**을 전달한다. 예: “07_그림1의 을 발언만 아래 원문으로 바꾸고, 갑 발언·인물·이름·그림 폭은 유지해줘. 바뀐 글 분량에 맞춰 을의 말풍선만 재조판하고 두 납품 파일을 함께 갱신해줘.” 기존 파일을 교체할지 새 이름으로 보존할지도 명시한다.

- 원문·수치·관계가 서로 모순되면 출제 측에 구체적인 충돌을 알린다. 정답에 맞게 자료를 조용히 고치지 않는다.
- 실제 자료를 찾지 못하면 확인한 범위와 누락을 보고한다. 가상 값으로 대체하려면 출제 측이 자료 성격을 명시적으로 바꿔야 한다.
- 새 원화가 필요한데 생성 도구가 없으면 제공되었거나 재사용을 명시한 원화를 먼저 검토한다. 여전히 부족하면 대상·포즈·시점·식별 특징·스킬 화풍·배경 조건의 생성 프롬프트와 비최종 벡터 조판을 준비하고 필요한 원화를 요청한다. 프롬프트는 응답 본문으로 전달하며 별도 납품 파일을 추가하지 않는다. 임시 아이콘·코드 얼굴·과거 예시로 대체하거나 원화가 빠진 조판을 완성으로 보고하지 않는다.
- 글꼴·글리프·치수·편집성 또는 저장·재열기·내보내기에 문제가 있으면 미충족 항목을 정확히 보고한다. 앱 코드를 고치거나 다른 프로그램으로 임의 대체하여 검증 완료로 처리하지 않는다.
- 명백한 시각 결함은 수정 후 전체를 다시 본다. 스킬의 기본 최대 3회 수정 원칙과 정체·도구 한계 시 중단·보고 원칙을 따른다.

### 연결 중단·진행 상태와 복구

제작자가 현재 도구 목록/스키마에서 지원을 확인한 경우만 진행 상태 조회·체크포인트·복구·진단 미리보기를 사용한다. 진행 카운터는 완료율이 아니고, 진단 이미지와 체크포인트는 납품 완료가 아니다. 체크포인트는 최종 두 파일과 구별한 내부 임시 영역에 저장하며 추가 납품 파일로 만들지 않는다. 취소·응답 유실·결과 캐시 만료 뒤 같은 편집을 새 ID로 중복 실행하지 않고 실제 상태를 확인한다. 세션 소실 시 저장되지 않은 편집을 복구했다고 주장하지 않는다. 복구 문서는 새 ID/revision으로 재검수한다. `vectora_status`에 `runtimeResources`가 반환되면 문서·캔버스 수 등 진단 정보로만 사용한다. 완성된 문서는 저장 확인 후 닫고, 재개할 때는 실제 저장 경로와 documentId를 재사용한다. 중단되거나 연결이 끊긴 작업은 저장·재열기·JPEG 검수를 실제로 마치기 전까지 성공으로 보고하지 않는다. 구형 연결본에서는 기존 저장·재열기 경로를 사용하고 지원하지 않는 기능을 주장하지 않는다. 자세한 제작 실행 계약은 설치된 SKILL.md 안에 있으므로 제작자에게 별도 네 번째 지침을 읽게 하지 않는다.
