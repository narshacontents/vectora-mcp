### 화면 외피

웹·앱·휴대폰 화면 또는 발화 없는 방송 자막 외피다. 필요한 탭·주소창·조작부·스크롤바를 기존 프레임 안에서 선택한다. 모든 화면에 같은 아이콘을 강제하지 않는다. 방송 화면 안 장면과 자막의 역할을 분리하고 말풍선을 자동 추가하지 않는다.

요청에 화면·사이트 이름과 본문 제목이 함께 있으면 둘을 구별해 표시한다. 브라우저의 사이트 이름은 `background.tabTitle`, 기사·자료 제목은 `title`에 넣는다. 이름을 생략한 빈 탭이나 제목의 임의 중복으로 명시된 매체명을 대체하지 않는다. 미제공 이름은 새로 만들지 않는다.

댓글형 화면은 본문 줄 수와 작은 흉상의 실제 높이 중 큰 값에 최소 상하 여백을 더해 행 높이를 정한다. 한 줄 댓글은 흉상 높이 약4–5mm·상하 약1mm부터 검토하며 큰 초상 슬롯 때문에 매 행을 두껍게 만들지 않는다. 교사 소개와 옆 자료가 있는 상단은 작은 초상 옆에 이름·본문을 놓는 구성을 먼저 검토해, 큰 초상 아래에서만 글을 시작하는 빈 공간을 줄인다. 긴 본문·사용자가 지정한 초상 크기는 실제 높이에 맞춘다.

#### 선택 브라우저 배경 실행

브라우저는 `variant:"browser"`이며 `headerHeightMm`/`titleHeightMm`으로 조작부/제목, `asideWidthMm`/`asideHeightMm`으로 옆 삽화 영역을 예약한다. 기본 aside는 본문 전체와 나란한 고정 열이다. 그림 옆에서 시작한 글이 그림 아래에서 전체 폭으로 이어지는 요청에는 감싸기 조판을 선택하며, 고정 열만 만든 상태를 완성으로 취급하지 않는다. `illustrationSlots`는 빈 자리이며 그림이 들어 있지 않다. 휴대폰·앱·방송 등 미지원 외피는 직접 구성한다.

라이브 스키마에 `background.chromeStyle`이 있으면 탐색 도구 중심 `classic`, 간결한 주소창 `simple`, 검색창 중심 `search` 중 외피를 고른다. 이는 본문의 내용 분류가 아닌 시각적 선택이다. 일반 안내·기사에도 여러 외피가 자연스러우므로 특정 내용이면 항상 같은 값을 고르는 대응표를 만들지 않는다. 항상 필드를 생략해 같은 기본 틀을 반복하지 않으며, 선택값은 저장하여 내용 수정·폭 변경·재열기 때 유지한다. 지원이 없으면 해당 필드를 보내지 말고 지원되는 편집 개체로 조작부만 보완한다.

외형을 지정하지 않은 신규 제작에서는 같은 웹페이지라는 이유만으로 이전 외피 선택을 재사용하지 않는다. 같은 작업에서 여러 새 화면을 만들면 의미상 동등하게 적합한 외피 중 서로 다른 조합을 선택한다. 조작부의 구성과 작은 회색 면, 요청에 포함된 삽화의 위치·크기로 변화를 주되, 사용자 지정 구도와 충분한 본문 공간을 우선한다. 이전 완성 그림을 참조하거나 가상의 사이트명·장식 문구를 더해 다양성을 만들지 않는다. 같은 문서의 수정 요청에는 이 신규 선택 규칙을 적용하지 않는다.

새 브라우저의 조작부 높이를 요청하지 않았다면 `headerHeightMm`을 생략하고 네이티브 기본 조판을 먼저 사용한다. 라이브 계약의 `compact-v2`는 8pt 탭 제목과 두 줄 조작부를 위한 작은 기본값이며, 예전 기본 높이·허용 최솟값을 임의로 고정 입력하지 않는다. 기존 저장본의 정책이나 명시 치수는 유지하고, 조작부를 줄이려고 본문·탭 제목 글자를 축소하지 않는다.

#### 검사

내용과 조작부/자막 경계, 옆 삽화에 의한 예약 공간 침범, 마지막 줄과 프레임 충돌을 확인한다.

화면 외피와 내부 자료 컴포넌트·예약 영역을 구별한다.
