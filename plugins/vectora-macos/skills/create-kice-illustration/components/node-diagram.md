## 도식 공통·조건부 배치

- 대상과 관계를 먼저 확정한다. 노드/영역과 연결표(출발·도착·방향·분기 문구)를 요청에서 작성하고 미지수·빈 질문을 풀지 않는다. 노드형 도식에서 질문·특성은 흰 직사각형, 짧은 대상/결과는 원 또는 직사각형이다. 같은 역할의 짧은 노드는 형태·기본 크기를 맞추되, 독립 노드를 다른 긴 설명 노드에 맞춰 모두 키우지 않는다. 여러 행을 좌우로 비교하는 판은 대응 행의 높이를 가장 긴 내용에 맞춰도 된다. 이때 그 행의 필요한 실측 높이만 쓰며 다른 행까지 키우지 않는다. 크기가 다른 대응 노드는 중심과 연결 축을 맞춘다. 명시된 동일 크기는 보존하며 모든 질문을 마름모로 바꾸지 않는다.
- 연결이 있으면 특성 대응은 무방향, 절차·판정은 방향, 상호 관계는 의미에 따라 무/단/양방향이다. 교차는 접속이 아니다. 실제 공유 줄기만 하나의 분기점으로 만들고 공통 특성 상자를 복제하지 않는다. 화살촉 끝은 도착 윤곽에 닿으며 도형 안으로 들어가지 않는다.
- 글상자를 조판한 뒤 사방 여백으로 노드 크기를 정한다. 측정 폭은 노드 외곽이 아니라 생성기의 안쪽 여백을 뺀 실제 글 프레임 폭이다. 짧은 이름을 한 줄로 둘 때도 실제 행수를 확인하고, 여러 줄이면 글 높이에 맞춰 외곽 높이를 함께 정한다. 짧은 특성은 얇고 긴 띠, 대상 원은 짧은 글만 담으며 단문 띠 높이의 약 1.2–1.6배 지름부터 검토한다. 여러 줄 문장에는 그 비율을 강제하지 않는다. 반복 띠 사이 틈은 높이 약 1/3, 분기 문구·촉을 담는 순차 통로는 약 3–7mm부터 조정한다.
- 연결은 수평·수직·간결한 사선으로 출발·꺾임·도착을 정렬한다. 같은 수준의 가지·병렬 판정·결과 높이를 맞추며 불필요한 긴 빈 선을 줄인다. 꺾임 통로를 도형 밖에 예약하고 글을 가리는 선은 흰 덮개 대신 경로/라벨 배치로 해결한다. 범례는 단계 간격을 밀어내지 않는 공간에 둔다. 단계 간격은 실제 노드 높이·분기 문구·촉에 필요한 통로로 정하고 전체 높이에 비례해 늘리지 않는다. 수평 대응만 있는 비교 행 사이에는 수직 분기 통로가 필요하지 않다. 짧은 행을 내용과 무관한 고정 간격으로 배치하지 말고 실측 행 높이에 좁은 구분 간격을 더해 다음 행을 정한다.
- 묶음 대상 원은 묶음 중심 높이, 공유 결과는 관련 질문 사이 높이로 조정할 수 있다. 과거 도형 수·좌우 위치를 틀로 고정하지 않는다. 이동 후 선·촉·라벨을 다시 맞추고 연결표와 모든 선을 대조한다. 노드의 텍스트 프레임·글 획이 내부 여백을 포함해 상자 안에 들어가고 상자와 글이 그룹/클립 경계에서 잘리지 않는지 확인한다. 범례 열은 실제 문구 폭으로 정해 짧은 낱말의 한 음절 고립을 피한다.

## 노드·연결 생성 spec

`spec:{kind:"schematic",layout,widthMm,gapMm?,nodes,edges}`. 확인된 layout은 `sequential,shared,crossing,shared-results,relations`이며 분류 ID 자체를 layout으로 넣지 않는다. nodes는 `{id,text,shape:"rect"|"circle",widthMm?,level?,xMm?,yMm?}`; edges는 `{id,from,to,direction:"none"|"forward"|"both",routing:"straight"|"orthogonal",label?,dashed?,fromAnchor?,toAnchor?,via?:[{xMm,yMm}]}`다. 안정적 ID로 대응을 유지한다.

요청에서 반드시 지켜야 할 배치·관계와 제작자가 임의로 택한 좌표·junction/anchor/via 핀을 구분하고, 제작자가 고른 핀만으로 `rowLayout` 불가를 판단하지 않는다. 사용자가 명시한 배치는 보존한다. 독립 schematic에서 모든 노드가 직사각형이고 요청 관계가 아래향 무라벨 연결이며 live schema/plan이 `rowLayout` v1을 지원하면, 좌표를 설계하기 전에 `layout:"relations", rowLayout:{version:1,horizontalGapMm:1,verticalGapMm:3,xPolicy:"auto",rows:[{id:"r1",nodeIds:["a"]},{id:"r2",nodeIds:["b","c"]}]}`처럼 필요한 간격을 명시한 간단한 row plan을 먼저 시도한다. 행은 위계 단계와 일대일일 필요가 없어 추가 행을 둘 수 있고, 연결은 행을 건너뛸 수 있으며, 단독 행은 `alignToNodeId`로 다른 행의 노드에 정렬할 수 있다. `rows[].nodeIds`로 행과 행 안의 원소 순서를 정하고, `edges`에는 실제 관계만 따로 적는다. plan의 자연폭(`minSingleLineWidthMm`)·최종 폭·`lines`를 확인하고, 불확실한 줄은 실제 안쪽 폭과 UND 8pt 및 선택한 문자 역할의 자간으로 `vectora_measure_text`해 검토한다. 좁은 폭에서는 기존 노드 사이 간격을 보존한 자연 줄바꿈을 먼저 사용한다. 긴 이름을 한 줄로 유지하려고 모든 행의 간격을 함께 줄여 상자들이 거의 붙게 만들지 않는다. 구조 하한 `minimumWidthMm`는 자연어 실측 하한이 아니며, 자연 줄바꿈 후보가 `widthMm`에 들지 않으면 계획이 실패하므로 폭을 넓히거나 행을 나눈다. `widthMm`는 입력 외피이므로 plan의 실제 잉크 폭과 대조해 필요하면 `fitContentWidth` 대신 spec/대화상자의 `widthMm`를 갱신하고 다시 계획한다. 행 높이는 측정된 내용과 필요한 화살표 여유로 정하며 스타일 지침의 도식 전체 높이에 맞춰 짧은 행을 늘리지 않는다.

행 모드에서는 `nodes[].xMm/yMm/level`, `via`, junction·anchor 핀을 섞지 않는다. 루트 `xMm/yMm` 이동은 지원된다. 원·라벨 연결·아래향이 아닌 관계·중첩 제작처럼 live 계약상 지원하지 않는 조건, 사용자가 명시한 좌표 또는 요청에 필수인 교차·특수 경로가 있거나, 간단한 row plan에서 실제 거부 사유가 확인되면 해당 조건을 지원하는 기존 coordinate layout으로 전환한다. 그때는 plan의 실제 안쪽 폭·줄 수·필요 높이와 `vectora_measure_text`의 `lines`를 써서 폭·상자 높이·다음 좌표를 조정한다. 짧은 낱말, 특히 괄호 설명을 단어 중간에서 나누지 않도록 폭과 배치를 고친다. 측정은 생성될 글상자와 같은 `autoFit`·`textAlign`이어야 하며 `autoFit:false`를 생략하면 줄바꿈이 달라질 수 있다. 수정 뒤 저장된 실제 JPEG에서 직각 연결과 노드 경계 앵커를 확인하고, 높이·통로도 다시 살핀다. 계획 성공만으로 겹침 없는 최종 그림이라 판단하지 않는다.

행 모드에 제목·위아래 설명이 필요하고 live 계약이 지원하면 `rowLayout.title:{text}`와 `rowLayout.caption:{text,position:"above"|"below",arrowDirection:"none"|"up"|"down"}`를 우선 사용한다. 같은 도식 안에서 실측 높이와 간격을 함께 갱신하므로 글·노드를 바꿀 때 별도 좌표 보정을 반복하지 않는다. 설명 화살표는 요청한 의미가 있을 때만 넣고, 불필요한 고정 높이를 주지 않는다. 제목·설명이 필요하지 않은 도식에는 추가하지 않는다.

`shared`의 열 배정은 연결 관계에서 계산되므로 `xMm/yMm/level`로 열폭 제한을 우회하지 않는다. 행 모드의 제목·설명 계약이 적용되지 않는 도식에서는 별도 글 컴포넌트로 둔다. 직접 좌표를 설계할 때는 `relations`를 선택하되 열폭·간격도 실제로 들어가야 한다. `shared` 열폭 충돌에는 노드 폭·간격·배치를 조정하며, 글자 축소나 관계 삭제로 해결하지 않는다.

노드의 내부 좌표와 생성된 컴포넌트의 문서 좌표를 구별한다. 제목·아래 설명과 결합할 때는 생성 직후 실제 루트 외곽을 inspect해 배치한다. 지원 좌표 필드를 바꿨는데 source만 달라지고 실좌표가 남으면 같은 update를 반복하지 말고 기존 루트를 문서 좌표로 이동한 뒤 선·글을 함께 확인하고 앱 결함으로 기록한다. 이미 배치한 루트의 보존 수정 뒤에도 이 검사를 적용한다.

좌표 모드에서는 공유 줄기의 edges에 같은 `sharedStemId`와 필요하면 같은 `junctionMm:{xMm,yMm}`를 준다. 선언 없는 교차는 분리된다. 명시 좌표·via로 교차·줄기를 보존하되 컴포넌트 이동 후에는 도구 계약의 좌표계와 실제 노드 앵커를 대조해 수직 구간이 사선으로 바뀌지 않게 한다. 순환을 sequential 제약에 강제로 넣지 않고 명시 좌표 또는 relations를 쓴다. 일반 테두리·연결선은 0.3pt; 비그래프 파선 주기는 내용·크기에 맞춰 결정한다. 벤 계약은 해당 하위유형 안에 있다. 노드 계약으로 표현되지 않는 공간 구조는 지원 요소를 먼저 생성하고 부족한 면·경계·기호만 편집 가능한 개체로 보충한다.
