- 복합형은 `kind:"composition",layout:"row"|"column"|"grid",widthMm,gapMm,maxHeightMm?,columns?,children`의 지원을 확인한다. 각 child는 안정된 고유 id와 native 자료 `spec`, 본문 `text`/`richText`, 빈 공간 `reserve` 중 지원되는 내용 형식을 가지며 선택 widthMm를 쓴다. grid에서만 columns를 쓴다. children은 최대32개, 중첩은 깊이6/총128개 한도다. 안정 ID와 수동 수정 보존을 확인한다. 내부 의미 단위는 각각 편집 가능한 컴포넌트로 유지하고 무조건 한 SVG로 평탄화하지 않는다. 무지원이면 기존 개체·그룹으로 같은 조판을 구성한다.
- 제목 아래 단일 도식·표를 놓는 column에서는 할당 폭과 내부 자료의 실제 폭이 다를 수 있다. 가운데 정렬한 제목 아래에 좁은 자료만 왼쪽으로 붙지 않도록 plan의 실제 외곽 중심을 비교하고 지원되는 크기·배치 옵션으로 맞춘다. 고정 비율 자료를 가로로 늘리거나 본문 문단까지 가운데 정렬하지 않는다.
- 여러 독립 그래프 자식이 범례를 공유하면 부모가 소유하는 공통 범례 공간을 먼저 정한다. 두 자식의 자료를 가리지 않는 공통 빈 곳이나 가까운 외부 여백을 선택하며, 반드시 큰 하단 띠를 만들 필요는 없다. 활성 graph/composition 계약이 네이티브 공통 범례를 명시 지원할 때만 사용하고, 확인되지 않으면 각 자식의 `legend:"none"`과 series 색·패턴에 대응하는 견본·문자의 편집 가능한 공통 푸터를 쓴다. 자식 소유 범례를 형제 경계 너머로 옮기지 않는다. 수치 편집 뒤 저장된 결과에서 그래프 값과 범례의 색·패턴 대응을 확인하고, 푸터가 독립 개체이면 자동 연동이라고 설명하지 않는다.
- row/grid에서 `child.widthMm`과 `sizing`을 생략한 트랙은 고정 폭과 간격을 제외한 나머지를 균등 배분받는다. 고정 폭이 필요한 자료만 `widthMm`을 지정하고, 비율 조정에는 라이브 계약의 `sizing:{mode:"flex",weight,minWidthMm?,maxWidthMm?}`를 쓴다(`widthMm`과 상호 배타적이며 column에서는 미지원). `sizing:{mode:"content",minWidthMm?,maxWidthMm?}`는 row/grid의 native table 자식에만, 사용 중인 Vectora의 live composition/schema 지원을 확인한 경우에만 쓴다. 실제 UND 무줄바꿈 고유 폭 측정으로 자동 열·일반 문자열 제목·병합 셀을 검증하고 남는 폭은 auto/flex 트랙에 배분한다. 지도·그래프 옆의 짧은 라벨·숫자 표는 자동 열을 쓰고, 실제 높이를 비교해 content sizing 또는 flex 폭 배분을 고른다. 고정 가로세로 비율의 그래프 옆에서는 content sizing이 표를 지나치게 좁히고 그래프만 키울 수 있으므로 먼저 공통 높이에서 검토한다. 측정값을 모든 자식의 `widthMm`/`column.widthMm`에 일괄 복사하지 않는다. 긴 서술형 표는 기존 wrap/flex 경로를 유지하고, live 지원이 없으면 기존 측정 최소 폭+flex 경로를 쓴다. 명시 열 폭·원문·글꼴을 보존한다. grid에서는 같은 열의 명시 정책을 일치시키며 미지정 자식은 그 열의 정책을 따른다.
- plan의 계산 결과를 모든 자식의 고정 치수로 되쓰지 않는다. 지원되는 외피/부모 폭 변경은 자식을 같은 정책으로 재조판하므로 먼저 부모 폭만 갱신하고 실제 글·선택 프로필의 pt·지도 척도를 확인한다. 기존의 명시 고정 폭·열 비율은 임의로 바꾸지 않으며, 이를 축소할 때도 글이 자연스럽게 들어가는지는 별도로 검사한다. `LAYOUT_WIDTH_UNSATISFIABLE`이면 최소 폭·자료 비율·간격을 다시 설계하고, 문자 축소나 수동 좌표 보정으로 덮지 않는다.
- 높이가 다른 자료를 가로로 묶을 때 상단 맞춤과 가운데 맞춤 중 관계에 자연스러운 쪽을 고른다. live composition/schema가 지원하면 일반 row/grid의 `rowAlign:"center"`로 표·자료와 사이의 `+` 같은 독립 문자를 함께 맞춘다. 문자는 실제 획, 표는 외곽 높이를 기준으로 재조판하므로 글을 고칠 때마다 기호 Y좌표를 옮기지 않는다. 미지정은 기존 상단 맞춤이며 모든 복합형을 가운데 정렬하지 않는다. `bottom`은 바닥선 공유가 필요한 경우에만, column·sharedScalar는 해당 옵션 없이 고유 배치를 쓴다. 최종 높이·행 간격과 편집 후 정렬을 실제 JPEG로 확인한다.
- 같은 높이로 유지할 카드 표는 live composition/schema가 지원하면 표를 직접 소유한 부모의 `sharedTableRows:[{id,targets:[{childId,rowId}]}]`로 대응 행을 연결한다. 머리칸·본문을 따로 묶으면 글 추가·삭제 뒤에도 각 경계가 함께 맞춰진다. 공유하지 않을 행·표는 제외하며 일반 `rowAlign`과 구별한다. 파생 높이를 각 표의 고정 최소 높이로 복사하지 말고 기존 최소값과 연결 관계를 보존한다. 현재는 직접 native table 자식의 행만 지원하며, 대상 행에 걸친 rowSpan과 같은 owner의 sharedScalar는 지원하지 않는다. 중첩 격자는 해당 자식 부모에 연결하고 상세 제한은 live 계약을 따른다. 지정한 행이 모두 같은 실측 높이인지, 수정 후 다시 줄어드는지 저장본으로 확인한다.
- 연속된 자료 상자 사이의 짧은 채움 화살표는 live composition/schema에 `stageArrows`가 있으면 인접 자식 ID를 연결해 부모가 소유하게 한다. 보이는 간격에 맞춰 화살표 폭·길이를 정하고 길이보다 큰 간격을 확보한다. 지원 범위는 일반 row/column의 순방향 인접 관계이며, 대각선·분기·grid에 억지로 쓰지 않는다. 본문이 늘어난 뒤 화살표와 다음 상자가 함께 따라오는지 저장본에서 확인한다. 별도로 설계한 테두리·외피도 연결할 때만 [외피 경로 연동](frame-decoration-native.md)의 live `frameDecorations` 계약을 적용한다. 미지원 연결 앱에서는 기존 보충 경로와 AI 재조판을 사용하고 자동 연동으로 보고하지 않는다.
- 같은 원자료를 표·지도·차트에 반복 표시할 때는 live capabilities의 `composition.sharedData`와 `vectora.shared-numeric/v1`에서 해당 연결 대상 지원을 확인하고 명시 연결한다. 지도 비례값은 record ID, 표 숫자는 cell ID, 지원되는 범주형 막대·선 차트의 `graphSeriesValue`는 series ID와 정확한 고유 범주명으로 연결하며 모두 안정된 child ID 경로를 쓴다. 같은 숫자라는 이유로 연결하거나 고정 참조 범례를 연결하지 않는다. 최초 표시값을 맞춘 뒤 owner의 `sharedData.rows`만 갱신한다. 소비자 직접 수정은 owner에서 수정하거나 명시적으로 연결을 해제하는 경로로 바꾼다.
- 행·열 합계도 연동할 때는 live 계약의 `sum:{rowIds:[...]}` 지원을 확인해 원자료 행만 참조한다. 총합은 중간 합계가 아닌 모든 해당 원자료를 참조하며, 최초 합계 캐시를 맞춘 후에는 직접 고치지 않는다. 100% 누적 그래프에도 원래 인원·수량을 연결하고 백분율은 생성기가 계산하게 한다. 0과 결측 null을 구별하며, 합계에 결측이 있으면 합계도 결측이다. 100% 누적 차트의 결측·합계 0 등 미지원 조건을 임의의 0으로 바꾸지 않는다. 수치 수정 의뢰에서는 재열기 후 합계·차트 갱신을 확인한다.
- 공유하지 않은 내부 값은 `inspect`로 얻은 실제 자식 component ID에 `update`하여 owner를 통해 재조판한다. 공유 계약 미지원 시 표·지도·차트의 대응 값을 각각 명시적으로 갱신하되 한 `vectora_apply` 트랜잭션에 묶을 수 있으며, 이를 단일 원자료 자동 연동이라고 보고하지 않는다. 지원 차트 형식·합계 제한 등 세부 계약은 live resource `vectora://production/composition`을 따른다.
- 단순 사각 본문 카드가 필요하고 live table/schema가 `cells[].content`를 지원하면, 1셀 native table 안의 composition이 식별 표기와 본문을 소유하도록 구성할 수 있다. 셀은 `text:""`, richText 생략, state 생략 또는 `value`이며 실제 본문은 content 안에 한 글상자로 둔다. 테두리·안쪽 여백은 컨테이너가 맡고 행 높이를 미리 고정하지 않는다. 독립 카드마다 컨테이너를 나누면 서로 다른 본문 높이를 유지한다. 일반 본문 `replaceTextRange` 뒤 셀·테두리·부모 배치의 재흐름과 ID 보존을 실제로 확인한다. 다른 외피까지 모두 이 모양으로 바꾸지 않는다.
- 한 본문의 선언문·번호 목록은 단일 글상자의 네이티브 문단 간격을 우선한다. 지원되지 않는 앱에서 의미상 독립된 항목만 각각 한 글상자인 column 자식으로 둘 수 있다. 이 경우 `gapMm`는 기준선 간격이 아니므로 실제 마지막·첫 기준선으로 확인하고, 내용 수정 의뢰에서는 뒤 항목과 외피의 재배치를 확인한다. 자동 줄별 분리나 그림을 감싸 흐르는 한 문단의 분리는 하지 않는다.
