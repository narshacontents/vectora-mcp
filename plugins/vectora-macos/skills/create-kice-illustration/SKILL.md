# 평가원 스타일 일러스트 제작

요청에서 내용·구도를 설계한다. 과거 기출이나 완성 예시를 복사/추적하지 않는다. 이번 요청에서 제공한 원본의 명시적 재현, 실제 인물·사물의 참조 검색, 승인된 지도 바탕은 허용한다. 기존의 10유형과 세부분류는 검색·기록용으로 유지하며 읽기 위계나 파일 수를 강제하지 않는다.

스타일 기본값은 **2028학년도 평가원 예시문항 시험지에서 추출한 형식**을 우선한다. 그 시험지에 없는 구성만 기존 평가원 기출 기준을 적용한다. 제작 시 원본 예시 열람을 요구하지 않고, 준비된 해당 구성의 지침으로 적용한다.

## 1. 요청을 제작 단위로 정리

표시할 원문·기호·강조·값·대응 관계와 그림에 표시하지 않을 출제 맥락을 구별한다. 실제 자료인지 가상/정성 자료인지, 최종 외곽 폭과 내부 예약 공간 치수, 신규/수정 범위를 확정한다. 내용의 의미가 달라지는 누락만 확인하고 일반적인 조판은 제작자가 결정한다.

간단한 의뢰는 자연어 그대로 받는다. 복합 자료는 원문·자료표·대응 관계를 충분히 자세히 받아도 된다. **짧은 프롬프트 자체가 목표는 아니며, 의미상 필요한 입력을 받아 첫 결과를 자연스럽게 만드는 것이 목표**다. 호출자에게 내부 분류 ID나 좌표·도구 필드를 작성하게 하지 않는다. 외부 출제 에이전트의 입력 도움말은 [의뢰 가이드](references/caller/exam-agent-guide.md)에 둔다.

- 배치에 맞는 recipe를 고른다. 대화는 vertical-dialogue / horizontal-dialogue / presentation, 매체는 newspaper / webpage / paper / scroll / board / worksheet, 교사와 칠판은 teacher-board다. 표·차트·도식·지도 등의 실제 지원 이름과 variant는 `--list`로 확인한다.
- 독립적으로 읽을 표·그래프·지도는 각각 unit으로 준비하고 한 그림으로 결합한다. 공유 장면의 외피·인물·보조 발언을 별도 완성 그림으로 쪼개지 않는다. 모든 구성요소의 필요한 규칙을 읽는다.
- 실제 인물/사진/새 원화, 실자료 조사, 산문, 밑줄, 문단 박스, 빈 공간 예약 등 **요청에 있는 조건**을 contains/dataSource에 포함한다. 한 문단이 그림 옆에서 아래로 이어지는 요청만 text-flow다. 실제 자료 조사 요청은 research다.
- 분류가 모호하면 [경로 판별](references/routing.md)의 관련 항목만 읽는다. 비교판과 분기 절차, 체크리스트와 교차표, 관측 선과 이론 곡선, 공유 칠판과 독립 대화, 실재 배치도/장소/옛 지도 등을 이름만 보고 같은 생성기로 치환하지 않는다. 분류 코드 자체는 MCP kind가 아니다.

## 2. 이번 작업의 지침 준비

스킬 루트에서 내부 임시 JSON에 **실제 제작 조건만** 적고 실행한다. 작업조건은 지침 선택용이며 그 자체를 Vectora에 보내지 않는다. 원문·데이터·인물 설명은 원 요청에서 그대로 가져온다.

```json
{"units":[{"id":"dialogue","recipe":"vertical-dialogue","contains":["prose","underline","inline-box"]}]}
```

```sh
node scripts/prepare_task.mjs --request <내부 작업조건.json> --out <내부 임시 폴더>
```

반환된 **readNow**를 읽고 설계한다. **beforeExecute**는 실제 제작 전, **beforeDeliver**는 검수·저장 전에 반드시 읽는다. 각 단계 문서는 중복 규칙을 한 번만 포함한다. 원본 조각을 전부 읽거나 유형/세부 파일을 별도로 다시 읽지 않는다. 선택 목록에 원 요청의 실제 조건이 빠졌으면 JSON을 고쳐 다시 준비한다. 인물은 자동 포함되는 조건부 구성요소이며 별도 파일 수 예외가 아니다.

네이티브 제작 입력을 준비했다면 해당 unit의 `spec`에 같은 입력을 넣어 지침 선택을 대조한다. 알려진 본문·서식·예약·인물·내부 자료 필드에서 필요한 원칙을 연결하고, 반환된 `inference`에 근거 필드를 남긴다. 일반 `table`에 실제 병합 셀이 있으면 병합표 지침으로 연결하며, 명시한 세부분류가 구조와 충돌하면 오류를 해결한다. 내부 자료의 의미상 분류가 모호하면 오류에 표시된 경로에 `specRecipes`로 recipe/variant를 지정한다. 추가된 지침을 제작 전에 읽는다. 이 점검은 누락 방지용이며 원문이나 native spec을 수정하지 않고, 앱의 실제 스키마 검사·자료 해석·이미지 검수를 대신하지 않는다.

별도 외피 없이 독립 자료들을 결합하는 최상위 composition은 각 자료 unit에 해당 child spec을 연결한다. 지침 준비만을 위해 요청에 없는 외피형을 선택하지 않는다.

추가 recipe/variant/조건은 `--list`, 입력 형식은 `--help`로 확인한다. 기존 세부 ID도 recipe 값으로 그대로 사용할 수 있다. contains에는 people / prose / underline / inline-box 및 실제 해당 feature 이름을 넣는다. dataSource는 research / provided / hypothetical / qualitative 중 하나이며 **실제 자료를 찾아 달라는 요청은 research**다. 한국 시도·시군구 등 국내 전용 지도를 제작할 때만 korea 조건을 선택한다. 세계·동아시아 지도에 한국이 포함된다는 이유만으로 선택하지 않는다. textMode는 labels / prose / none이며 IT 계열 기본은 prose다. 명시된 글자 없는 원화에만 none을 사용한다. 외부 출제 에이전트 의뢰는 최상위 caller:"exam-agent", Gemini CLI는 client:"gemini"를 지정한다.

## 3. 내용에서 배치를 계산하고 제작

원문·자료·최종 폭 → 실제 글/자산 측정 → 내용 영역 → 주변 요소·외피 → 최종 외곽 순서다. 필수 제약, 미지정 시 기본값, 조건부 규칙, 특정 오류의 임시 우회를 구별한다. 사용자 명시 조건은 기본값보다 우선하며 원문 의미·데이터 관계·편집 가능성을 희생해 맞추지 않는다.

문항 한 단의 폭은 약 108mm이며, 전체 단을 쓰는 자료는 미지정 시 실제 내용 외곽도 그 폭에 가깝게 제작한다. 부분 자료는 단 안의 비율이나 요청 폭을 따른다. 글자 크기로 그림 전체를 축소해 폭을 역산하지 않는다. 앱의 등록 문자 스타일을 본문·발언·표 셀·일러스트 라벨별로 선택하고 실제 pt·장평·자간과 검정 벡터 선을 유지한다. 등록 프리셋을 바탕으로 필요한 글자 크기를 변형하며, 작은 측정 차이마다 별도 스타일을 만들지 않는다. 고정 높이를 먼저 잡고 글을 억지로 넣거나 원본의 시각적 행마다 엔터를 넣지 않는다. 지원되는 네이티브 생성기로 최대한 만든 뒤 미지원 부분만 보충한다. 개체·자료 관계를 보존하고 실제 응답의 ID/리비전·단위를 사용한다.

**생성기의 기본 출력과 첫 완성본을 구별한다.** 제작 전에 선택 지침의 배치·선·문자·외곽 치수를 plan/기본값과 대조하고, 지원되는 설정과 필요한 보충 작업을 첫 조판에 포함한다. 이미 알려진 이름 위치·꼬리·구조선 차이를 이미지 검수 뒤 고칠 일로 미루지 않는다. 생성기 성공 응답만으로 모든 원칙이 적용됐다고 가정하지 않으며, 기본값 보충과 이미지 검수 후 보정을 따로 기록한다.

## 4. 실제 이미지 검수와 납품

첫 완성본과 **저장된 실제 JPEG**를 사용 크기와 확대에서 직접 본다. 내용·서식·대응 관계, 인물/꼬리·간격·불필요 여백·잘림을 확인하고 명백히 어색하면 수정한다. 첫 결과와 수정 후 결과를 구분한다. 최대 3회 수정 후 남은 문제는 미완료/도구 한계로 알린다. 자동 검사 통과를 시각 합격으로 대신하지 않는다.

납품은 기본 **같은 이름의 .vectora 1개 + .jpeg 1개**다. 사용자 지정 이름·폴더·형식이 우선이며 미지정 폴더는 현재 작업 공간이다. 실제 내용 외곽으로 아트보드를 맞춘 뒤 Vectora 저장·재열기·JPEG 내보내기를 검증한다. 지원되는 KICE 납품 프로필 또는 준비된 수동 경로를 사용한다. JPEG 자체를 대화에 표시하고 원본 링크를 제공한다.

## 유지보수 경계

각 규칙의 원본은 한 곳에서 관리하고 작업별 지침은 생성물로 취급한다. core는 안정적인 공통 원칙, recipes는 제작 순서/형식, components는 조건부 재사용 요소, execution은 실제 도구 계약이다. taxonomy는 분류 사전이다. 앱은 정확한 측정·편집 의미·자료 연동·저장/복원을 맡고, AI는 구도·정보 우선순위·적절한 여백·장식·다양성을 판단한다. 하나의 성공 예시를 고정 레이아웃이나 앱 기본 강제값으로 만들지 않는다. 인간의 주된 후속 편집은 수치 변경과 본문의 짧은 추가·삭제이므로, 제작자가 조판까지 끝내며 인간의 수동 폭 조절을 전제로 납품하지 않는다. 기능 오류의 우회책을 영구 화풍 원칙으로 만들지 않는다. 앱 수정이 필요하면 재현 입력·기대/실제 결과·수정 위치·완료 조건을 기록해 사용자가 지정한 앱 담당 채팅에 전달하며, 일반 제작 중 앱 코드를 임의 변경하지 않는다. 채팅 전송 권한이 없는 환경에서는 사용자에게 전달할 내용으로 남긴다.
