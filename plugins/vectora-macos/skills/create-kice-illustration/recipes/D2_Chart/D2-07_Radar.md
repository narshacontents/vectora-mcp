# D2-07_Radar — 방사형

중심 축 배치. 레이더·풍향장미

2028 예시문항의 **동일 크기 다각형 꼭짓점에 순위 숫자를 적는 비교 도식**은 반경이 값인 레이더가 아니다. 요청이 이 형식이면 동일한 외곽 실선·중심에서 꼭짓점으로 가는 가는 파선·꼭짓점 밖 숫자·공통 축 설명을 유지하고, 순위로 면적이나 반경을 바꾸지 않는다. 실제 반경 척도가 있는 정량 레이더나 풍향장미는 기존 해당 형식 기준을 적용한다.

라이브 스키마에 순위 모드가 있으면 정육각형 비교는 `kind:"graph",type:"line",chartStyle:"radar",dataFidelity:"exact",legend:"none"`와 `chartOptions.radarMode:"ordinal"`을 사용한다. 서로 다른 축 이름 6개를 categories에, 실제 양의 정수 순위 6개를 단일 series.values에 넣는다. 공통 축 설명은 같은 방향의 `radarMode:"ordinal-key",series:[]`로 만들며 더미 순위를 넣지 않는다. `radarPlotSizeMm`은 마주보는 꼭짓점 사이 길이이고 모든 비교 도형에 같은 값을 쓴다. `radarStartAngle`·`radarClockwise`도 맞추고, 라벨이 길면 패널 공간을 조정하며 순위나 도형 반경을 바꾸지 않는다. 순위 편집 후 원자료와 꼭짓점 문자가 함께 갱신되고 정육각형은 유지되는지 확인한다. 여섯 축이 아닌 도식에 이 모드를 억지로 쓰지 않는다.

중심에서 각 축으로 뻗는 거리·각도·순서를 확정한다. 범주 레이더는 동일 반경 척도와 같은 축 순서로 비교하며 서로 다른 단위 지표의 정규화는 제공된 근거만 쓴다. 폐합선·면적이 총량을 뜻한다고 추가 해석하지 않는다. 풍향장미는 방향별 각도·빈도/크기 매핑을 보존하고 레이더로 의미를 바꾸지 않는다.

값을 이은 채운 다각형과 원형 보조눈금이 필요하면 실제 numeric radar 계약의 `radarFill:true`, `radarRingShape:"circle"`을 우선한다. 채움은 계열의 `fill`을 사용하며 원자료 수정에 연결한다. 결측 방향을 임의 연결하여 닫지 않는다. 고정 척도의 작은 반복 도형에는 지원되는 `radarPlotSizeMm`으로 같은 외곽 지름을 명시한다. 이때 `widthMm`은 라벨을 포함한 배치 예산이고 실제 내용 폭은 더 작을 수 있으므로, 전체를 다시 확대해 지름을 바꾸지 않는다. 생략한 기존 자동 크기·다각형 고리·무채움과 순위 모드는 별개다. 부채꼴 풍향도는 이 다각형 옵션으로 대체하지 않는다.

지도 위 작은 반복 도형은 큰 독립 그래프의 굵기를 그대로 쓰면 내부 눈금이 뭉친다. 별도 지시가 없으면 자료선 0.2–0.3pt, 원형 눈금·방사선 0.1–0.2pt부터 실제 크기로 확인한다. 지원되는 `radarGuideStrokePt`는 numeric radar의 눈금·방사선만, `strokePt`는 자료선을 조절한다. 가는 실선 눈금은 `gridStyle:"solid"`로 명시하고, 공통 범례에도 같은 눈금·방위·지름 척도를 적용한다. 범례와 지도 속 기호가 서로 다른 선 표현을 갖지 않게 한다. 순위 도식이나 큰 독립 레이더에 이 작은 기호용 값을 일괄 적용하지 않는다.

`chartStyle:"radar",type:"line"`은 범주 3개 이상·primary만; `chartOptions.radarRings,radarStartAngle,radarClockwise,radarSpokeLine`을 지원 범위에서 쓴다. 모든 축에 같은 반경 척도를 적용하고, 수치 눈금은 가능한 한 실제 방사축 하나의 같은 쪽에 공통 눈금자로 모아, 어떤 반경을 읽는지 분명하게 한다. 자료선과 부딪히면 눈금열 전체의 쪽·간격·기준 축을 함께 조정하고, 숫자마다 따로 밀지 않는다. 숫자마다 방향을 바꾸거나 긴 안내선으로 축에서 멀리 떼어 놓지 않는다. 값·폭 변경은 기존 그래프의 자료와 치수를 갱신해 재조판한다. 명시적으로 요청한 눈금은 보존한다. 눈금 밀도가 미지정이면 최종 패널 크기에서 읽히는 일정 간격의 주요 수치부터 정하며, 보조 고리마다 숫자를 반드시 붙이지 않는다. 라이브 계약이 고리·숫자 밀도 분리를 지원하면 `radarRings`로 동일 간격 고리 수를, `ticks`로 표시할 수치를 정하고 실제 고리가 누락되지 않았는지 확인한다. 숫자들이 자료선을 가로지르는 긴 인출선을 요구하면 폭 배분과 수치 눈금 밀도를 먼저 재검토한다. 실제 척도나 자료값을 바꾸거나 연결되지 않은 고리·숫자로 대신하지 않는다. 풍향장미 부채꼴이 기본 관계 자체로 미지원이면 직접 벡터 계산한다. 수치 없는 `scaffoldOnly` 외곽 틀은 도식 의미이므로 정량 레이더와 혼동하지 않는다.

월별 방사형처럼 범주와 수량 단위가 함께 있으면, 기온·빈도 등의 단위는 수치 눈금이 모인 방사축 끝 가까이에 둔다. 월 같은 범주 단위는 대표 범주 표기와 가까이 묶고, 대응 축에서 떨어진 빈 모서리에 따로 두지 않는다. 단위와 바깥 범주 글자가 겹치면 축 값/단위 묶음의 한쪽 간격을 함께 조정한다.
