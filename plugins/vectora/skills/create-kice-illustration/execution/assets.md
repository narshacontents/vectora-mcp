# 포함 이미지의 보존



- 포함 PNG/JPEG 이미지로 가져오고 임시 경로 의존을 제거한다. vector asset 등록이 래스터를 거부하면 일반 이미지로 배치하며 등록을 위해 추적하지 않는다. 도구 연결 실패면 이용 가능한 실제 Vectora Editor 경로로 검사하되 파일 작성만으로 앱 저장·재열기를 주장하지 않는다. 앱 개발/외부 모델 설치로 범위를 넓히지 않는다.
- 자산의 역할과 좌표 기준을 실제 `vectora://production/asset` 계약에서 확인한다. 개별 화자 인물의 `headBounds`는 실제 머리 영역이고 `xMm/yMm`은 머리 중심이다. 풍경·사물·여러 사람이 함께 있는 장면에 가짜 머리 영역을 붙이지 않는다.
- 인물 위치를 잡는 머리 사각형은 정수리의 머리카락·귀·턱까지의 두개부를 감싼다. 턱 아래로 늘어진 긴 머리카락이나 목·어깨까지 포함해 이름과 꼬리의 기준점을 아래로 내리지 않는다. 머리 좌표는 원화의 자르기 범위가 아니므로 필요한 상체와 긴 머리 자체는 보존한다.
- 현재 스키마가 장면 계약을 제공하면 비인물 단품/장면을 `assetRole:"scene", reviewed:true, rasterPath, crop:"full"`로 등록하고 `sceneWidthMm`과 `xMm/yMm`으로 배치한다. 이때 폭은 실제 가시 원화 폭, 좌표는 가시 외곽의 왼쪽 위이며 비례를 유지한다. 머리 크기·머리 중심 필드는 섞지 않고, 개별 대화 화자는 인물 계약을 사용한다. 장면 계약이 없으면 일반 포함 이미지로 배치한다.
- `rasterPath`의 자동 범위는 알파 기준이다. 불투명한 흰 바깥 여백이 있으면 원화 전체를 늘려 맞추기 전에 실제 내용 외곽을 검수한다. 현재 계약이 지원하는 **포함 raster 입력의 `visibleBounds:{x,y,width,height}`**에 검수한 원본 픽셀 사각형을 지정하면 원본 바이트를 유지한 채 네이티브 이미지 크롭과 `sceneWidthMm` 배율에 반영된다. 이때 `rasterPath`와 `raster`를 함께 보내지 않는다. `raster`에는 원본 dataUrl·실제 mimeType·width·height도 필요하다. 바깥 여백만 제외하고 흰 물·구름·옷·연한 선과 내부 배경은 보존한다. 임의 임계값만으로 중요한 부분을 자르지 않으며, 다시 내보낸 JPEG의 실제 외곽과 재열기 후 크롭을 확인한다.
- 원화의 색·투명도는 최종 사용 크기와 실제 배경 위에서 판단한다. 미세한 RGB 채널 차이, 경계 안티앨리어싱, 눈에 보이지 않는 수준의 알파 차이만으로 불통과시키거나 원본을 다시 칠하지 않는다. 회색 출력에서는 실제 내보낸 회색 JPEG를 확인하며, 피부·옷이 배경을 눈에 띄게 비추거나 흰 사각 배경이 다른 요소를 가리면 수정 대상으로 본다.
- 이동·크기 변경 뒤 source 값만 보지 말고 실제 문서 좌표와 포함 픽셀을 대조한다. 지원되는 native update를 우선하며, 반복되는 좌표 수동 복구는 기본 제작 절차로 굳히지 않고 앱 문제로 기록한다.
