### 직접 설계한 외피의 내용 크기 연동

라이브 capabilities와 text/composition schema에 `frameDecorations`가 있으면, AI가 선택한 접힘선·종이 겹선·책 외곽 같은 보충 경로를 해당 내용 owner에 명시 연결한다. 외형 선택이나 곡선 설계를 생성기에 맡기지 않는다. 이미 자동 조판되는 기본 외피를 같은 경로로 중복 생성하지 않는다.

각 경로에 stable `id`, `layer:"back"|"front"`, M/L/Q/C/Z 명령과 실제 fill/stroke/strokePt를 지정한다. 각 좌표는 `{ratio,offsetMm}`이며 장식 추가 전 owner의 폭·높이에 ratio(0–1)를 곱하고 고정 mm를 더한다. 하단을 따르는 점은 y.ratio=1, 상단 고정은 0, 가운데는 .5를 출발값으로 삼되 모든 점을 같은 방식으로 늘이지 않는다. 세부 필드·허용 범위는 live schema로 확인한다.

장식은 내용 영역을 예약하거나 주변 자료를 밀지 않는다. 곡선/접힘의 공간은 내용 배치·패딩에서 먼저 확보하고, 바깥으로 나온 경로까지 포함한 실제 최종 외곽을 요청 폭에 맞춘다. plan의 내용 크기를 장식 포함 납품 크기로 오인하지 않는다. 표/그래프/본문을 경로로 바꾸거나 전체 그룹을 늘려 맞추지 않는다.

일반 본문 추가·삭제 또는 내부 표의 행 증감 뒤 하단/접힘과 뒤따르는 자료가 함께 늘고 줄어드는지 확인한다. 기존 내용·장식의 ID와 선 굵기는 보존하고, 새 행의 개체가 추가되는 것은 정상으로 구별한다. 이 연결이 표지 글의 시각적 균형이나 옆 그래프 높이까지 판단하지는 않으므로 실제 JPEG에서 검수한다. 형상 변경은 owner의 선언을 갱신하고, 해제는 live 계약의 null/빈 배열 경로를 쓴다. 미지원 앱에서는 편집 가능한 보충 경로와 AI 재조판을 유지하며 자동 연결로 보고하지 않는다.
