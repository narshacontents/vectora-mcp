### 화면 외피 구현

설계 단계에서 정한 외형을 실제 계약에 대응한다. 아래 옵션은 지원되는 기본 부품이며 전체 디자인 목록이 아니다. 선택한 외형이 옵션만으로 표현되지 않으면 native 내용의 편집·조판 연결을 유지하며 외피만 공개 편집 경로로 보완한다. 기존 문서 편집에는 저장된 외형을 보존한다.

브라우저 외피를 선택했을 때는 `variant:"browser"`이며, 탭의 사이트 이름은 `background.tabTitle`, 기사·자료 제목은 `title`에 넣는다. `headerHeightMm`/`titleHeightMm`으로 조작부/제목, `asideWidthMm`/`asideHeightMm`으로 옆 삽화 영역을 예약한다. 기본 aside는 본문 전체와 나란한 고정 열이다. 그림 옆에서 시작한 글이 그림 아래에서 전체 폭으로 이어지는 요청에는 감싸기 조판을 선택하며, 고정 열만 만든 상태를 완성으로 취급하지 않는다. `illustrationSlots`는 빈 자리이며 그림이 들어 있지 않다. 사이트 머리부만 있는 웹페이지·휴대폰·앱·방송 등 미지원 외피는 native 내용과 공개 편집 개체를 결합해 직접 구성한다.

라이브 스키마에 `background.chromeStyle`이 있으면 탐색 도구 중심 `classic`, 간결한 주소창 `simple`, 검색창 중심 `search` 중 외피를 고른다. 이는 본문의 내용 분류가 아닌 시각적 선택이다. 일반 안내·기사에도 여러 외피가 자연스러우므로 특정 내용이면 항상 같은 값을 고르는 대응표를 만들지 않는다. 항상 필드를 생략해 같은 기본 틀을 반복하지 않으며, 선택값은 저장하여 내용 수정·폭 변경·재열기 때 유지한다. 지원이 없으면 해당 필드를 보내지 말고 지원되는 편집 개체로 조작부만 보완한다.

새 브라우저의 조작부 높이를 요청하지 않았다면 `headerHeightMm`을 생략하고 네이티브 기본 조판을 먼저 사용한다. 라이브 계약의 `compact-v2`는 8pt 탭 제목과 두 줄 조작부를 위한 작은 기본값이며, 예전 기본 높이·허용 최솟값을 임의로 고정 입력하지 않는다. 기존 저장본의 정책이나 명시 치수는 유지하고, 조작부를 줄이려고 본문·탭 제목 글자를 축소하지 않는다.
