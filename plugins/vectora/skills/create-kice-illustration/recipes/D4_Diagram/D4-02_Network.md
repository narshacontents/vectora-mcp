# D4-02_Network — 관계도

임의 연결·인과·화살표 관계

임의 연결·인과·상호 관계이며 각 선의 방향과 관계명을 연결표에 대조한다. 순환은 각 출발/도착을 따로 검사하고 여러 종류의 흐름은 선종류/범례로 구별한다. 요청된 타원형 노드는 라이브 스키마가 지원할 때 네이티브 ellipse로 만들고, 원을 비균등 변형해 대신하지 않는다.

짧은 기호를 담은 소수 노드의 닫힌 관계도는 **노드 크기와 연결 통로를 함께** 정한다. 한 글자 원 노드와 짧은 관계 기호만 있는 경우, 이웃 원의 경계 사이 통로를 지름의 약 0.5–1배부터 검토한다. 이는 초기 배치의 기준이며 긴 관계명·교차·의미 있는 거리가 있으면 필요한 만큼 넓힌다. 최소 글상자에 맞춘 작은 원을 넓은 삼각형·사각형의 꼭짓점으로 멀리 벌리지 않는다. 거리 자체가 자료가 아니라면 관계 라벨·화살촉·대향선 간격에 필요한 만큼 통로를 잡고, 가운데 빈 면이 노드보다 두드러지면 노드 간 거리를 줄이거나 원의 지름을 키운다. 이때 라벨의 선택된 기본 글자 크기는 유지하며, 주자료를 강조하려고 문자까지 임의 확대하지 않는다. 옆 범례·예시와 높이를 맞추려고 연결선만 길게 늘리지 않는다. 보조 패널도 먼저 실측하여 주관계도와 비중·높이를 함께 조정하며, 예시의 노드가 주자료보다 강조되지 않게 한다.

윗변을 끊어 제목을 넣는 보조 상자는 **제목의 실제 표시 획**을 상자 가로 중앙에 놓고, 그 획 양끝에서 같은 여유를 뺀 위치까지 윗변을 그린다. 임의로 정한 선의 틈 중앙이나 넓은 글상자의 왼쪽에 제목을 놓지 않는다. 제목·문구 변경 시 획의 폭을 다시 재어 양쪽 윗변도 갱신한다. 범례·예시의 대응 열과 안쪽 여백을 맞추되, 설명이 짧다는 이유로 주관계도의 빈 통로를 늘리지는 않는다. 범례에서 선·화살표·표식은 본도와 같은 모양의 작은 견본으로 표시한다. 의뢰의 “화살표: 비판의 방향” 같은 관계 설명을 글자 “화살표”로 인쇄해 견본을 대신하지 않는다. 예시 설명은 보조 열에서 자연스럽게 줄바꿈하며, 한 줄에 모두 넣으려고 보조 열을 주관계도만큼 넓히지 않는다.

같은 노드 쌍을 잇는 대향 흐름은 가까운 평행 경로로 나누고, 지원되는 경우 서로 다른 cardinal attachment를 골라 작고 일정한 간격을 둔다. 라이브 스키마가 실제로 노출할 때만 `fromAnchorFraction`, `toAnchorFraction`을 cardinal anchor와 함께 선택적으로 쓰고, `viaPolicy:"orthogonal-v1"`은 필요한 직각 경로에서 문서화된 선행 조건을 만족할 때만 쓴다. 모든 선을 직각 경로로 강제하거나 고정 좌표·간격 템플릿을 만들지 않는다. 중앙 범례는 실제 항목 크기를 먼저 재어 필요한 자리만 확보하고 주변의 과도한 빈칸을 줄인다. 관계명·기호는 연결표가 가리키는 실제 선 구간에 놓고 텍스트가 늘어난 뒤 화살표 방향을 다시 확인한다. 관계명이 길어지거나 바뀌면 자동 줄바꿈 결과와 실제 잉크 폭·높이를 다시 재고, 문구 변경 후 첫 조판에서 해당 선과 상대 방향 선 사이 공간을 확보하도록 필요 시 지원되는 `labelOffsetMm` 또는 통로 배치를 조정한다. `labelOffsetMm`의 양수값이 항상 선 아래를 뜻한다고 가정하거나 임의 줄바꿈으로 간격을 만들지 말고, 라벨을 선 어느 쪽에 둘지는 실제 흐름과 공간에 맞춰 판단한다.

우회·곡선은 순환을 읽는 데 필요한 경우에만 쓴다. 인물 노드가 요청되면 이름·소속은 가까운 바깥, 관계명·기호는 연결 통로에 두며 말풍선 대화로 바꾸지 않는다. 얼굴 원화가 필요한 경우 전역의 원화 실행 규칙으로 실제 자산을 만들고 빈 인물 자리표시자로 끝내지 않는다. 노드의 affiliation/affiliationSide:left|right는 제공된 소속만 넣는다.
