- 복합형은 `kind:"composition",layout:"row"|"column"|"grid",widthMm,gapMm,maxHeightMm?,columns?,children`의 지원을 확인한다. 각 child는 안정된 고유 id와 native 자료 `spec`, 본문 `text`/`richText`, 빈 공간 `reserve` 중 지원되는 내용 형식을 가지며 선택 widthMm를 쓴다. grid에서만 columns를 쓴다. children은 최대32개, 중첩은 깊이6/총128개 한도다. 안정 ID와 수동 수정 보존을 확인한다. 내부 의미 단위는 각각 편집 가능한 컴포넌트로 유지하고 무조건 한 SVG로 평탄화하지 않는다. 무지원이면 기존 개체·그룹으로 같은 조판을 구성한다.
- row/grid에서 `child.widthMm`과 `sizing`을 생략한 트랙은 고정 폭과 간격을 제외한 나머지를 균등 배분받는다. 고정 폭이 필요한 자료만 `widthMm`을 지정하고, 비율 조정에는 라이브 계약의 `sizing:{mode:"flex",weight,minWidthMm?,maxWidthMm?}`를 쓴다(`widthMm`과 상호 배타적이며 column에서는 미지원). `sizing:{mode:"content",minWidthMm?,maxWidthMm?}`는 row/grid의 native table 자식에만, 사용 중인 Vectora의 live composition/schema 지원을 확인한 경우에만 쓴다. 실제 UND 무줄바꿈 고유 폭 측정으로 자동 열·일반 문자열 제목·병합 셀을 검증하고 남는 폭은 auto/flex 트랙에 배분한다. 지도·그래프 옆의 짧은 라벨·숫자 표는 사용자가 고정 폭을 지시하지 않으면 자동 표 열과 content sizing을 우선하고, 측정값을 `widthMm`/`column.widthMm`에 복사하지 않는다. 긴 서술형 표는 기존 wrap/flex 경로를 유지하고, live 지원이 없으면 기존 측정 최소 폭+flex 경로를 쓴다. 명시 열 폭·원문·글꼴을 보존한다. grid에서는 같은 열의 명시 정책을 일치시키며 미지정 자식은 그 열의 정책을 따른다.
- plan의 계산 결과를 모든 자식의 고정 치수로 되쓰지 않는다. 지원되는 외피/부모 폭 변경은 자식을 같은 정책으로 재조판하므로 먼저 부모 폭만 갱신하고 실제 글·8pt·지도 척도를 확인한다. 기존의 명시 고정 폭·열 비율은 임의로 바꾸지 않으며, 이를 축소할 때도 글이 자연스럽게 들어가는지는 별도로 검사한다. `LAYOUT_WIDTH_UNSATISFIABLE`이면 최소 폭·자료 비율·간격을 다시 설계하고, 문자 축소나 수동 좌표 보정으로 덮지 않는다.
- 같은 원자료를 표·지도·차트에 반복 표시할 때는 live capabilities의 `composition.sharedData`와 `vectora.shared-numeric/v1`에서 해당 연결 대상 지원을 확인하고 명시 연결한다. 지도 비례값은 record ID, 표 숫자는 cell ID, 지원되는 범주형 막대·선 차트의 `graphSeriesValue`는 series ID와 정확한 고유 범주명으로 연결하며 모두 안정된 child ID 경로를 쓴다. 같은 숫자라는 이유로 연결하거나 고정 참조 범례를 연결하지 않는다. 최초 표시값을 맞춘 뒤 owner의 `sharedData.rows`만 갱신한다. 소비자 직접 수정은 owner에서 수정하거나 명시적으로 연결을 해제하는 경로로 바꾼다.
- 행·열 합계도 연동할 때는 live 계약의 `sum:{rowIds:[...]}` 지원을 확인해 원자료 행만 참조한다. 총합은 중간 합계가 아닌 모든 해당 원자료를 참조하며, 최초 합계 캐시를 맞춘 후에는 직접 고치지 않는다. 100% 누적 그래프에도 원래 인원·수량을 연결하고 백분율은 생성기가 계산하게 한다. 0과 결측 null을 구별하며, 합계에 결측이 있으면 합계도 결측이다. 100% 누적 차트의 결측·합계 0 등 미지원 조건을 임의의 0으로 바꾸지 않는다. 최종 `.vectora`를 재열어 실제 수치 수정과 합계·차트 갱신을 확인한다.
- 공유하지 않은 내부 값은 `inspect`로 얻은 실제 자식 component ID에 `update`하여 owner를 통해 재조판한다. 공유 계약 미지원 시 표·지도·차트의 대응 값을 각각 명시적으로 갱신하되 한 `vectora_apply` 트랜잭션에 묶을 수 있으며, 이를 단일 원자료 자동 연동이라고 보고하지 않는다. 지원 차트 형식·합계 제한 등 세부 계약은 live resource `vectora://production/composition`을 따른다.
- 단순 사각 본문 카드가 필요하고 live table/schema가 `cells[].content`를 지원하면, 1셀 native table 안의 composition이 식별 표기와 본문을 소유하도록 구성할 수 있다. 셀은 `text:""`, richText 생략, state 생략 또는 `value`이며 실제 본문은 content 안에 한 글상자로 둔다. 테두리·안쪽 여백은 컨테이너가 맡고 행 높이를 미리 고정하지 않는다. 독립 카드마다 컨테이너를 나누면 서로 다른 본문 높이를 유지한다. 일반 본문 `replaceTextRange` 뒤 셀·테두리·부모 배치의 재흐름과 ID 보존을 실제로 확인한다. 다른 외피까지 모두 이 모양으로 바꾸지 않는다.
- 선언문·번호 목록에서 문단 사이 간격만 본문 행간과 다르게 지정해야 하고 단일 글상자의 문단 간격 기능이 없으면, 의미상 독립된 문단/항목을 각각 한 글상자인 column 자식으로 둔다. 문단 내부 자동 줄바꿈과 들여쓰기는 유지하고 화면의 행별로 나누지 않는다. `gapMm`는 프레임 사이 거리이므로 앞 문단 마지막 기준선과 다음 문단 첫 기준선을 실측해 목표 간격을 맞춘다. 종이 외피가 이 column을 소유하게 하여 짧은 본문 편집 후 다음 항목과 외피가 함께 이동하는지 확인한다. 한 문단이 그림 옆에서 아래로 이어지는 본문은 이 방식으로 쪼개지 않는다.
