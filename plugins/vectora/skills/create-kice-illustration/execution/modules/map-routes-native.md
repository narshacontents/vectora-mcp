# 지도 지점을 잇는 네이티브 경로

- 연결된 앱의 live `vectora_map_plan` 스키마와 기능 목록에 `routes` 및 `from`·`to`·`gapMm`가 공개된 경우에만 일반 경로 native 실행을 사용한다. 소스 코드·정적 스키마·추가 필드 허용만으로 실행 지원을 추정하지 않는다.
- 같은 지도의 geographic point overlay ID를 `from` → `to`로 잇는다. 지점 좌표를 바꿔도 ID를 유지하며 원자료 좌표를 만들거나 배치를 위해 이동하지 않는다.
- 일반 `routes`는 출발점에서 도착점으로 향하는 **직선 방향 화살표**다. 실제 항로·대권·곡선·무방향 관계·이동량 표현으로 확대 해석하지 않는다. 일반 단순 경로의 기본 선폭 0.3pt를 유지한다.
- `routes`·`overlays` 배열 patch는 전체 교체이므로 삭제 요청이 없는 기존 항목을 모두 보존한다.
- 폭/창·crop·도법·원점을 바꾼 뒤 점과 경로 ID, 0.3pt 물리 선폭, 점의 외곽 획에서 잰 `gapMm`, 화살촉과 도착점 대응을 확인한다.
- 지점 누락·잘못된 anchor·도법 또는 창 밖 지점은 명시적으로 실패 처리한다. 경로를 몰래 생략하거나 원 지점을 창 안으로 옮기지 않는다.
- 사용자가 독립 편집을 요청한 경로만 실제 production 객체 ID로 detach하고 현재 기하가 보존되는지 확인한다.

## 선택적 정량 흐름

- flow-map에서만 다룬다. 연결 앱의 live `vectora_map_plan` 기능·스키마가 top-level `flow`를 명시적으로 공개하고 native 수용을 확인했을 때 `TemplateMapSpec.flow`를 사용한다. 새 로컬 계약이나 UI 구현만으로 native 지원을 선언하지 않는다.
- live 응답이 `report.flowPreflight`를 제공하면 `passed`를 확인한 뒤 생성한다. `blocked`는 8pt 범례·지리·화살표·확대창의 실측 충돌 등 생성 전 실패이므로 원자료와 지리 앵커를 보존한 채 지도 창·예약 공간을 다시 계획한다. 이는 새 구성요소의 사전 검사이며 기존 수동 편집 상태·저장·재열기·JPEG 검수를 대신하지 않는다. 필드가 없으면 검사됐다고 추정하지 않는다.
- `flow`에는 필수 단위·자료 출처, 0–200개 자료 행, 1–8개 등급, 안정 ID가 있는 범례를 둔다. `flow.unit`은 저장된 수량과 범례의 authored 단위다. 사용자가 준비 단계의 단위 환산을 명시했다면 한 번 수행하고 원자료 단위·출처와 결과 단위를 밝힌다. 각 행은 같은 지도의 서로 다른 geographic point ID인 `from`/`to`와 유한한 비음수 원수량을 가진다. 0도 기록에서 제거하거나 바꾸지 않는다. flow 작성 뒤에는 편집·자료 갱신 때 원수량이나 스타일을 조용히 다시 환산·조정하지 않는다. ID는 새 항목에만 안정적으로 부여하고 기존 값을 보존한다.
- 등급은 `[0,∞)`를 빈틈·겹침 없이 덮고 시작 하한은 0이다. 각 비최종 등급의 `maxExclusive`는 그 등급의 `minInclusive`보다 크고 **바로 다음 등급의 `minInclusive`와 같아야** 한다. 마지막 등급만 `maxExclusive:null`로 둔다. 등급별 문구와 0.2–3pt 선폭을 연결하고 선폭은 순서대로 엄격히 커져야 한다. 범례 배치는 `inside-top-left` 또는 `below`, 선택 간격은 0–10mm(기본 1)다. 범례 문구와 단위는 등급에 대응시킨다.
- 범례 제목의 지표·단위와 각 등급의 문구를 구분해 같은 문장을 두 번 표시하지 않는다. 단일 화살표 표본 옆 문구에 단위까지 들어 있으면 한 행으로 충분하다. live schema가 `flow.legend.showTitle`을 지원할 때 `false`로 제목 행만 생략할 수 있으며, 저장된 `flow.unit`과 값·등급은 유지한다. 단위가 다른 곳에도 표시되지 않은 다중 등급 범례에서는 제목을 유지한다. 지원되지 않는 필드를 추정해서 보내지 않는다.
- live schema가 해당 선택 필드를 허용하면 record `stroke`는 `#RRGGBB`(기본 검정), `gapMm`은 0–5(기본 0.25)만 사용한다. 등급 선폭은 mm나 일반 경로의 0.3pt로 바꾸지 않는다.
- 화살표 옆에 수치를 표시할 때 live schema가 `flow.records[].valueLabel`을 지원하면 해당 행에 지정해 **그 행의 `value`와 연결된 숫자**로 만든다. 지원되는 `offsetMm`는 실제 경로 중간에서의 물리 mm 이동이며 원 지리 앵커를 옮기는 값이 아니다. 별도 글상자에 숫자를 복사하지 않고, 단위는 범례에서 한 번 읽히게 한다. 위치는 최종 크기에서 해안·경로·다른 기호와 대조해 정하며, 값 변경 뒤 숫자·등급 선폭·범례와 저장/재열기 상태를 함께 확인한다. 0은 원자료에 남기되 보이지 않는 흐름에 떠 있는 숫자만 남기지 않는다. 미지원 앱에서 추가한 수치는 비연동 보충임을 밝힌다.
- 관리 지도에 자료를 갱신할 때 기존 binding과 점·flow의 안정 ID, endpoint, 원수량, 단위, 출처, 등급을 요청 없이 reset/detach하거나 교체하지 않는다.
- 현재 flow 계약은 **등급화된 화살표**만 정의한다. 연속 비례 폭, 실제 항로·대권·곡선 기하를 지원한다고 추정하지 않는다. 그런 표현이 요청된 경우 지원되는 지도·지점 연결은 보존하고 미지원 수량 경로와 범례만 별도 벡터로 보충한다. 보충 연결은 수동/비연동으로 설명하며 전체 관리 지도를 detach하지 않는다.
