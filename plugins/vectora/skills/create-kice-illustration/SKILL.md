# 평가원 스타일 일러스트 제작

요청의 내용에서 새 그림을 설계한다. **일반 생성은 기출을 읽지 않고 이 스킬의 형식·원칙으로 수행한다.** 사용자 제공 원본의 명시적 재현, 실존 대상/실자료 참조와 승인된 지도 바탕은 허용한다. 구성·장식의 다양성은 AI가 판단하며 성공 예시를 고정 템플릿으로 반복하지 않는다.

## 1. 요청 → 필요한 지침

표시할 원문·값·단위·기호·강조·대응 관계와 표시하지 않을 출제 맥락을 구별한다. 신규/수정 범위, 실제 자료/가상 자료, 전체 외곽 폭·내용 예약 크기·저장 위치를 확인한다. 의미를 바꾸는 누락만 질문하고 배치·여백은 제작자가 결정한다. 복잡한 의뢰는 자세한 문장/자료표를 받아도 된다. 호출자에게 분류 ID·좌표·도구 필드를 요구하지 않는다.

스킬 루트에서 `node scripts/prepare_task.mjs --list`로 recipe/조건을 확인하고 내부 임시 JSON을 만든다. **원 요청**에서 필요한 요소를 먼저 고르며, 아직 만들지 않은 spec에 없다는 이유로 빼지 않는다.

```json
{"units":[{"id":"talk","recipe":"vertical-dialogue","contains":["prose","underline","inline-box"]}]}
```

```sh
node scripts/prepare_task.mjs --request <내부 작업조건.json> --out <내부 임시 폴더>
```

- 기본 입력은 `recipe`, 실제 추가 요소 `contains`, 필요한 `variant`다. 독립 표·그래프·지도는 각각 unit으로 준비해 결합하고 공유 장면의 외피·인물·발언을 독립 완성 그림으로 쪼개지 않는다.
- 실자료 검색 요청은 `dataSource:"research"`, 제공/가상/정성 자료는 각각 provided/hypothetical/qualitative로 구분한다. 인물·사진·새 원화·산문·밑줄·문단 박스·예약 등 요청 조건을 포함한다. 작은 평면 조작 아이콘만으로 artwork를 선택하지 않는다.
- 분류가 애매할 때만 [경로 판별](references/routing.md)의 해당 항목을 읽는다. 공유 칠판/독립 대화, 비교판/절차 분기, 관측선/이론곡선, 질적 기호/비례 지도는 이름보다 자료 의미로 나눈다. 한 장면의 발언도 실제 방향의 speech-horizontal/vertical/solo를 포함한다.
- 실제 native spec을 마련했으면 같은 unit의 `spec`으로 다시 준비해 추론된 자식·서식·미검사 경고를 대조한다. 세부 입력/충돌 해결은 [작업조건](references/task-input.md)을 필요한 경우만 읽는다. spec은 자동 변경되지 않는다.

반환된 **readNow**로 설계하고, **beforeExecute**는 실행 직전, **beforeDeliver**는 저장/검수 전에 읽는다. 파일 안의 조건부 상세 링크는 그 상황일 때만 읽고 원본 조각을 전부 다시 읽지 않는다. 선택 목록을 원 요청과 대조해 누락을 보완한다. 지침 준비는 자료 해석·스키마 검사·시각 검수를 대신하지 않는다. 단계 문서 안의 경로는 스킬 루트 기준이다.

## 2. 설계 → 제작

준비된 지침의 제작 계획에 따라 **보존할 내용·요소 관계·구현/확인 방법**을 내부 `plan.md`에 짧게 남긴다. 실제 글/자산 측정 → 자료 좌표·내용 영역 → 외피·인물·주변 요소 → 실제 외곽 순서로 만들며, 측정 결과에 맞춰 계획을 갱신한다. 지원되는 네이티브 생성기를 우선하고 미지원 부분만 보충한다.

- **필수:** 원문 의미·자료 관계·편집성·명시 조건을 보존한다. 실제 응답의 ID·리비전·단위를 쓰며 한 텍스트 덩어리는 한 편집 가능한 글상자로 만든다.
- **미지정 시 기본:** 전체 문항 단 자료는 실제 외곽 약108mm, 부분 자료는 그 안의 비율. 문자 역할에 맞는 UND 3.1 등록 스타일과 검정 벡터 선으로 시작한다. 글자를 8pt에 맞춰 전체 그림을 축소하지 않는다.
- **AI 판단:** 묶음의 소속·읽는 순서·정렬·여백·장식·범례 위치를 실제 내용으로 선택한다. 기본값은 출발점이며 사용자 조건이 우선한다. 생성기 출력의 알려진 부족함은 첫 조판에 보충하고 시각 보정을 허용한다. 원문/글 크기/데이터를 바꾸어 공간 문제를 숨기지 않는다.

## 3. 실제 이미지 검수 → 납품

첫 완성본과 **저장된 실제 JPEG**를 사용 크기/확대에서 직접 보고 원 요청·계획과 대조한다. 내용 오류·배치 오류·편집 구조 오류를 구분해 원인에 해당하는 부분을 수정한다. 수정 대상과 보존할 부분을 기록하고 영향받은 주변 배치와 완성본 전체를 재확인한다. 최초/수정 후 결과를 구분하되 시각 보정은 허용한다. 수정 3회를 기본 예산으로 삼고 개선 가능성/요청 범위로 계속 여부를 판단하며 같은 실패나 도구 한계는 숨기지 않는다.

기본 납품은 **같은 이름의 .vectora 1개 + .jpeg 1개**다. 지정 이름·폴더·형식이 우선이며 없으면 현재 작업 공간을 쓴다. 내용 폭을 먼저 맞추고 실제 내용 외곽으로 대지를 맞춘 뒤 저장·재열기·내보내기를 검증한다. JPEG 자체를 대화에 표시하고 원본 링크를 제공한다.

## 범위

앱은 측정·편집 의미·자료 연동·저장 복원, AI는 구도·우선순위·여백·다양성을 맡는다. 인간의 짧은 글/수치 편집까지 보존하되 인간의 반복 위치·폭 보정을 전제로 납품하지 않는다. 일반 제작 중 앱 코드를 고치지 않는다. 기능 오류는 재현 입력·기대/실제·위치·완료 조건을 정리해 전송 권한이 있는 지정 앱 담당 채팅에 전달하거나 사용자에게 남긴다. 오류 우회를 영구 화풍 규칙으로 만들지 않는다.

외부 출제 에이전트에는 [의뢰 가이드](references/caller/exam-agent-guide.md)를 전달한다. 내부 분류는 검색/기록용이며 고정 읽기 위계나 파일 수를 요구하지 않는다.

### Claude 로컬 실행 경계

Claude에서 현재 노출된 MCP 도구 목록으로 Vectora 연결·실제 도구 이름·입력 스키마를 확인한다. 플러그인 접두사가 붙을 수 있다. 로컬 MCP는 Claude Code와 Claude Desktop Cowork 로컬 세션에서 사용하며 일반 웹/클라우드에는 자동 연결되지 않는다. MCP가 없으면 비최종 설계안만 준비하고 로컬 편집·저장·재열기·내보내기를 완료했다고 주장하지 않는다.

Claude 코드 실행 첨부 경로는 로컬 앱·글꼴 경로와 별개일 수 있다. 실제 노출된 vectora_fonts 및 제공되는 vectora_check_font/vectora_measure_text를 사용하고, SVG 문자열/data URL은 가져오기 스키마가 허용할 때만 전달한다. 첨부 경로를 Vectora 저장 경로로 재사용하지 말고 사용자가 지정한 실제 로컬 경로를 사용한다. Claude Code 로컬 플러그인에서는 번들된 보조 스크립트를 사용할 수 있다.

이 패키지는 이미지 생성 모델을 포함하지 않는다. 먼저 현재 세션에 실제 연결된 외부 이미지 생성/편집 MCP 등의 도구를 확인한다. 있으면 이번 작업에 준비된 제작·인물 지침의 해당 화풍 계약·참조 검색·배경 조건을 해당 도구의 실제 스키마에 맞춰 전달한다. 생성 결과는 실제로 열어 대상·화풍·배경을 확인하고 Vectora가 접근 가능한 로컬 파일 또는 지원되는 data URL로 가져온다. 원격 URL이나 Claude 첨부 경로를 로컬 파일 경로로 간주하지 않는다.

생성 도구 부재의 재사용 검토·생성 프롬프트·비최종 조판·미완료 보고는 작업 지침의 「새 원화와 참조 검색」 규칙을 적용한다.
