## 조건부 확대·패널·보완 자료

먼저 위치도와 확대 상세도의 방향을 구분한다. 연결 앱의 live `vectora://production/map/schema` 및 `vectora_production`/`vectora_map_plan` 기능이 native `locators`를 공개하고 수용할 때 자식 지도를 `TemplateMapSpec.locators`로 주 지도에 소유시킨다. 기본 locator는 주 지도의 실제 crop 범위를 자식 지도 안에 그려 더 넓은 지역 맥락을 보여 준다. `extent`를 생략하거나 선 스타일 객체를 쓰면 이 기존 부모 범위 동작을 유지한다. 같은 live 계약이 literal `extent:false`도 명시적으로 지원할 때에만 locator를 지리적 확대 삽입도로 사용해 **자식 확대 지도 안에 주 지도 범위선을 만들지 않는다**. 자식은 부모 소유·고정 모서리 배치를 유지하며 부모 crop의 역투영이나 범위 경로는 만들지 않는다. `false`일 때 범위선 스타일 필드는 보내지 않는다. 새 로컬 계약·UI·정적 schema만으로 설치 앱의 native 수용을 단정하지 않는다. native 지원이 확인되지 않거나 요청한 범위 방향을 지원하지 않으면 기존 독립 편집 지도와 수동 표시 fallback을 쓰고 연결이 수동·비연동임을 알린다. locator는 창 사이 자동 대응 연결선을 약속하거나 추정하지 않는다. 같은 source의 원형 상세 확대는 기존 `magnify` 관계를 따른다. 각 자식 `spec`은 별도 `assetRef`/`sidecarRef`/해시, crop, projection 등록을 유지하며 계층형 locator spec은 그대로 보존하고 별도 map unit이나 composition으로 펼치지 않는다.

locator는 안정적이고 부모별로 유일한 `id`, `spec`, `widthMm`(필수 1–108mm), `anchor`(`top-left`/`top-right`/`bottom-left`/`bottom-right`), `gapMm:{x,y}`(필수, 0 이상)를 가진다. 자식 `xMm`/`yMm`은 보내지 않고 선언된 `frameMm`의 원점은 `(0,0)`으로 둔다. 폭은 자식 `spec.widthMm`와 frame 폭에 우선한다. 높이는 선언된 frame 비율을 따르고 frame이 없으면 crop 비율을 따른다. 앵커와 안쪽 간격은 범례·바깥 여백이 아닌 주 지도의 geographic viewport frame 기준이며, 들어가지 않으면 배치를 줄이거나 왜곡하지 말고 명시적 fit 실패를 해결한다. 지도당 8개, 전체 32개, 중첩 깊이 4단계를 넘기지 않는다.

위치도 관계의 주 범위선은 locator가 소유한 파생 경로다. 주 지도의 실제 geographic crop 경계를 자식의 독립 등록·crop·projection으로 재투영한다. `verifiedIds`, feature 선택이나 수동 가시성으로 범위를 추정하지 않는다. 기본은 채움 없는 검정 0.3pt 실선이며 `extent`에서는 stroke/폭/dash만 조정한다. 지원되는 위치도 관계에서는 native locator가 범위선을 소유하므로 직접 그리거나 독립 객체로 만들지 않는다. 확대 상세도 관계에서 live 계약이 `extent:false`를 지원하지 않는 경우에만 수동 fallback을 명시해 사용한다. 주/자식 등록 누락, 역투영 불가·horizon·seam 모호성, 범위선 비가시, fit 불가 진단은 그대로 해결하고 임의 범위선으로 가리지 않는다. 여러 source blob과 저장된 native 편집은 같은 부모 소유 관계를 유지한다.

- locator/inset은 원범위와 확대창의 관계를 정확히 표시하며 연결선을 이동 경로와 구별한다. 각 창의 바탕·mask·좌표 등록·배율을 따로 기록하고 같은 주제 비교에는 공통 척도/등급/범례를 우선한다. 독립 척도면 표시한다. 다른 관찰 방향/도법은 해당 조건의 별도 검증 바탕이 필요하다.
- 보조 위치도는 국토와 대상 위치를 알아볼 수 있는 작은 크기로 계획한다. 주 지도 옆/아래의 빈 띠가 위치도 때문에 과도하게 커지면 두 창의 크기·가로세로비·간격부터 재배치한다. 고위도 국가 전체를 보여줄 때는 주 지도의 국지 도법을 그대로 복제하지 말고 승인된 해당 지역 도법과 필요한 범위를 골라 국토가 창을 고르게 채우게 한다. 지도 자체를 가로·세로로 다르게 늘이지 않는다.
- 요청된 두 창 사이의 확대 대응선은 별도 지리 관계나 수동 벡터로 준비·검수할 때만 그린다. 창 테두리에서 대응점을 짧고 명확하게 연결하고 지도 내용·축척 숫자를 관통하지 않게 한다. locator가 이런 창 사이 연결선을 자동 생성한다고 가정하지 않는다. 축척 숫자는 실제 막대 끝과 대응이 읽히게 두며, 막대가 짧으면 위·아래 배치 등으로 글자를 분리한다. 글자 폭에 맞춰 막대의 물리 길이를 늘리거나 숫자를 먼 빈 공간으로 밀지 않는다. 폭·범위 변경 후 창의 대응점과 축척을 원 좌표·거리에서 다시 검증한다.
- 대응선이 빈 공간이나 위치도를 길게 가로지르는 우회 사각형처럼 보이면 충돌만 없다는 이유로 통과시키지 않는다. 확대 범위의 대응 모서리와 주 창을 짧고 명확하게 잇도록 창·범례·축척의 배치를 함께 고친다. 경위도 라벨은 해당 눈금 쪽 문자 끝을 정렬해 짧은 글자만 눈금에서 멀어지지 않게 한다.
- production magnify의 sourceId/sourceRegionMm/targetRegionMm은 문서 범위 `{xMm,yMm,widthMm,heightMm}`를 원형으로 복제한다. LOD/새 도법을 만들지 않는다. 사각 view는 별도 작업본·경로·clip으로 조립한다. 패널·원자료 이미지·라벨·범례를 독립 편집 가능하게 두며 잘린 프레임 조각을 새 패널로 추정하지 않는다.
- 실제 래스터/위성영상은 원자료 그대로 포함하고 문자·범례는 벡터로 둔다. import/crop/늘이기는 재투영·warping이 아니다. 없는 자연자료를 imagegen/임의 등치선으로 대체하지 않는다.
- native 선이 있어도 실제 출력에서 지리선이 흐리면 통과가 아니다. 필요시 같은 원지리 벡터에 동일 변환·정확한 창내 clip을 적용한 독립 native 선 overlay로 보완할 수 있으나 자동 기능으로 가정하지 않는다. 래스터 따라그리기·눈대중 단순화·원기하 삭제/clip 해제로 숨기지 않는다. 중첩 변환은 선 스타일을 먼저 정해 같은 배율을 적용하고 재열기 정합이 깨지면 원프리셋부터 복구한다.
