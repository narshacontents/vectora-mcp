# 제작 계획

생성 전에 내부 작업 폴더의 `plan.md`에 아래 판단을 짧게 남긴다. 단순 그림은 한 문단이면 충분하며 새 양식·좌표를 의뢰자에게 요구하지 않는다. 원문·데이터·규칙 전문을 복사하지 말고 입력 파일/단위 ID를 참조한다. 계획은 사용자 요청을 대신하지 않는다.

- **보존할 내용:** 표시할 내용과 숨길 출제 맥락, 실제/가상 자료 구분, 값·단위·기호 대응, 사용자 지정 폭/예약 영역·수정 범위. 의미를 좌우하는 미확정 정보만 질문한다.
- **배치할 관계:** 주자료·비교·설명·공통 표기의 소속과 읽는 순서, 공유할 정렬선/축/범례, 가릴 수 없는 부분. 수치는 측정 후 정하고 복합형은 `core/composition.md`에 따라 한 장면으로 설계한다.
- **구현과 확인:** 사용할 네이티브 생성기·별도 보충 부분, 실제 글/자산을 측정할 순서, 이 그림에서 특히 확인할 내용·배치·편집성 조건. 선택한 기본값과 명시 조건을 구별하고, 미지원 기능을 지원한다고 가정하지 않는다.

측정이 예상과 다르면 자료 의미·문자 규격을 보존하면서 배치 선택을 갱신한다. 생성 후 계획의 단위에 실제 component/개체 ID와 보충 개체의 소속을 연결해, 수정 대상과 함께 움직일 부분을 찾을 수 있게 한다. 단순 그림은 반환 spec/inspect 기록을 참조해도 된다. 앱의 `production_plan`은 치수·유효성 측정 도구이며 이 설계 판단이나 완성 이미지 검수를 대신하지 않는다.

첫 이미지부터 원 요청과 계획을 함께 대조한다. 문제가 있으면 `core/review.md`의 원인 분류로 해당 부분을 고치고, 변경한 판단만 계획에 갱신한다. 이 기록은 내부용이며 기본 납품 파일을 늘리지 않는다.
