# 출제 에이전트의 일러스트 의뢰

출제자는 문항의 평가 요소·정답·자료 타당성을 결정하고, `create-kice-illustration`을 실행하는 제작자는 구도·조판·원화·편집 가능한 Vectora 문서와 JPEG를 만든다. 스킬 이름은 MCP 함수명이 아니다. 실행 환경의 스킬 로딩/위임 기능으로 호출하고, 실제 Vectora 도구와 필요한 파일에 접근 가능한 에이전트에게 맡긴다. 다른 머신의 경로만 전달해 파일을 공유했다고 간주하지 않는다.

## 간단한 그림과 복합 자료

간단한 그림은 자연어 한두 문장과 표시할 내용이면 충분하다. 복합형은 자세한 설명, 표/JSON 원자료, 첨부 파일을 함께 준다. **프롬프트를 억지로 짧게 줄이지 않는다.** 내부 recipe·분류 코드·MCP 인자·개체 좌표까지 호출자가 설계할 필요는 없다.

최소한 다음을 알 수 있어야 한다.

- **보여 줄 내용과 관계**: 원문·값·기호·화자·방향·포함 관계·빈칸·강조, 또는 이것들을 얻을 조사 지시.
- **자료의 성격과 바꾸면 안 되는 조건**: 실제 제공/실제 조사/가상/정성 자료인지, 무엇을 비교·읽게 할 것인지. 제작 의도·정답·해설은 표시할 문구와 분리한다.
- **작업 범위**: 새 그림인지 기존 파일의 수정인지. 수정이면 실제 원본과 변경/유지 항목을 준다.

문항/그림/의뢰 버전, 외곽 폭, 높이 제한, 저장 폴더·파일명은 필요한 경우만 덧붙인다. 본문에 없는 정답·제목·이름·기관·연도를 제작자가 채우게 하지 않는다. 모순이나 의미를 바꾸는 누락만 확인하고, 평가 의미에 영향 없는 배치·여백·장식은 제작자가 선택한다.

## 자료별로 빠뜨리면 안 되는 정보

| 자료 | 의미상 필요한 입력 |
|---|---|
| 수치 표·차트 | 범주·계열·시점·값, 단위·분모·소수 자릿수·결측. 축 범위/생략/범례는 특별히 유지할 조건만 지정한다. 결측을 0으로 쓰지 않는다. |
| 실자료 조사 | 지표 정의·지역·기간/기준 시점·단위·선호 생산 기관 또는 원표/직접 URL. 확인되지 않은 값을 만들지 않는다. 반올림·단위 환산이 허용되는지 밝힌다. |
| 이론 그래프 | 축의 뜻, 곡선·경계·영역·교점·이동의 관계, 꼭 표시할 점·구간, 수치 눈금이 필요한지. 정성 개형에 임의 숫자를 붙이지 않는다. |
| 지도 | 지리 범위, 위치·영역·이동, 지명 표시 여부, 행정 경계 기준 시점, 통계 공간 단위. 실제/가상을 구별한다. |
| 대화 | 화자별 이름과 발언 원문·순서·강조·빈칸. 반복 화자를 구별한다. 화자 수와 발언 수는 다를 수 있다. |
| 새 인물·장면·사물 | 식별 대상, 읽혀야 할 행동·관계·필수 소품. 특정 시점·신체 범위가 필요하면 지정한다. 실제 인물/유물의 정확한 이름이 있으면 제작자가 참조 이미지를 조사한다. |
| 사진·기존 원화 | 실제 파일/URL, 재사용·보존 범위. 원본 사진 사용과 선화 재작화를 구별한다. 같은 인물을 유지하려면 원화와 대상 대응을 전달한다. |
| 본문과 내부 자료 | 전체 본문·실제 문단, 밑줄/박스의 대상 문자열, 삽입될 표·그래프·사진과 위치 관계. 시각적 행 끝은 강제 개행 조건이 아니다. |

최종 그림 폭과 내부 텍스트 상자의 치수는 별개다. N줄 예약이면 적용 너비와 줄 수를 전달한다. 독립 자료 여러 개를 한 그림에 넣을 때 공통 시점·값·기호의 대응을 적고, 바뀔 때 함께 갱신되어야 할 원자료를 구별한다. 외피·장식 하나마다 별도 자료로 나누지 않는다.

## 복합형 의뢰 예시

아래 형식은 선택 사항이며 MCP 스키마가 아니다. 필요한 항목만 채운다.

```text
create-kice-illustration 스킬로 아래 자료를 한 그림으로 만들어줘.
[역할] 두 시점의 지역별 이용 인구 차이를 표와 그래프로 비교하게 할 자료.
[표시할 글] 제목 ‘문화 시설 이용’, 본문 ‘다음은 세 지역의 이용 인구이다.’
[자료] 가상 자료, 단위 천 명. 행 A/B/C, 열 2015/2025.
값 A=20/35, B=30/25, C=15/40. 표와 묶은 막대그래프에 같은 값을 사용.
[관계] 위에 본문, 아래에 표와 그래프를 함께. 두 연도의 범례 대응을 유지.
[유지/금지] 값을 임의 환산하지 말고 순위·증가폭·정답 해설은 추가하지 말 것.
[치수/납품] 실제 외곽 폭 102mm. 현재 작업 공간에 12_그림1로 저장.
배치·표와 그래프의 폭 배분·소박한 외피는 제작자가 결정해줘.
```

원문에 삽입할 박스·밑줄·특정 위치 이후 들여쓰기처럼 기능 요구가 있으면 대상 문자열과 뜻을 설명한다. 호출자가 공백이나 강제 엔터를 반복해 시각적 정렬을 만들어 전달하지 않는다.

## 제작과 납품 계약

- 제작자는 최신 스킬의 작업별 지침을 준비해 해당 단계만 읽는다. 설치 버전 숫자만으로 기능을 보장하지 않고 연결 앱의 실제 capability·명령·schema를 확인한다. 상세 도구 사용법은 제작 스킬이 담당하며 호출 문서에 중복하지 않는다.
- 사용자 명시 조건과 필수 보존 원칙을 우선한다. 글꼴·선·폭·원화 화풍의 기본값은 제작 지침의 단일 원본을 따른다. 호출자가 모든 기본값을 반복 입력하거나 앱 기본값과 다르게 고정할 필요는 없다.
- 실제 자료·특정 인물·유물은 필요한 참조를 확인한다. 과거 완성 예시를 찾아 복사하지 않는다. 요청한 원본 재현·동일 인물·승인 지도 양식은 스킬이 허용하는 범위에서 쓴다. 생성 도구가 없는 환경에서 코드 얼굴이나 임시 그림을 완성 원화로 대체하지 않는다.
- 문자·말풍선·표·차트·범례·도형은 편집 가능하게, 원화·사진은 이동/비례 크기/교체 가능한 포함 이미지로 둔다. 그림 전체를 한 래스터로 만든 것을 편집 가능한 원본으로 납품하지 않는다. 원화까지 순수 벡터여야 하는 경우 별도 조건을 준다.
- 기본 납품은 같은 이름의 `.vectora`와 `.jpeg` 한 쌍이다. 지정 이름·폴더·형식이 우선한다. 미지정은 현재 작업 공간, JPEG 4배·회색조·불투명 배경이다. 실제 내용 외곽에 대지를 맞추며 의도된 본문 빈칸/장면 안 공간은 보존한다. 무관한 파일을 덮어쓰거나 지우지 않는다.
- 저장·재열기와 최종 문서에서 내보낸 **실제 JPEG 직접 열람**이 필요하다. 자동 audit/기술 성공과 시각 합격은 별개다. 첫 결과의 명백한 결함은 수정하되 최대 3회 후 정체·도구 한계는 남은 문제로 밝힌다.

## 결과 회수와 내용 수정

응답 본문에서 상태, 실제 원본/JPEG 경로, 실측 외곽 크기, 원문·자료·관계 보존, 저장·재열기·시각 검수 결과, 포함 원화 여부, 해당하는 출처/변환과 남은 문제를 받는다. 의뢰 ID가 있으면 함께 반환한다. 별도 검수/응답 파일은 기본 납품에 추가하지 않는다. 미실행·실패를 통과로 보고하지 않는다.

출제자는 JPEG를 문항에 넣기 전에 기호 대응·빈칸·자료 해석·정답 유일성을 확인한다. 그림이 답이나 개념명을 불필요하게 드러내거나 자료 의미를 바꾸면 수정 의뢰한다. `.vectora`는 편집 원본으로 연결하고 두 파일이 같은 상태인지 확인한다.

주된 후속 수정은 **표/그래프의 값 교체, 본문 일부 추가·삭제**다. 기존 파일과 변경/유지 항목을 보내면 제작자가 자료 연동·재조판까지 처리한다. 예: “B의 2025년 값을 45로 바꾸고 본문 뒤에 ‘단, 조사 대상은 성인이다.’를 추가해줘. 다른 자료와 전체 폭은 유지해줘.” 인간이 여러 폭·좌표를 손으로 조절해야 완성되는 파일을 목표로 하지 않는다.

연결 중단·응답 유실은 실제 저장 상태를 확인한 뒤 재개한다. 편집을 무작정 다시 보내거나 체크포인트/진단 미리보기를 완성본으로 보고하지 않는다. 누락 자료·미지원 기능 때문에 완성이 안 되면 필요한 입력과 가능한 범위를 구별해 반환한다. 앱 자체 수정은 별도로 승인된 개발 작업이며 일반 제작자가 임의로 수행하지 않는다.
