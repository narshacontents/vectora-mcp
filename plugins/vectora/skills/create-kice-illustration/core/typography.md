# 편집 가능한 문자와 정확한 입력


## 미지정 시 서체·조판 기본값

- **새 제작 프리셋은 바탕 11.5pt·바탕 10.5pt·돋움 10pt·돋움 8pt 네 가지다.** 연결 앱의 `vectora://capabilities`에 있는 `textProfiles.catalog`에서 영역의 역할에 맞는 등록 스타일(기본 프리셋)을 고른다. 돋움 7pt·9pt·9.5pt·11.5pt 등이 필요하면 돋움 기본 프리셋의 글자 크기를 변형하며 별도 프리셋을 만들지 않는다. 기존 추가 스타일 ID는 문서 호환용이며 새 제작에서 선택하지 않는다. 한 그림 안에서도 본문·제목·표 셀·도해 라벨에 서로 다른 스타일을 쓸 수 있다. 바탕은 실제 **UND v3.1 Batang(UND 3.1 바탕)** 계열을 선택하며, 영문만 별도 Body로 바꾸지 않는다. **UND v3.0 Body는 새 제작에서 사용하지 않는다.**

| 역할 | 선택 기준 |
|---|---|
| 일러스트 라벨·이름·축·범례 | 도해용 스타일을 출발점으로 삼고 원본의 주석·제목 크기 차이를 구별한다. |
| 상자·말풍선·카드의 줄글 | 돋움 기본 프리셋에서 역할에 맞는 크기를 지정한다. 외피가 같아도 본문 크기는 같다고 가정하지 않는다. |
| 바탕 본문·진술 | 바탕 11.5pt 기본 프리셋. |
| 표의 머리글·내용·수치 | 셀 역할별로 선택한다. 돋움 머리글과 바탕 내용의 혼용을 보존한다. |
| 자료 제목·비정보성 장식 | 해당 역할의 검증된 스타일 또는 명시 부분 서식. 본문에 크기를 강제하지 않는다. |

- 외피가 웹페이지·칠판·말풍선이라는 이유만으로 그 안의 모든 문자를 같은 크기로 만들지 않는다. 독립적으로 읽는 줄글 영역과 도해의 짧은 라벨을 구분한다. `prose` 지침을 읽었다는 사실만으로 서체·크기를 자동 변경하지 말고 실제 자료 역할을 먼저 정한다. 원본 또는 의뢰가 지정한 혼용·굵기·부분 크기를 유지한다.
- 표 스타일은 실제 행·열로 자료를 비교하는 셀에 적용한다. 산문 테두리를 네이티브 1셀 표로 구현했더라도 그 안의 글은 본문 역할이다. 구현 도구의 `kind`만 보고 본문을 표용 크기로 바꾸지 않는다.
- **행간은 비율로 저장한다. 새 글상자와 돋움·바탕 10.5pt 프리셋은 130%, 바탕 11.5pt 프리셋은 150%**다. 프리셋을 선택하면 그 프리셋에 저장된 비율을 적용하고, 글자 크기만 변형하면 현재 비율을 유지한다. 비율은 실제 기준선 간격이며, 130%인 돋움 9pt는 11.7pt다. 사용자가 지정한 비율이나 기존 문서의 명시 서식을 보존하며, 원본별 고정 pt 행간을 새 제작 기본으로 복사하지 않는다.
- 장평·자간은 선택한 앱 프리셋을 측정과 생성에 동일하게 적용한다. **글꼴 모양과 역할별 선택은 2028 예시문항을 우선하고, 여기에 없는 유형만 과거 기출을 보완 근거로 쓴다.** 행간에는 위 사용자 지정 비율을 우선한다. 문항 폭 약108mm를 기준으로 실제 크기를 판단하며, 예전 8pt 정규화 결과를 근거로 삼지 않는다. PDF 직접 추출값과 이미지에서 추정한 값은 구분한다. 제작값은 10pt·10.5pt·11.5pt처럼 쓰기 편하게 정리하고, 장평·자간·행간도 불필요하게 세분화하지 않는다. 소수점 둘째 자리까지 맞추거나 작은 측정 차이마다 새 스타일을 만들 필요는 없다. 반올림한 결과를 실제 인쇄 크기로 대조하며, 줄별 양끝 조판 값과 글꼴 모양 차이를 기본 자간·크기로 오인하지 않는다.
- 앱 catalog가 스타일 ID와 수치의 기준이다. 스킬에 수치 목록을 복제하거나 ID 이름으로 실제 크기를 추론하지 않는다. 적절한 등록 스타일이 없으면 근거 있는 명시 서식을 전달하며, 없는 ID를 만들어 호출하지 않는다. 반복되는 실제 역할 차이가 확인된 경우에만 새 기본 스타일을 제안한다.
- Regular·Bold·Italic·BoldItalic은 실제 설치된 면을 확인해 선택한다. UND v3.1 Main은 SDIJ 돋움, UND v3.1 Batang은 SDIJ 바탕 기반이며 두 서체의 4개 면씩 총 8개를 별도 글꼴 폴더에서 설치한다. `(가)`~`(하)` 전용 표시는 두 v3.1 서체에 통합되어 새 설치에 v3.0 보조 글꼴이 필요하지 않다. 글꼴이 누락되면 해당 폴더를 직접 설치한 뒤 앱을 다시 연다. 원본 SDIJ로 문단 전체를 조용히 대체하거나 합성 굵게/기울임으로 실제 면을 흉내 내지 않는다.
- 측정과 생성에 **선택한 문자 역할의 같은 장평**을 적용한다. 글자 속성을 사용하며 그룹의 가로 Scale로 대신하지 않는다. 설치 앱이 아직 새 면·장평을 지원하지 않으면 차이를 밝히고 구형 결과를 새 폰트 검증으로 보고하지 않는다. 기존 문서의 명시적 서식은 요청 없이 소급 변경하지 않는다.

## 필수 보존과 조건부 조판

- 동그라미·세모·네모·별을 포함한 문장부호·기호는 현재 UND 면을 기본으로 한다. **2028 예시문항과 같은 글자 크기로 겹쳐 비교해 모양 차이가 확인된 문자**는 사용자가 제공한 글꼴 중 일치하는 글리프만 선택 대치할 수 있다. 다른 종류의 문자 코드로 바꾸거나 본문 한글까지 일괄 교체하지 않는다. 대치 근거·범위·실제 면을 기록하고 측정·화면·내보내기·재열기에서 일치하는지 확인한다. 과거 바탕체 기호 합성 규칙을 검증 없이 되살리지 않는다.
- **UND v3.1 Main Regular**의 자료 제목 꺾쇠 `< >`, 수식 등호 `=`, 범위 물결 `~`는 지원 앱에서 검증된 **평가원 기호** 서식을 해당 문자에 선택한다. 저장 원문은 ASCII 그대로 두고 표시 글리프만 바꾼다. 사용자 명시 모양과 URL·코드는 우선 보존한다. 바탕·Bold·Italic이나 숫자·영문에 이 서식을 확대 적용하지 않으며, 표의 숫자·ABC를 본문 숫자 모양과 같게 만들려고 일괄 대치하지 않는다.
- 바탕 본문의 작은 목록 원 `￮`는 **U+FFEE 그대로** 입력한다. 앱이 이 문자만 동일 굵기·기울기의 UND v3.1 돋움 글리프로 표시하며, 바탕 문단의 서체·기준선·줄간격은 유지한다. `○`·`∘`로 문자 코드를 바꾸거나 기호를 별도 글상자로 분리하지 않는다. 구형 앱에서 이 표시 경로가 지원되지 않으면 차이를 기록한다.

- 선택한 스타일의 실제 pt를 유지한다. 사용자 명시 서식, 원본 재현에서 확인한 부분 서식, 선택 지침에서 허용한 **비정보성 장식 문자**의 크기 예외는 해당 범위에만 적용한다. 본문·제목·수치를 공간에 맞추려고 축소하지 않는다. 예외 역할과 실제 크기를 기록해 폭 변경·재열기 후에도 보존한다.

- 요청된 전체·부분 굵은 글씨는 native 문자 서식과 선택한 UND 계열의 실제 Bold/BoldItalic 면으로 유지하고, 자동 Regular 기본값으로 덮어쓰지 않는다. 저장된 style provenance가 `explicit`인지 확인하고 결과의 실제 face를 검수한다. KICE audit의 자동 결과와 명시 서식은 별도로 대조한다.

- 폰트 바이너리는 그림·스킬에 임베드하지 않는다. 검증된 전용 글리프 변환 외에는 폰트·면을 조용히 대체하지 않는다. 기존 문서의 서체·자간은 요청 없이 바꾸지 않는다.

- 기존 0→⓪ 입력 변환은 유지하며, ⓪를 포함한 실제 출력 문자의 지원 여부를 현재 설치 면에서 확인한다. 예전 폰트의 누락 목록을 새 폰트의 지원 여부로 단정하지 않는다.

- **한 텍스트 덩어리는 반드시 하나의 편집 가능한 글상자**로 만든다. 발언·본문·셀·라벨의 자동 줄바꿈/명시 개행과 글꼴·강조·밑줄 범위 서식을 그 안에 유지한다. 줄별 글상자나 이를 묶은 그룹으로 대체하지 않는다. 제목/본문·서로 다른 발언/셀 등 독립된 내용만 나눈다.

- 제공된 전체 본문은 생략하지 않는다. 전사한 시각적 행 끝은 엔터로 고정하지 말고 지정 폭에서 자연 줄바꿈한다. 실제 문단·목록·명시 개행은 보존한다. 어절 중간 분리나 짧은 끝줄을 자동으로 오류 판정하지 말고 아래 줄별 실측 조판 규칙으로 해결한다.

**줄별 실측·자간 조판:** 새 조판 또는 조판 수정에서는 한 텍스트 프레임 안의 각 실제 렌더링 줄을 지정 폭, 실제 글꼴·범위 서식, 선택한 문자 프로필의 실제 pt·장평·자간에서 측정한다. 어절 경계가 어색하거나 끝 음절이 홀로 남으면 앞선 줄들의 자간을 서로 다르게 소폭 압축·확장해 자연스러운 어절 경계를 찾을 수 있다. 다만 ‘보자.’처럼 짧더라도 완결된 마지막 어절은 허용하며, 그것만 짧다는 이유로 앞선 줄의 자간을 조정하지 않는다. 한 프레임 안에서 줄마다 자간이 달라도 되며, 자간을 고정된 일률 값으로 강제하지 않는다. 마지막 줄 자체를 채우도록 벌리지 않고, 실제 짧은 문단과 자연스러운 끝줄의 오른쪽 여백은 보존한다. 폭이나 본문이 바뀌면 다시 측정·조판되는 편집 가능한 경로를 사용한다.

이 조정은 별도 글상자, 강제 엔터, 가짜 공백, 글자 크기 축소, 말풍선 폭 축소로 대신하지 않는다. 숫자 범위와 native `inlinebox`는 분리 불가 단위로 유지하고, 원문·반칸(`U+2002`)·밑줄 범위·문자별 스타일 및 원래 인덱스를 보존한다. 정상적인 자간 조정으로도 긴 비분리 단어가 들어가지 않으면 과도한 자간이나 글자 겹침으로 강제하지 말고 안전한 기존 줄바꿈 처리를 유지한다.

원문은 내용·의미·문단을 보존한다. 다만 기존 세 조판 규칙(원문자 뒤 밑줄, 표시용 콜론, 문장 속 박스 뒤)에 필요한 공백은 입력 원문의 일반 공백과 달라도 적용하고, 최종 문자열에 맞춰 서식 범위를 다시 계산한다. 사용자가 문자 코드 또는 원문 공백을 그대로 보존하라고 명시한 경우와 URL·코드는 예외로 두며, 전역 Unicode 정규화는 하지 않는다.

**원문자 뒤 밑줄 앞은 Vectora Alt+Space 반칸** `U+2002` 한 개로 `㉠ 본문`처럼 저장한다. MCP도 같은 실제 문자를 넣는다. 앱이 일반 공백 폭의 절반으로 고정하고 양쪽 자간을 배제하므로 폰트 em 폭으로 추정하거나 일반/전각/중복 공백·별도 글상자로 대체하지 않는다. 원문자와 반칸은 밑줄 범위에서 제외한다. 삽입 뒤 실제 문자열로 textRange/underlines 위치를 다시 계산하고 재조판·재열기에서 공백과 범위를 확인한다.

**표시용 콜론 `:`은 모두 앞에 Alt+Space 반칸 `U+2002`, 뒤에 일반 한 칸 `U+0020`을 하나씩 둔다:** `주제 : 비교 우위`. 라벨·본문·수치 표기 모두 적용하고 기존 주변 공백은 중복시키지 않는다. URL·코드의 구문 구분자는 바꾸지 않는다. 측정·밑줄·문단 박스 삽입 전에 확정하고 실제 문자열 기준으로 서식 범위를 계산한다.

자료 식별 (가)~(하)는 그대로 입력·저장하고 앱의 자동 전용 글리프 표시를 유지한다. 이 명시된 자동 표시 경로는 임의 글꼴 대체 금지의 예외이며, 제작자가 느낌표·골뱅이·샵·달러·PUA로 원문을 치환하지 않는다. 누락 글리프는 실제 지원과 렌더러 표시 경로를 확인하고, 위의 검증된 글리프 대치 원칙을 적용한다. 여전히 미지원이면 원문 코드를 보존한 채 차이를 기록하고, 사용자 요청 없는 유사 문자 치환으로 숨기지 않는다. 원문이 요구하는 괄호를 폰트로 표시할 수 없는 경우에는 괄호만 벡터 선으로 두고 안 문자는 편집 가능하게 유지한다.

괄호는 저장할 **문자 코드부터** 확인한다. 일반 입력·이미지 전사의 보통 괄호는 ASCII `() [] {} <>`를 쓰며, 모양만 보고 `（ ）〔 〕〈 〉` 같은 전각/CJK 괄호로 바꾸지 않는다. 명시된 원문 코드와 책명/인용의 `「」『』`는 보존한다. 틈이 이상하면 문자 코드·숨은 공백·서체/범위와 글리프 자체의 폭·좌우 여백을 구분해 확인하고 같은 조건의 일반 입력과 비교한다. 전체 Unicode 정규화·공백 삭제·문장 분리·문단 전체 자간 축소로 숨기지 않는다.
