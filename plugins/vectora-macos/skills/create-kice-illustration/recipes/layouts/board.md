### 학습 화면·게시판

학습 화면·슬라이드·칠판·게시판을 제작한다. 보드·핀·받침·조작부는 매체에 필요한 요소만 선택한다. 교사와 말풍선은 같은 단위로 구성하며 실제 구성요소 조건에 맞는 지침을 task instructions에 포함한다.

**칠판을 요청하면 흰 내용 면을 감싸는 두꺼운 회색 테두리는 필수**다. 가는 검정 선 하나의 단순 상자를 칠판으로 대신하지 않는다. 회색 프레임 띠는 최종 크기에서 약0.8–1.5mm를 출발값으로 두고, 검정 윤곽과 얇은 하단 받침으로 판의 구조를 읽게 한다. 프레임 두께는 선 획을 무작정 굵게 하는 것이 아니라 내용 면 밖의 회색 구조 폭이다. 본문 공간을 먼저 확보하고 받침이나 모서리에 여유가 있으면 분필·지우개를 작게 추가할 수 있다. 소품 때문에 판 높이를 늘리거나 글을 밀지 않으며, 필수 장식으로 고정하거나 매번 같은 소품을 복제하지 않는다.

교사·발표자가 있으면 선택된 [발표 배치](presentation.md)와 [발언·인물 대응과 승인 원화](../../components/speech.md)의 동일 조건을 적용한다.

#### 네이티브 칠판

현재 `vectora://production/text/schema`가 `chalkboard`를 지원하면 칠판은 `kind:"text",variant:"chalkboard"`로 만들고 실제 제목과 본문 또는 순서가 있는 text/component/reserve 블록을 소유하게 한다. 표는 component 블록 안에 native spec으로 둔다. 표의 분류가 모호하면 기존 `specRecipes` 정확 경로를 사용하고, 병합 셀이 있는 `table` 매핑은 중첩 표 지침으로 연결한다. 교사가 칠판 옆에 있고 발언이 위에 오는 장면은 공개 스키마가 지원하면 위 칠판을 `dialogue.screenComponent`로 넣고 `presentationOptions.layout:"speech-above-board"`를 사용한다. 본문 변경 때 외피·말풍선·교사가 함께 재배치되게 한다. 고정 y 좌표와 수동 이동을 기본 편집 방식으로 삼지 않는다. 칠판과 발표가 실제 위아래로 분리된 요청만 `composition`의 세로 자식으로 구성한다. 다른 구도에 이를 강제하지 않는다.

제목을 일반 text 블록으로 넣으면 `id:"title"`만으로 제목 정렬이 적용된다고 가정하지 않는다. 별도 요청 없는 자료 제목은 안쪽 자료 영역 가운데에 둔다. 이 생성기의 블록은 `{type:"text",id:"title",text:{text:"제목",textAlign:"center",textProfile:"등록 ID"}}`처럼 **text 안에 서식**을 넣는다. 블록의 별도 `richText`나 text-kind 최상위 `textProfile`은 보내지 않는다. 가리키는 손과 판의 접점은 인물 바깥 사각형이 아니라 실제 손끝으로 재며, 그 관계를 유지하도록 판의 가용 폭과 전체 배치를 먼저 정한다.

연결 앱이 `screenComponent`를 지원하지 않고 일반 `presentationMode:"screen"`이 가는 자료판만 그리면 이를 칠판으로 간주하지 않는다. 네이티브 칠판과 발표를 지원되는 복합 배치로 결합하되 자동 연동 범위와 AI가 다시 조판해야 하는 관계를 구별해 알린다.

자료 제목·기호·사진은 화면의 실제 안쪽 영역에 둔다. 말풍선이 빈 테두리와 겹칠 수 있다는 규칙을 자료 제목의 배경 덮개로 롤·액자 일부를 잘라내도 된다는 뜻으로 적용하지 않는다. 여러 자료가 나란하면 제목 높이까지 먼저 확보하고 본문·그림과 조작부를 분리한다. 너비는 live 측정 slot/plan으로 정하고 자식 너비는 사용자가 고정하지 않았다면 생략하며, 명시한 물리 너비는 그대로 보존한다.

#### 선택 게시판 실행

동등한 가로 카드열이 필요한 경우 라이브 `noticeboard`로 본문부터 제작한다. 미지정 열 수·같은 카드 높이·제목 종이·압정·말림은 생성기 구현 기본값이며 평가원 필수 구도가 아니다. 실제 글의 역할과 수로 열·행을 설계하고, 다른 구도는 native 내용/복합 조판과 필요한 외피만 보충한다. 요청에 없는 빈 카드나 제목 종이를 기본 출력을 채우기 위해 만들지 않는다.

네이티브 경로를 사용할 수 없고 설계가 동등한 가로 카드열에 맞을 때만 스킬 루트의 `node scripts/build_text_frame.mjs --spec <입력.json> --output <배경.svg>` 또는 `buildTextFrame(spec)`을 사용할 수 있다. 이 helper의 `variant:"noticeboard"`는 기본 3열과 고정 압정 부속을 만들므로 그대로 완성 디자인으로 간주하지 않는다. `widthMm` 기본 108/범위 30–108, 필수 `contentHeightMm`은 실제 측정/지정 내용 높이, `paddingMm`은 밖에 더하는 여백이다. 실제 설계에 맞는 `columns`와 필요한 슬롯 높이를 지정하고 남는 부속은 정리한다. 기존 출력은 명시적 `--force`일 때만 교체한다.

반환 `{svg,layout}`의 `layout.slots`는 문서 px 좌표의 chrome/title/content/author 자리다. 실제 높이에 맞는 `textAlign`/`verticalAlign`을 적용하고 빈 `illustrationSlots`는 요청한 초상으로 채운다. 배경 도구는 본문과 줄 수를 측정/작성하지 않으며 미지원 `lineCount`/`contentWidthMm`을 입력하지 않는다. 실제 슬롯 폭과 연속 직사각형 높이를 확인하고 교사·말풍선은 별도 개체로 배치한다. 다른 학습 매체는 위 원리로 직접 구성한다.


가로 3칸 게시판을 요청하면 `columns:3`으로 구성하며 다른 가로 칸 수를 받으면 그 수를 따른다. 세로로 붙인 메모를 카드 수만 보고 가로 열로 바꾸지 않는다. 세로 메모는 지원되는 순서 있는 종이 블록으로 본문·작성자·다음 메모가 함께 재조판되게 구성한다. 카드 제목·본문·하단 작성자/초상을 각각 예약하고, 생성된 빈 초상 슬롯은 실제 요청된 초상만 채운다. 요청한 압정·클립도 첫 완성본에 포함한다. 외피에 속하지 않은 독립 부속은 본문 편집으로 카드가 움직인 뒤 기존 ID를 유지해 같은 모서리로 옮기며, 이를 자동 연동이라고 보고하지 않는다.

메모의 제목·작성자 슬롯은 실제 글높이로 시작한다. 한 줄 표지에 큰 고정 높이를 미리 주거나 압정 공간·안쪽 패딩·제목 슬롯의 빈 부분을 중복해서 쌓지 않는다. 가능한 자동 실측을 먼저 쓰고, 압정 아래 실제 글 획까지의 여백과 제목→본문 간격을 plan과 이미지에서 확인한다. 동등한 메모의 윗선·제목·작성자 정렬은 유지하되 작은 말림·압정 방향·접촉 음영으로 자연스러움을 줄 수 있다. 다양성을 위해 본문을 기울이거나 읽을 순서를 흐트러뜨리지는 않는다. 요청한 답안 빈 영역은 장식용 여백과 구별해 보존한다.

#### 검사

화면과 발언 대응, 꼬리 형상/실제 윤곽 간격, 바깥 이름·높이 기준·하단 정렬을 확인한다. 독립 흉상·발표는 선택된 인물 구성요소의 기본 끝 정렬을, 명시된 공동 장면은 좌석·시점 관계를 확인한다. 각 발언/본문 덩어리가 여러 줄이어도 글상자 하나이고 밑줄은 그 글상자의 서식인지 검사한다. 게시판이면 카드 간격·작성자 대응·예약 공간을 함께 검사한다.

독립 완결 표·차트를 native 내부 컴포넌트 또는 기존 편집 그룹으로 보존한다.

같은 크기의 카드 여러 개를 요구하면 가장 긴 카드의 실제 본문 높이와 공통 패딩으로 크기를 정한다. 한 카드의 글을 늘린 뒤에도 모든 카드의 외곽 높이·머리칸·행 간격을 함께 확인한다. 행 시작점만 맞는 격자 배치를 같은 높이의 자동 연동으로 간주하지 않는다. 지원되는 공유 행 높이 연결을 사용하고, 머리칸과 본문 등 실제 맞춰야 하는 행만 선택한다. 연결본에 공유 높이 기능이 없으면 재측정한 공통 높이를 각 카드의 소유 원본 설정에 반영하며, 개별 도형 이동으로 맞추거나 자동 유지된다고 보고하지 않는다.

같은 크기가 요구되지 않은 자료까지 모두 가장 긴 카드 높이에 묶지 않는다. 내용량 차이가 크면 같은 가로 행끼리 높이를 맞추거나 독립 카드로 구성해 불필요한 빈 면적을 줄인다. 명시된 동일 크기 조건은 보존한다.
