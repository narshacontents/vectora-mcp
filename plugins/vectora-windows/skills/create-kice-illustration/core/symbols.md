# 기호·괄호: 해당 문자가 있을 때

## 기본 계열

돋움 문맥은 UND v3.1, 바탕 문맥은 UND v3.1 Batang의 기호를 사용한다. 돋움 기본·돋움 본문용·바탕의 역할을 유지하고, 낯선 기호도 같은 역할 안의 문장부호·괄호/인용·수학·주석·도형 계열을 따른다. 마침표·쉼표 등을 양쪽 서체에 한 가지 모양으로 통일하지 않는다. 짝/반복 기호의 획·크기·기준선을 함께 본다. 뜻이 다른 물결·동치·범위 표시를 치환하거나 제작 중 폰트를 이식하지 않는다. 차트 표식·패턴·비례 원은 글꼴 기호로 대신하지 않는다.

## 괄호와 자료 식별

- 보통 괄호는 ASCII `() [] {} <>`로 입력한다. 모양만 보고 `（ ）〔 〕〈 〉`로 바꾸지 않으며, 명시된 원문 코드와 책명/인용 `「」『』`는 유지한다.
- 자료 식별 `(가)`~`(하)`는 그대로 저장한다. **Main만 문맥에 따른 전용 고정 글리프 표시**, **Batang은 괄호·한글·괄호 세 문자 표시**다. 이 앱의 변환을 사용하고 제작자가 느낌표·골뱅이·샵·달러·PUA로 치환하지 않는다.
- 제목·자료명의 ASCII `< >`는 해당 괄호 범위에 앱의 **평가원 제목 괄호** 서식(`kice-title-brackets-v1`)을 적용한다. 수학 부등호·URL·코드에는 적용하지 않는다. 돋움·바탕의 실제 굵기/기울임을 유지한다. 실행 범위 계약은 `execution/text-ranges.md`를 읽는다.

## 이상한 틈·누락이 있을 때만 진단

문자 코드 → 숨은 공백 → 서체·범위 서식 → 글리프 자체의 폭·좌우 여백 순으로 같은 조건의 일반 입력과 비교한다. 전역 정규화·공백 삭제·문장 분리·문단 전체 자간 축소로 숨기지 않는다. ⓪는 원문자 상용구 단축키도 가능하나 일반 0을 자동 치환하지 않는다. 실제 설치 면의 지원을 확인하고 옛 누락 목록을 그대로 적용하지 않는다. 미지원은 원문을 보존해 알린다. 요구한 괄호를 실제로 표시할 수 없는 경우에 한해 괄호만 벡터 선으로 보충하고 내부 문자는 편집 가능하게 둔다.
