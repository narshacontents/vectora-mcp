단일 편집 문단을 그림 옆에서 감싸고 그림 아래에서 본문 폭으로 이어 달라는 요청에만 적용한다. 일반 문단·사진 캡션에는 선택하지 않는다. 본문은 하나의 논리적 편집 텍스트 개체로 유지한다.

그림을 기준으로 좁아지는 것은 겹치는 행뿐이다. 첫 문단만 감싸고 다음 문단·각주는 전체 폭을 쓰라는 요청에서는, 이후 블록의 허용 폭도 전체 본문 폭인지 확인한다. 그림의 기준 높이는 지정한 문단 시작이며 제목 행에 임의로 맞추지 않는다. 고정 aside 열의 폭을 모든 문단에 물려주는 방식으로 대신하지 않는다.

글이 그림 아래까지 이어져야 한다고 명시되면 생성 전 조판 계획에서 그림 하단과 회피 여백을 지난 본문 행이 실제로 생기는지도 확인한다. 짧은 문단이 모두 그림 옆에서 끝난다면, 식별 가능한 범위에서 그림 크기를 조절한다. 복귀 행을 만들려고 본문을 덧붙이거나 엔터·과도한 행간으로 길이를 늘리지 않는다. 지정된 크기와 내용으로 불가능하면 그 제약을 남기며, 감싸기 기능을 켰다는 이유만으로 요청을 충족했다고 판정하지 않는다.

웹페이지가 자체 소유한 삽화를 감쌀 때는 라이브 text 계약의 `aside.layout:"wrap"`을 우선한다. 첫 본문을 명시적 id가 있는 text block으로 두고 `aside.anchorBlockId`로 연결하며, `background.asideWidthMm`과 `asideSide`에 그림 영역 폭과 방향을 준다. 앱이 실제 래스터 ID·본문 프레임·아래의 전체 폭 문단을 함께 관리하므로, 이 경우 자식 이동·수동 textFlow 연결을 덧붙이지 않는다. 현재 계약이 첫 문단만 지원하면 이후 문단 시작의 감싸기·여러 장애물 등에 확대 적용하지 않는다. 미지원 배치나 독립 텍스트/이미지에는 아래 일반 textFlow 경로를 쓴다.

`TextFrameSpec.textFlow` 계약은 `bodyFrame: {xMm, yMm, widthMm, heightMm?}`와 `obstacles: [{objectId, side: 'left'|'right', marginMm}]`다. 먼저 현재 연결된 라이브 `vectora_apply` 스키마가 `textFlow`를 지원하는지 확인한다. 지원하면 `{type:'textFlow', id, flow:{bodyFrame, obstacles}}` 또는 `{type:'textFlow', id, obstacles}` 중 하나를 사용한다. 둘을 함께 보내지 않는다. `flow`를 지정할 때 bodyFrame은 실제 문서 텍스트 프레임의 위치·폭과 맞춘다. 필요한 프레임 폭 조정에는 `resizeTextFrame`을 쓰며 글자 크기는 유지된다.

장애물은 라이브 문서의 실제 래스터 자식 `FabricImage` ID, 또는 연결 앱이 지원하는 **유효한 native map 루트 ID**다. 자산 ID·임의 그룹·지도 자식 경로 ID를 대신 넣지 않는다. `vectora_inspect`에서 현재 ID와 지도 binding을 확인하고 `side`는 그림이 놓인 쪽으로 지정한다. `textFlowBounds`를 만들어 보내지 않는다. 런타임이 실제 그림 경계와 지도 clip/자식 표시 범위를 계산한다. 지도 폭·crop·내용이 바뀐 후에도 동일 본문이 재조판되는지 확인하고, 감싸기 때문에 지도를 래스터로 바꾸거나 본문을 옆/아래 두 객체로 나누지 않는다.

이미 연동된 웹페이지/자료 컴포넌트의 전체 너비를 바꿀 때는 해당 컴포넌트의 지원되는 `widthMm` 업데이트를 먼저 사용한다. 앱이 본문 frame·이미지·후속 문단·각주·외피를 재배치하는지 확인한 뒤 미지원 부분만 보충한다. 처음부터 각 자식의 좌표를 모두 다시 쓰거나 네이티브 재배치 후 같은 폭 변경을 한 번 더 적용하지 않는다. 변경 뒤 source 폭과 실제 외곽 폭, 텍스트 흐름의 bodyFrame 및 장애물 ID가 일치하는지도 검사한다.

적용 뒤 같은 텍스트 개체가 유지되는지, 이미지 옆 줄이 겹치거나 잘리지 않는지, 이미지 아래 첫 줄이 전체 본문 폭으로 돌아오는지 확인한다. 짧은 마지막 줄의 오른쪽 빈칸만으로 전체 폭 복귀 실패로 판정하지 말고, 해당 행의 허용 폭과 그 행의 y가 이미지 하단을 지났는지 확인한다. 이미지 이동·크기 변경 뒤에도 다시 확인한다. 텍스트 편집으로 연결된 뒤따르는 블록이나 페이지 프레임이 움직일 수 있으므로 현재 문서에서 실제 linkage와 위치를 확인하고, 오래된 예약 공백이 남았는지도 점검한다. 기대한 재배치가 일어나지 않으면 필요한 위치를 조정하고 관찰한 도구 한계를 보고한다.
