# 외곽 맞춤·저장·재열기·실제 JPEG 납품



- 평가원 그림의 기본 납품은 편집 가능한 .vectora 원본과 4배 .jpeg이며, JPEG/PNG 래스터는 기본 회색조로 내보낸다. 사용자가 컬러를 명시하면 컬러를 우선한다. rasterColorMode는 PNG/JPEG에만 전달하고 SVG/PDF/WebP에는 보내지 않는다(거부됨). 기존 legacy vectora_export_package의 래스터 옵션은 PNG에 적용하며, 지원되는 profile:"kice"에서는 JPEG에 적용한다.

- 색상 변환은 내보내기 단계에서만 한다. 편집 원본의 채움·선·이미지 색상을 바꾸어 회색으로 만들지 않는다. vectora_preview와 SVG/PDF/WebP 미리보기는 원래 색을 유지한다. PDF colorMode RGB/CMYK는 별도 설정이다.

- 호출 전에 라이브 tools/list 스키마를 확인한다. vectora_export 또는 vectora_export_package에 rasterColorMode가 없으면 추측해 보내거나 다른 앱/변환기로 회색조를 흉내 내지 않는다. 해당 기능을 지원하는 앱으로 업데이트하고 MCP를 다시 연결한 뒤 사용한다.

- 완성 그림마다 기본 **같은 본체의 .vectora 한 개 + .jpeg 한 개**, 복합형도 한 쌍. 다른 형식/추가 파일은 명시 요청 때만. SVG/원본 PNG/기록/검수 이미지는 내부 임시 영역, 폰트 파일은 포함하지 않는다. 기존 파일을 두 개로 맞추려고 삭제하지 않는다.

- 이름과 폴더는 각각 사용자 지정 우선(번호·공백·대소문자 유지); 확장자를 분리해 동일 본체, 한쪽만 final/preview 접미사 금지. `.jpg` 명시 시 그 확장자. 미지정 폴더는 **현재 작업 공간 바로 안**(날짜/output 폴더 임의 생성 금지), 상대 경로는 작업 공간 기준. 자동 이름 충돌은 양쪽에 같은 번호; 지정 이름의 불명확한 교체는 확인한다. 무관한 기존 파일은 덮어쓰지 않는다.

1. 제작 중 추가·수정한 표시 문자열은 [생성 전 검사](base.md)와 같은 방법으로 최종 spec에서도 확인한다. 이미 검토한 원문만 반복 검사하지 않고 새 제목·범례·중첩 자료와 서식 범위가 올바른지 확인한다.

2. **요청 폭은 저장 방식과 관계없이 먼저 맞춘다.** 생성 spec의 widthMm과 실제 보이는 내용 외곽 폭을 대조한다. 흰 전체 배경·컴포넌트의 여유 상자 폭만 요청값이라고 해서 내용도 같은 폭인 것은 아니다. 의도된 종이 테두리·내용 예약 칸은 실제 구성에 포함한다. 제목/라벨까지 포함한 실제 외곽을 기준으로 배치·외피·내용 영역을 계산하고, 아래의 보존 계약을 검증해 맞춘다. 작은 픽셀 반올림 차이를 쫓아 반복 확대하지 않는다. KICE 패키지는 현재 외곽에 대지를 맞추는 납품 기능이며 요청한 내용 폭까지 자동으로 보정했다고 가정하지 않는다.

연결 컴포넌트는 해당 생성기의 폭/영역 변경으로 먼저 재조판한다. 이미 실제 폭이 맞으면 다시 확대하지 않고 대지만 맞춘다. 일반 `fitContentWidth`는 라이브 계약이 대상의 연결 관계와 물리 서식을 보존할 때 사용한다. 실제 납품 개체를 선택하고 `values.width`를 `mm-pt`에서는 mm로 지정하며, 성공 응답뿐 아니라 전후의 바인딩·자료 좌표·실측 치수를 확인한다. 연결이 무효화되면 실패로 취급하고 원 상태를 복원한다. `fitSelection`은 내용물 폭을 바꾸지 않고 대지만 보이는 렌더 외곽에 맞춘다. selectAll은 잠금·타 대지 누락/혼입을 확인한다. 과잉 여백·누락은 지원되는 artboard update의 x/y/width/height로 바로잡고 연결 컴포넌트 재조판 후 이미지로 확인한다. KICE 패키지 보고서의 `fit.status`와 실측 치수도 별도로 확인한다.

폭 맞춤 뒤 영역별 선택 프로필·명시 범위의 실제 pt와 장식 문자의 지정 크기·선폭·문단 박스의 지정 mm가 유지되는지 검사한다. 기능이 실패하거나 그룹 배율만 남기면 실패 결과를 그대로 납품하지 말고 외피/내용 배치와 해당 컴포넌트의 폭을 수정해 재조판한다. 원화는 비례를 유지하며, 정량 자료의 좌표 관계를 바꾸어 폭을 맞추지 않는다.

기존 문서의 내용 수정 뒤에도 이 외곽 확인을 다시 한다. 본문/표/외피가 정상적으로 늘어도 기존 대지는 자동 확대되지 않을 수 있다. **첫 이미지 검수 전에도 대지가 실제 내용 전체를 포함하도록 맞춘다.** 원본의 반응형 대지 연결이 재조판을 유발하면 지원되는 출력 준비 복사본에서 외곽을 맞춘다. 초기 대지 때문에 잘린 미리보기를 완성본 검수로 삼지 않으며, 실패 진단용 JPEG에도 전체 상태를 보여준다. 대지 맞춤을 그림의 수동 보정과 혼동해 생략하지 않는다.

3. **지원되는 KICE 최종 출력 프로필을 우선 사용한다.** 현재 capabilities.deliveryProfiles와 도구 스키마에 kice가 있고 사용자가 지정한 파일명·확장자·형식을 정확히 지원하면 `vectora_export_package({profile:"kice",documentId,directory,baseName,artboardId?,rasterScale:4,rasterColorMode:"grayscale",overwrite:false})`로 같은 본체 .vectora와 .jpeg 한 쌍만 저장한다. 사용자 배율/컬러/교체 지시가 우선이다. directory는 접근 가능한 기존 절대 폴더, baseName은 경로 구분자 없는 파일 본체다. includePdf:true는 거부된다. 이 프로필은 원본 작업 문서를 유지하고 별도 준비 복사본에서 responsive fitToArtboard 바인딩을 현재 해결된 폭에 고정한다. 내부 문자·도형·컴포넌트의 편집 구조는 유지한다. 실제 표시 획/alpha 외곽을 측정하여 외곽 맞춤→원본 저장→실제 파일 독립 재열기·비교→같은 재열기 상태 JPEG를 처리하므로 기존 save/open/export를 중복 호출하지 않는다. 그전에 1–2항의 이미지 직접 검수는 필요하다. sourceDocumentId/sourceRevision, preparation.bindingsFrozen/closeStatus와 fit.status·실제 치수를 읽고 unavailable/실외곽 불일치를 성공으로 쓰지 않는다. files의 written/failed/not-run·실제 경로·오류를 확인하며 일부 원본 저장을 두 파일 완성으로 보고하지 않는다. success/technicalChecks는 기술 검사이고 deliveryReady:false와 visualReview.status:"pending"은 직접 이미지 검수 전 상태다. **저장된 실제 JPEG를 직접 열어** 최종 크기/확대에서 원문·값·대응·글/선·원화·외곽·저장본 일치를 검수한 뒤만 완료로 보고한다. 결함 수정은 같은 문서에서 2항을 적용하고 이 프로필을 다시 실행해 두 파일을 같은 최종 상태로 맞춘다. 기본 납품에 추가 파일을 만드는 legacy export_package는 쓰지 않는다.

4. **KICE 프로필이 없거나 사용자 지정 파일명·형식을 정확히 지원하지 않으면 검증된 수동 경로를 쓴다.** profile:kice는 .jpeg를 만들므로 사용자가 .jpg를 명시하면 임의로 바꾸지 않고 아래 save→재열기→JPEG export를 .jpg 경로로 실행한다. 다른 명시 형식도 실제 지원 export 계약으로 실행하며 원본과 출력은 같은 파일 본체를 유지한다. 사용자 지시가 프로필 선호보다 우선이다. 앞의 외곽 폭·대지 맞춤을 적용한 뒤 `vectora_save({documentId,path,format:"vectora"})`→실제 파일 존재 확인→`vectora_open_document` 재열기와 문자·도형·그룹·포함 이미지·치수 보존 검사→최종 외곽 재확인→`vectora_export({documentId,path,format:"jpeg",scale:4,transparent:false,rasterColorMode:"grayscale"})` 순서다. 사용자 배율/컬러/명시 대지 지시가 우선이며 라이브 지원 옵션만 보낸다. 실제 JPEG 직접 열람으로 1–2항을 재검수하고 수정 시 저장·재열기·JPEG를 반복한다. 파일 작성·확장자 변경·별도 PNG 변환을 Vectora 저장/내보내기로 주장하지 않는다.

`AUDIT_BLOCKED` 등 원칙 위반 진단은 수동 저장 경로로 우회해 합격시키지 않는다. 사용자 지정 예외인지, 잘못 적용한 서식/구조인지 확인해 원인을 고친다. 검수용 실패본 보존은 가능하지만 정상 납품과 구별한다.

5. 그 JPEG 자체를 `![그림 설명](<절대 JPEG 경로>)`로 표시하고 `.vectora` 파일 링크 제공. 경로·저장/재열기/내보내기 상태·혼합 원화 여부를 사실대로 보고한다. 기능 실패는 미완료를 밝히며 두 파일 완성으로 주장하지 않는다.
