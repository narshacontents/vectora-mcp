# 출제 에이전트의 일러스트 의뢰

출제자는 문항의 평가 요소·정답·자료 타당성을 결정하고, `create-kice-illustration`을 실행하는 제작자는 구도·조판·원화·편집 가능한 Vectora 문서와 JPEG를 만든다. 스킬 이름은 MCP 함수명이 아니다. 실행 환경의 스킬 로딩/위임 기능으로 호출하고, 실제 Vectora 도구와 필요한 파일에 접근 가능한 에이전트에게 맡긴다. 다른 머신의 경로만 전달해 파일을 공유했다고 간주하지 않는다.

## 바로 전달할 의뢰 형식

아래 항목 중 해당하는 것만 채워 제작 에이전트에게 전달한다. JSON이나 내부 도구 명령으로 바꿀 필요는 없다. 제작자는 작업별 지침을 준비할 때 `caller:"exam-agent"`를 지정한다.

```text
create-kice-illustration 스킬로 제작해줘.
그림: [보일 구성과 서로의 관계]. 최종 외곽 폭 [필요하면 mm].
표시할 원문: [실제 문단·화자별 발언·제목·라벨].
자료: [실제/가상/정성 구분, 항목·시점·값·단위·분모].
서식 의미: [밑줄 대상, 문단 속 박스, 빈칸, 화살표 방향 등].
유지/금지: [평가에 필요한 조건, 표시하지 않을 정답·해설].
납품: [필요하면 폴더와 파일명]. 배치와 조판은 맡길게.
```

단순한 경우에는 “A·B 지역의 인구 변화를 선그래프로 그려줘. 연도는 …, 값은 …, 단위는 만 명, 폭85mm. 제목은 넣지 마.” 정도면 충분하다. 외곽 폭만 지정하고 본문·자료 영역의 개별 좌표나 줄별 폭은 제작자가 계산하게 한다. 선 굵기를 일일이 지정할 필요도 없으며, 특별한 강조가 필요할 때만 ‘기간 화살표가 주자료로 읽히게’처럼 역할을 말해준다. 제작자가 자료선·축·보조선의 위계와 범례 대응을 함께 정한다.

## 간단한 그림과 복합 자료

간단한 그림은 자연어 한두 문장과 표시할 내용이면 충분하다. 복합형은 자세한 설명, 표/JSON 원자료, 첨부 파일을 함께 준다. **프롬프트를 억지로 짧게 줄이지 않는다.** 필요한 관계는 자연어로 구체적으로 지정할 수 있다(예: 곡선·절편·점과 투영선의 대응, 흐름의 출발지→도착지·단위·등급, 학습지 제목·안내·표 블록의 순서와 빈칸·점수 행의 대응). 이를 위해 내부 recipe·분류 코드·MCP 인자·개체 좌표나 의미와 무관한 세부 스타일을 설계할 필요는 없다.

최소한 다음을 알 수 있어야 한다.

- **보여 줄 내용과 관계**: 원문·값·기호·화자·방향·포함 관계·빈칸·강조, 또는 이것들을 얻을 조사 지시.
- **자료의 성격과 바꾸면 안 되는 조건**: 실제 제공/실제 조사/가상/정성 자료인지, 무엇을 비교·읽게 할 것인지. 제작 의도·정답·해설은 표시할 문구와 분리한다.
- **작업 범위**: 새 그림인지 기존 파일의 수정인지. 수정이면 실제 원본과 변경/유지 항목을 준다.

병합표는 상위 머리글이 묶는 하위 열/행과 각 셀의 항목을 알려준다. 문장형 셀의 줄바꿈 위치나 줄 수는 지정하지 않아도 된다. 목록형 계획서에서는 항목 위계와 빈칸이 들어갈 문장의 위치·표시 기호만 구별하면 제작자가 들여쓰기와 글 속 박스를 배치한다. “두 번째 모둠 설명 자리를 긴 (가) 박스로 비워줘”처럼 전달하고 박스 좌표나 부분 서식 인덱스는 계산하지 않는다.

문항/그림/의뢰 버전, 외곽 폭, 높이 제한, 저장 폴더·파일명은 필요한 경우만 덧붙인다. 본문에 없는 정답·제목·이름·기관·연도를 제작자가 채우게 하지 않는다. 모순이나 의미를 바꾸는 누락만 확인하고, 평가 의미에 영향 없는 배치·여백·장식은 제작자가 선택한다.

## 자료별로 빠뜨리면 안 되는 정보

| 자료 | 의미상 필요한 입력 |
|---|---|
| 수치 표·차트 | 범주·계열·시점·값, 단위·분모·소수 자릿수·결측. 표의 방향이 중요하면 “A·B는 가로 두 열, 답변·점수는 세로 두 행”처럼 행과 열의 대응도 알려준다. 항목 이름만 나열하면 전치된 표도 성립할 수 있다. 축 범위/생략/범례는 특별히 유지할 조건만 지정한다. 매월 눈금을 모두 읽어야 한다면 “1–12월 전부 표시”처럼 필수 표시를 밝히고, 그렇지 않으면 대표 눈금의 간격은 제작자가 고른다. 결측을 0으로 쓰지 않는다. |
| 질문·응답표 | 질문별 원문과 각 응답 열의 ○·×·체크·빈칸을 짝지어 준다. 빈칸이 미확인인지 직접 답할 공간인지 구별하고 기호 설명도 제공한다. 수정 대상을 찾기 위한 행 번호와 실제로 인쇄할 번호를 구분한다. 질문·응답 열의 폭과 긴 질문의 행 높이는 제작자에게 맡긴다. |
| 구성비·누적 비교 | 원자료가 인원/금액인지 이미 계산한 비율인지, 각 막대의 전체 분모, 구간 순서와 공통 범례를 알려준다. 전체 길이로 총량을 비교할지, 모두 같은 길이의 100%로 비교할지도 구별한다. 비율의 반올림 합계가100과 달라도 제작자가 몰래 재분배하지 않게 원자료·표시값을 구분한다. |
| 실자료 조사 | 지표 정의·지역·기간/기준 시점·단위·선호 생산 기관 또는 원표/직접 URL. 확인되지 않은 값을 만들지 않는다. 반올림·단위 환산이 허용되는지 밝힌다. |
| 이론 그래프 | 축의 뜻, 곡선·경계·영역·교점·이동의 관계, 꼭 표시할 점·구간, 수치 눈금이 필요한지. 절편으로 정한 경계와 별도 소비점·관측점을 구별하고 제공 좌표를 준다. 두 곡선 사이 면적을 칠한다면 어느 두 계열 사이인지 구별한다. 정성 개형에 임의 숫자를 붙이지 않는다. |
| 산점·버블 | 이름별 x·y 값과 각 축의 지표·단위, 크기가 별도 수량을 나타내면 그 값도 준다. 관측점을 잇는 선이 필요한 경우에만 그 관계를 명시한다. 수정할 점의 이름과 새 값을 전달하면 되며, 가까워진 점의 좌표를 벌리지 않고 이름 위치를 조정하는 일은 제작자가 맡는다. |
| 기간 비교 | 공통 시점/기간 경계, 기간 길이, 행별 주체, 각 구간의 시작·끝과 이름을 준다. 경계 시점에 붙는 사건명과 두 경계 사이에 붙는 구간명을 구별한다. |
| 분기도·논증도 | 시작·판단·결과의 본문, 인쇄할 단계 제목과 빈칸 표기, 각 연결의 출발→도착·방향·응답 라벨, 공통 분기·합류 및 파선의 뜻. 여러 질문이 같은 결과들을 판정하면 질문마다 어느 결과가 예/아니요인지 따로 적는다. 공통 범례 사용 여부는 지정할 수 있지만, 질문 폭·연결선 길이·결과 간격은 제작자에게 맡긴다. 전제에서 결론이 나오는 관계와 시간 순서의 절차를 구별한다. 반대 방향마다 기호가 다르면 “갑→을 A, 을→갑 B”처럼 두 관계를 따로 준다. |
| 조직·분류 위계 | 각 상위 항목과 그에 속한 하위 항목을 묶어 준다. 같은 단계의 형제 관계와 순서가 의미 있는 경우를 밝히고, 겸임·교차 소속은 별도로 알려준다. 소속을 잇는 선과 진행 방향 화살표를 구별한다. 긴 항목명의 줄바꿈·상자 높이·공통 분기선은 제작자가 함께 맞춘다. |
| 벤 다이어그램·합계 | 집합별 전체 인원인지 해당 집합에만 속하는 인원인지 구별한다. 교집합·어느 집합에도 속하지 않는 영역·전체 수를 주고, 함께 표시할 합계의 뜻을 명시한다. |
| 방사형 비교 | 각 축의 순서·척도·상한과 계열별 값을 준다. 순위를 적는 동일 크기 도형과 반경이 실제 점수인 그래프를 구별한다. 특별히 요구하지 않은 눈금 개수·패널 폭 배분은 제작자에게 맡긴다. |
| 지도 | 지리 범위, 위치·영역·이동, 지명 표시 여부, 행정 경계 기준 시점, 통계 공간 단위. 실제/가상을 구별한다. |
| 지도 위 수량·방향 | 점 하나의 수량과 지역별 총량, 비례 기호의 값·단위, 또는 풍향별 순서·빈도와 지점/시점을 준다. 풍향 값을 이은 다각형과 방향별 부채꼴처럼 형태가 중요하면 그 차이도 자연어로 지정한다. 합성 분포인지 실제 위치인지 구별하고, 바다에도 값이 있는지와 지도에 표시할 범위를 밝힌다. |
| 구성비 좌표·면적 | 삼각 그래프는 성분 이름과 합이 같은 세 값, 면적 비례 도표는 범주별 값과 전체 분모를 준다. 계산 원자료와 그림에 실제 인쇄할 숫자·이름을 구별한다. |
| 대화 | 화자별 이름과 발언 원문·순서·강조·빈칸. 반복 화자를 구별한다. 화자 수와 발언 수는 다를 수 있다. 인물 없는 대본·해설에서도 역할명을 인쇄하려면 `교사: …`처럼 표시할 원문에 포함한다. |
| 공동 수업·토론 장면 | 참석자 수·역할, 화면·교사·학생의 공간 관계, 이름과 발언의 대응, 화면 안의 원문·표·그래프 자료. 인물은 한 장면이어도 읽을 글과 자료는 편집 가능하게 제작한다. |
| 새 인물·장면·사물 | 식별 대상, 읽혀야 할 행동·관계·필수 소품. 특정 시점·신체 범위가 필요하면 지정한다. 실제 인물/유물의 정확한 이름이 있으면 제작자가 참조 이미지를 조사한다. |
| 사진·기존 원화 | 실제 파일/URL 또는 검색할 대상의 정확한 이름·시대와 보존 범위. 원본 사용과 선화 재작화를 구별한다. 검색용 인물명과 그림에 인쇄할 `(가)`·`(나)` 등의 표시는 따로 적고, 원형 자르기처럼 필요한 외곽 형태만 지정한다. 같은 인물을 유지하는 수정이면 원화와 대상 대응을 전달한다. |
| 산출식·분수 | 좌변, 분자·분모, 식 바깥 배수를 구별하고 표 셀/본문 중 들어갈 위치를 준다. 한 줄의 `/` 표기와 가로 분수선이 중요한 차이라면 이를 명시한다. |
| 본문과 내부 자료 | 전체 본문·실제 문단, 밑줄/박스의 대상 문자열, 삽입될 표·그래프·사진과 위치 관계. 반복 메모·카드는 항목별 본문과 인쇄할 작성자 문구를 짝지어 주고, 가로 나열인지 세로 나열인지 밝힌다. 시각적 행 끝은 강제 개행 조건이 아니다. |
| 계층·병합이 있는 표 | 상위 제목이 묶는 하위 열/행, 합쳐 쓸 설명·답안 칸의 범위, 표시할 값이나 자리표시자를 준다. ‘위는 A/B 두 열, 아래 공통 특징은 두 열을 합침’처럼 자연어로 설명하면 되며 셀 좌표나 병합 API는 필요 없다. 빈칸에 기호만 둘지 직접 쓸 공간을 남길지도 구별한다. |

원자료는 **그림에 인쇄할 항목과 별개로** 충분히 전달한다. 표시하지 않는 값도 도형의 크기·위치·개수 계산에 필요할 수 있다. 실제 주소가 없는 합성 분포는 그 사실을 명시하고, 제작자가 좌표·개수를 추정해 자료 누락을 메우게 하지 않는다. 예: “국가별 값은 회색 등급을 계산하는 데만 쓰고 지도에는 A·B·C만 표시해줘.” 출제 맥락이나 정답 판단 근거는 표시할 원문과 분리한다.

책·접힌 안내장처럼 내용 길이에 따라 외곽도 바뀌는 자료는 바꿀 문장·셀과 유지할 면의 역할을 알려 준다. 제작자가 지원되는 경로 연동을 설정하고 글의 짧은 추가·삭제를 확인한다. 호출자가 접힘선 좌표나 바뀐 높이를 계산할 필요는 없으며, 내용이 크게 바뀌면 옆 자료와 표지의 시각적 균형도 제작자에게 재검수하도록 요청한다.

최종 그림 폭과 내부 텍스트 상자의 치수는 별개다. N줄 예약이면 적용 너비와 줄 수를 전달한다. 독립 자료 여러 개를 한 그림에 넣을 때 공통 시점·값·기호의 대응을 적고, 바뀔 때 함께 갱신되어야 할 원자료를 구별한다. 예를 들어 “이 인원 자료를 표와 막대그래프로 함께 보여주고, B 지역의 값을 바꾸면 둘 다 바뀌게 해줘”라면 원자료는 한 번만 전달해도 된다. 단순히 값이 같다는 이유로 별개 자료를 자동 연동시키지 않도록 관계를 밝혀 준다. 외피·장식 하나마다 별도 자료로 나누지 않는다.

## 첫 결과를 안정적으로 만드는 전달 요령

- 복잡한 텍스트일러는 **공유 배경의 종류, 읽을 블록의 수·역할·관계**를 말해 준다. 예: “신문 한 장에 주기사와 짧은 보조기사”, “선택 탭의 자료 아래 별도 해설”, “칠판 위 두 자료와 아래 공통 답안 공간”. 블록별 원문을 짝지어 주고, 꼭 필요한 외형만 지정한다. “배경 세부 디자인은 평가원 계열에서 자연스럽게 선택해줘”라고 맡길 수 있으며, 클립 좌표나 모든 장식 모양을 정할 필요는 없다. 여러 대안을 원하면 동일한 내용·폭을 유지한 배경 대안이라고 명시한다. 새 디자인을 원한다는 것과 기존 문서 편집 때 디자인을 유지한다는 것을 구별한다.
- 별도 외형 지시가 없는 신규 의뢰도 제작자가 배경을 설계한다. 기출 번호·이전 완성 그림·고정 템플릿을 넘겨야 하는 것은 아니다. “이 내용과 폭을 유지해 서로 다른 신문 5개”처럼 요청하면 본문을 가려도 외피 구조가 구별되는 대안을 만들며, 본문 단 나누기만 바꾸거나 작은 아이콘만 이동한 복제본은 대안으로 세지 않는다. 여러 문항에서 같은 서식을 써야 하는 경우에만 유지할 서식을 명시한다.

- 신문·웹페이지 안에 표나 그래프가 있으면 **외피, 본문, 내부 자료를 한 의뢰에** 넣는다. 본문에는 문장, 표/그래프에는 행·열/계열별 값을 주고 같은 정보를 이미지로만 전달하지 않는다. 본문을 늘렸을 때 내부 자료와 외피도 함께 재조판할 수 있다.
- **신문 전체인지 기사 일부를 오린 자료인지** 구별한다. “학습지 가운데에 아래 제목·본문의 기사 스크랩을 넣어줘”라면 충분하며, 제호·날짜까지 필요한 신문 전체와 구별해 불필요한 머리글 공간이나 없는 문구가 생기지 않게 한다. 표 사이의 관계 기호나 높이가 다른 자료의 정렬은 제작자가 결정하도록 맡긴다.
- 함께 놓는 자료의 비중이 다르면 어느 쪽이 주자료이고 어느 쪽이 보조자료인지 알려준다. 동등한 비교 자료의 크기 균형·제목 중심·라벨과 범례의 정렬은 제작자가 판단하므로 호출자가 좌표나 간격을 일일이 지정하지 않는다.
- 여러 질문이 같은 결과를 가리키면 각 질문별 **응답→결과**를 따로 적는다. 예를 들어 “위 질문은 예→A·아니요→B, 아래 질문은 반대로”처럼 주면 순차 질문으로 오해하지 않는다. 빈 질문은 그대로 두라고 명시하고, 상자 크기·연결선의 꺾임 좌표와 응답 라벨 간격은 제작자가 결정한다.
- 관계도에 범례·예시를 붙이면 **주관계, 범례가 설명하는 선/기호, 예시에 다시 등장하는 대상**을 구별한다. “A는 갑→을, 예시도 같은 A 관계”처럼 방향과 대응을 주면 충분하다. 노드 지름·연결선 길이·보조 상자 폭은 제작자가 함께 결정한다. 예시에도 같은 이름이 등장한다는 것과 이후 이름 수정이 자동 연동된다는 것은 별개이므로, 동시 변경이 필요하면 그 범위를 밝힌다.
- “공원 면적”처럼 의미가 달라질 수 있는 지표는 **1인당인지 총량인지** 명시한다. 범례의 지표명과 단위, 등급/항목 이름은 구분해 전달한다. 단일 화살표 범례에 같은 문구를 제목과 항목으로 두 번 쓰도록 요구하지 않는다.
- 대화는 화자 목록보다 **발언 순서와 화자 대응**이 중요하다. 네 발언에 두 사람이 등장하면 같은 인물이 반복되게 요청한다. 인물의 상세 좌표·말풍선 크기·꼬리 위치는 제작자에게 맡긴다. 교사가 칠판을 설명하는 장면은 칠판의 제목·본문·표 자료와 교사의 발언을 구별해 준다. 표는 행·열·값으로 전달하고, “왼쪽 칠판의 표를 오른쪽 교사가 가리킨다”처럼 관계를 적으면 된다. 내용의 짧은 추가·삭제 뒤에도 판·인물·발언이 함께 조판되게 하며, 인물의 머리 폭이나 판 높이를 각각 고정할 필요는 없다.
- 공동 장면에서 배치가 중요하면 “자료판은 왼쪽, 교사는 오른쪽에서 설명하고, 아래의 다섯 학생은 자료판을 본다. 교사 발언은 위, 학생 발언은 아래”처럼 상대 위치와 역할을 적는다. 읽을 표·그래프와 인물 중 무엇이 주자료인지도 밝히면 제작자가 자료를 먼저 측정하고 원화·발언 영역을 함께 계획할 수 있다.
- 지도·자료판에 인물이나 말풍선을 겹쳐도 되는 장면은 **풀이에 반드시 보여야 하는 정보**를 알려준다. 예를 들어 “A~E 지점·기호와 60°N 표시는 보여야 한다. 교사는 원형 초상으로 지도 가장자리에 걸쳐도 된다”면 충분하다. 초상의 확대·마스크, 말풍선 공통 열, 비정보 영역의 겹침 위치와 여백은 제작자가 정하며 호출자가 픽셀 좌표나 줄 수를 맞출 필요는 없다.
- 지도는 **국가를 비교하는지, 자연환경/문화권의 분포를 보는지, 연안 경로를 읽는지**를 알려준다. 제작자가 2028 예시문항을 우선으로 국경 표시·바다색·확대용 바탕을 선택하므로 이들을 매번 직접 지정할 필요는 없다. 특정 경계·바다색·도법이 문제 풀이의 조건이면 따로 명시한다. 과거 기출은 예시문항에 없는 조건을 보강하는 자료로만 사용한다.
- “괄호를 박스로”라고만 쓰지 말고 “본문 중 `(가)`를 편집 가능한 문단 박스에 넣어줘”처럼 대상과 역할을 지정한다. 밑줄도 대상 문자열로 지정하고, 여러 번 나오는 문자열은 해당 문장을 함께 준다. 시각적 행 끝의 엔터나 연속 공백은 넣지 않는다.
- 변경 의뢰는 **기존 .vectora + 변경 내용 + 유지 조건**을 준다. 예: “2025년 이용자를1300으로 바꾸고 기사 끝에 이 문장을 추가해줘. 밑줄과 폭108mm는 유지해줘.” 최초 제작 프롬프트만 다시 보내 새로 그리게 하지 않는다. 표의 행을 바꿀 때는 “기존 세 일정은 유지하고 아래 두 일정을 끝에 추가”처럼 추가·삭제·전체 교체와 위치를 구별해 준다. 외피 높이·하단 문구 이동량은 제작자가 내용에 맞춰 처리한다. 제작자가 자료 연동·재조판까지 처리하며, 인간에게 여러 폭·좌표를 손으로 조절하도록 넘기지 않는다.
- 본문을 나중에 고칠 종이·편지에는 “본문을 늘려도 틀과 모서리 장식이 따라오게”처럼 **편집 후 기대 동작**을 적을 수 있다. 문단 박스는 대상 문자열만 지정하면 된다. 제작자는 원문·박스가 유지되는지와 외피·장식이 함께 움직이는지를 따로 확인하며, 단순히 모든 요소를 선택할 수 있다는 이유로 자동 연동을 보장하지 않는다.

이 요령은 다양한 내용의 새 의뢰와 본문·수치 변경 검수에서 사용한 입력 원칙이다. 특정 예시의 배치나 장식을 재사용하라는 지시가 아니며, 한 번의 도구 호출 또는 모든 새 내용의 무결함을 보증하지 않는다.

## 복합형 의뢰 예시

아래 형식은 선택 사항이며 MCP 스키마가 아니다. 필요한 항목만 채운다.

```text
create-kice-illustration 스킬로 아래 자료를 한 그림으로 만들어줘.
[역할] 두 시점의 지역별 이용 인구 차이를 표와 그래프로 비교하게 할 자료.
[표시할 글] 제목 ‘문화 시설 이용’, 본문 ‘다음은 세 지역의 이용 인구이다.’
[자료] 가상 자료, 단위 천 명. 행 A/B/C, 열 2015/2025.
값 A=20/35, B=30/25, C=15/40. 표와 묶은 막대그래프에 같은 값을 사용.
[관계] 위에 본문, 아래에 표와 그래프를 함께. 두 연도의 범례 대응을 유지.
[유지/금지] 값을 임의 환산하지 말고 순위·증가폭·정답 해설은 추가하지 말 것.
[치수/납품] 실제 외곽 폭 102mm. 현재 작업 공간에 12_그림1로 저장.
배치·표와 그래프의 폭 배분·소박한 외피는 제작자가 결정해줘.
```

여러 항목이 있으면 큰 항목과 그 아래 설명·산출식·조건의 관계가 드러나게 원문을 전달한다. 들여쓰기 수치나 공백 개수를 정할 필요는 없으며 제작자가 같은 단계의 시작선을 맞춘다. 원문에 삽입할 박스·밑줄·특정 위치 이후 들여쓰기처럼 기능 요구가 있으면 대상 문자열과 뜻을 설명한다. 호출자가 공백이나 강제 엔터를 반복해 시각적 정렬을 만들어 전달하지 않는다. 반칸까지 미리 입력할 필요는 없다. 제작자가 스킬의 조판 공백을 적용하고, 최종 문자열에서 밑줄·박스 범위를 확인한다. 코드나 공백까지 그대로 보존해야 하는 인용만 그 조건을 명시한다.

지도 지점마다 이름과 수치를 함께 표시할 때는 “A: 위치, 값, 단위”처럼 **같은 항목의 묶음**으로 전달하고, 수치를 작은 상자에 넣을지 등을 지정한다. 자리나 지시선 좌표는 제작자가 정한다. 두 그래프가 같은 계열을 공유하면 선종류·명칭의 대응과 공통 범례 여부를 알려주며, 자료마다 기호를 다시 정의하지 않는다. 이론 그래프에서 절편만으로 개형이 정해지지 않으면 직선·매끄러운 곡선·구간별 연결 중 평가에 필요한 모양을 함께 알려준다.

## 제작과 납품 계약

외피는 신문·웹·칠판에 한정되지 않는다. 책/스프링노트/앨범, 엽서/편지, 접이식 안내장/포스터, 이메일/SNS/휴대기기, 롤스크린·전시판처럼 **사람이 부르는 매체 이름**과 읽을 면의 관계만 알려주면 된다. 예를 들어 “펼친 책 왼쪽은 인용문, 오른쪽은 두 항목 해설”, “접이식 안내장 앞면은 행사 안내, 옆면은 비교표”, “태블릿 안에서 두 사람이 주고받은 메시지”처럼 설명한다. 내부 recipe·좌표·장식 종류를 전부 지정할 필요는 없다. 특정 형태를 보존할 이유가 없으면 “배경은 매체가 자연스럽게 보이는 범위에서 새롭게 구성”이라고 맡긴다.

한 문단이 사진 옆에서 시작해 아래로 이어져야 하는 경우와, 서로 독립된 두 단/두 페이지인 경우는 구별해 알려준다. 분량이 다른 면을 나란히 쓸 때는 “왼쪽은 표지, 오른쪽은 설명과 일정 표”처럼 각 면의 역할과 실제 내용을 준다. 짧은 표지의 여백 배분이나 긴 본문에 맞춘 책 외곽 높이는 제작자가 결정하므로 맞추기용 빈 줄·글자 크기·좌표를 지정할 필요는 없다. 실제 유물·우표·지폐의 모습이 문제 단서이면 대상명/원본 보존 조건을 주고, 새로운 종이 프레임으로 바꾸지 말라고 명시한다. 현재 생성기에 전용 외피가 없더라도 제작자는 지원되는 내용 컴포넌트와 필요한 외피만 결합하며, 자동 재조판이 확인되지 않은 보충 장식까지 연동을 약속하지 않는다.

- 제작자는 최신 스킬의 작업별 지침을 준비해 해당 단계만 읽는다. 설치 버전 숫자만으로 기능을 보장하지 않고 연결 앱의 실제 capability·명령·schema를 확인한다. 상세 도구 사용법은 제작 스킬이 담당하며 호출 문서에 중복하지 않는다.
- 사용자 명시 조건과 필수 보존 원칙을 우선한다. 글꼴·선·폭·원화 화풍의 기본값은 제작 지침의 단일 원본을 따른다. 호출자가 모든 기본값을 반복 입력하거나 앱 기본값과 다르게 고정할 필요는 없다.
- 실제 자료·특정 인물·유물은 필요한 참조를 확인한다. 과거 완성 예시를 찾아 복사하지 않는다. 요청한 원본 재현·동일 인물·승인 지도 양식은 스킬이 허용하는 범위에서 쓴다. 생성 도구가 없는 환경에서 코드 얼굴이나 임시 그림을 완성 원화로 대체하지 않는다.
- 문자·말풍선·표·차트·범례·도형은 편집 가능하게, 원화·사진은 이동/비례 크기/교체 가능한 포함 이미지로 둔다. 그림 전체를 한 래스터로 만든 것을 편집 가능한 원본으로 납품하지 않는다. 원화까지 순수 벡터여야 하는 경우 별도 조건을 준다.
- 기본 납품은 같은 이름의 `.vectora`와 `.jpeg` 한 쌍이다. 지정 이름·폴더·형식이 우선한다. 미지정은 현재 작업 공간, JPEG 4배·회색조·불투명 배경이다. 실제 내용 외곽에 대지를 맞추며 의도된 본문 빈칸/장면 안 공간은 보존한다. 무관한 파일을 덮어쓰거나 지우지 않는다.
- 저장·재열기와 최종 문서에서 내보낸 **실제 JPEG 직접 열람**이 필요하다. 자동 audit/기술 성공과 시각 합격은 별개다. 첫 결과의 명백한 결함은 수정하되 최대 3회 후 정체·도구 한계는 남은 문제로 밝힌다.

## 결과 회수와 내용 수정

인물이 여러 명이면 동일 인물의 반복인지 서로 다른 사람인지 구별해 준다. 그 밖의 식별 특징·같은 화풍·칠판에 맞는 신체 범위는 제작자가 정하므로 호출자가 얼굴 모양이나 크롭 좌표를 설계할 필요는 없다. 빈칸은 “㉠ 뒤에 답란”인지 “㉠을 가운데 두고 양옆에 같은 길이의 밑줄”인지 뜻을 명시한다. 기간의 `t+1기`는 일반 기준선 표기이며 지수와 구별한다. 단독 이론 좌표도의 축 비례와 제목 위치, 작은 웹 아이콘·탭 여백은 제작자가 최종 인쇄 크기로 검수한다.

응답 본문에서 상태, 실제 원본/JPEG 경로, 실측 외곽 크기, 원문·자료·관계 보존, 저장·재열기·시각 검수 결과, 포함 원화 여부, 해당하는 출처/변환과 남은 문제를 받는다. 의뢰 ID가 있으면 함께 반환한다. 별도 검수/응답 파일은 기본 납품에 추가하지 않는다. 미실행·실패를 통과로 보고하지 않는다.

출제자는 JPEG를 문항에 넣기 전에 기호 대응·빈칸·자료 해석·정답 유일성을 확인한다. 그림이 답이나 개념명을 불필요하게 드러내거나 자료 의미를 바꾸면 수정 의뢰한다. `.vectora`는 편집 원본으로 연결하고 두 파일이 같은 상태인지 확인한다.

후속 수정에서 필요한 **연결 범위**도 자연어로 알려준다. “관측값은 나중에 바꾸고 지도 범위도 조정할 거야”처럼 말하면 충분하다. 제작자는 값→도형, 지도 범위→관측 위치, 공통 척도→범례 중 실제 유지되는 관계를 구분해 확인한다. 한 부분의 편집 가능성을 모든 부분의 자동 연동으로 확대하지 않는다. 여러 단계의 설명을 나중에 늘릴 예정이면 “글이 늘어나도 다음 상자와 사이 화살표가 함께 따라오게”처럼 관계를 알려준다. 호출자가 새 높이나 이동량을 계산할 필요는 없다.

특수 모양을 요구하면 그 모양의 의미도 적는다. “항로 길이를 화살표 모양의 막대로 표시”라면 화살촉까지 수량 길이에 포함한다. “이동 방향을 가리키는 화살표”와는 다르다. 실제 수치로 감소율을 계산하게 한다면 해당 값을 인쇄하도록 명시한다. 값 변경 뒤 기본 막대만 늘어나고 보충 화살촉이 남거나, 지도만 바뀌고 관측 기호가 옛 위치에 남는 결과는 완성으로 받지 않는다. 미지원 표현은 제작자가 다시 조판하되, 사용자가 직접 여러 개체를 옮기도록 넘기지 않는다.

같은 값이 표·그래프·지도 수치에 반복되면 “같은 원자료라서 한 번 수정하면 함께 바뀌어야 한다”고 지정한다. 화면에 같은 숫자가 있다는 것만으로 연동을 보장하지 않으며, 제작자가 원자료 한 값을 바꾸어 관련 표시들이 함께 갱신되는지 확인하게 한다.

좌표가 있는 점을 옮길 때는 “소비점을 (70,65)로 옮기고 보조선과 대응 눈금도 따라오게, 기존 경계의 절편은 유지”처럼 변화와 불변 조건을 구별한다. 라벨이 길어졌을 때의 배치·여백은 제작자가 처리하며, 보조선 자동 갱신이 수동 눈금 목록까지 자동 수정한다는 뜻은 아니다.

구성비 수정은 바뀐 항목뿐 아니라 **합계를 유지하는 방법**까지 전달한다. 예: “2000년의 A/B/C를50/20/30으로 바꾸고 다른 연도는 유지.” A만 늘리라고 하면서 총합100도 유지해야 한다면 어느 항목에서 줄일지 정해야 한다. 제작자는 나머지 비율을 임의 변경하지 않는다. 공통 범례는 시점마다 색·순서·이름이 같은 뜻일 때 사용한다.

막대그래프나 흐름 지도는 “정확한 수치를 읽어 계산해야 한다” 또는 “대략적인 대소관계·등급만 비교한다”를 알려주면 수치 라벨·범례·보조선의 표시를 고르기 쉽다. 원자료를 모두 제공해도 모든 값을 그림에 인쇄할 필요는 없다. 필수 수치 표시는 명시하고, 나머지 정렬과 보조선 선택은 제작자에게 맡긴다. 값과 점선이 모두 필요하다고 알려주면 제작자가 작은 흰 배경으로 겹침을 처리하므로, 호출자가 숫자별 좌표를 옮겨 지시할 필요가 없다.

연결 중단·응답 유실은 실제 저장 상태를 확인한 뒤 재개한다. 편집을 무작정 다시 보내거나 체크포인트/진단 미리보기를 완성본으로 보고하지 않는다. 누락 자료·미지원 기능 때문에 완성이 안 되면 필요한 입력과 가능한 범위를 구별해 반환한다. 앱 자체 수정은 별도로 승인된 개발 작업이며 일반 제작자가 임의로 수행하지 않는다.

실제 초상을 넣는 의뢰에서는 인물명과 원본 보존 조건만 주면 제작자가 시선을 안쪽으로 배치한다. 사진 속 문자·사건 방향을 보존해야 하면 반전 금지를 명시한다. 표의 사방 판독 여백, 회색 면의 문자 윤곽, 독립 논증 기호와 화살표의 굵기 균형은 제작자가 검수하므로 호출자가 개별 좌표·효과 두께를 나열할 필요는 없다.
