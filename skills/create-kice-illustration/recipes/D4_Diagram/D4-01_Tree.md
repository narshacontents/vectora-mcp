# D4-01_Tree — 위계도

분류 체계·조직도·삼단논법. 무순환

분류·조직·논리 위계의 부모/자식·단계·가지 수를 보존하고 순환을 만들지 않는다. 같은 위계 노드는 정렬하며 범주를 정형 틀에 맞춰 합치거나 줄이지 않는다. 부모를 잇는 공유 줄기는 실제 공통 분기만 사용한다. 삼단논법은 요청의 논리 관계를 그대로 배치하고 연결이 자동으로 인과나 정답을 뜻하게 하지 않는다.

기본 상자는 각진 직사각형이며, 별도 요청이 있을 때 둥근 모서리를 쓴다. 기본 분기는 원형 접속점 없이 얇은 공통 가로줄과 수직 가지로 표시한다. 같은 단계의 형제는 한 줄부터 배치하며 폭이 부족하면 실제 글 폭·노드 여백·간격을 먼저 조정한다. 불가피하게 여러 줄로 나누더라도 아래 행을 바로 위 형제의 자식으로 오독하지 않게 공통 부모까지의 연결을 명확히 한다. 긴 이름 하나 때문에 모든 단계 간격을 크게 늘리지 않는다.

하위 항목 수가 다른 조직도는 **각 하위 묶음의 실제 폭을 먼저 배분하고 부모를 그 묶음 중심에 놓는다.** 부모만 등간격으로 놓은 뒤 자식을 끼워 맞추지 않는다. 같은 부모의 형제는 가깝게 묶고 다른 부모의 묶음 사이에는 구별되는 일정한 여유를 둔다. 자식이 하나인 가지 앞에 큰 빈칸이 생기거나 연결선이 다른 묶음을 가로지르지 않는지 전체 그림으로 확인한다. 항목을 추가·삭제하면 같은 부모/자식 관계를 유지해 전체 묶음을 다시 배분하며, 빈 노드나 가짜 자식으로 간격을 맞추지 않는다.

현재 도식 계약이 지원하면 단일 부모·인접 단계·각진 상자로 된 조직도는 `layout:"relations"`, `rowLayout:{version:1,xPolicy:"tree",...}`를 우선한다. 단계별 노드와 연결만 선언하고 수동 x좌표는 넣지 않는다. 하위 묶음은 부모 순서대로 연속 배치한다. 항목 추가 때 같은 노드 ID와 소속을 유지하면 실제 묶음 폭으로 다시 조판된다. 계획의 실제 외곽 폭을 확인하고, 지나치게 넓거나 좁아 거부된 폭을 빈 경계상자로 꾸며 맞추지 않는다. 복수 부모·겸임·단계 건너뜀·논증 합류는 이 경로의 지원으로 간주하지 말고 관계도에 맞는 배치를 사용한다.

병렬 전제 사이의 `+`는 두 상자의 실제 안쪽 간격 중앙에, 아래 결론·화살표는 전제군 전체의 실제 중심에 맞춘다. 생성기 원점과 문서 좌표를 혼용하지 않는다. 밑줄 답란은 지원되는 `inlineBlanks:{at,widthMm,underline:true}`를 사용하며 전각 공백·밑줄 문자를 반복해 폭을 흉내 내지 않는다. 지원되지 않으면 편집 가능한 선으로 보충하고 본문 변경과 자동 연동된다고 보고하지 않는다.
