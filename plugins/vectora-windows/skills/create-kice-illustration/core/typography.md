# 편집 가능한 문자와 정확한 입력


## 미지정 시 서체·조판 기본값

- **새 제작 프리셋은 바탕 11.5pt·바탕 10.5pt·돋움 10pt·돋움 8pt 네 가지다.** 연결 앱의 `vectora://capabilities`에 있는 `textProfiles.catalog`에서 영역의 역할에 맞는 등록 스타일(기본 프리셋)을 고른다. 돋움 7pt·9pt·9.5pt·11.5pt 등이 필요하면 돋움 기본 프리셋의 글자 크기를 변형하며 별도 프리셋을 만들지 않는다. 기존 추가 스타일 ID는 문서 호환용이며 새 제작에서 선택하지 않는다. 한 그림 안에서도 본문·제목·표 셀·도해 라벨에 서로 다른 스타일을 쓸 수 있다. 바탕은 실제 **UND v3.1 Batang(UND 3.1 바탕)** 계열을 선택하며, 영문만 별도 Body로 바꾸지 않는다. **UND v3.0 Body는 새 제작에서 사용하지 않는다.**

| 역할 | 선택 기준 |
|---|---|
| 일러스트 라벨·이름·축·범례 | 돋움 8pt를 출발점으로 삼고 원본의 주석·제목 크기 차이를 구별한다. |
| 상자·말풍선·카드의 줄글 | 선택 recipe가 지정한 자료 역할·서체를 먼저 적용한다. 독립 줄글은 돋움 10pt, 도해에 종속된 짧은 설명은 돋움 8pt에서 시작한다. 상자 안이라는 이유만으로 인용문·제시문 등의 서체를 덮어쓰지 않는다. |
| 바탕 본문·진술 | 바탕 11.5pt 기본 프리셋. |
| 표의 머리글·내용·수치 | 돋움 10pt 또는 바탕 10.5pt에서 셀 역할별로 선택하고 혼용을 보존한다. |
| 자료 제목·비정보성 장식 | 해당 역할의 검증된 스타일 또는 명시 부분 서식. 본문에 크기를 강제하지 않는다. |

- 외피가 웹페이지·칠판·말풍선이라는 이유만으로 그 안의 모든 문자를 같은 크기로 만들지 않는다. 독립적으로 읽는 줄글 영역과 도해의 짧은 라벨을 구분한다. `prose` 지침을 읽었다는 사실만으로 서체·크기를 자동 변경하지 말고 실제 자료 역할을 먼저 정한다. 원본 또는 의뢰가 지정한 혼용·굵기·부분 크기를 유지한다.
- 표 스타일은 실제 행·열로 자료를 비교하는 셀에 적용한다. 산문 테두리를 네이티브 1셀 표로 구현했더라도 그 안의 글은 본문 역할이다. 구현 도구의 `kind`만 보고 본문을 표용 크기로 바꾸지 않는다.
- **행간은 비율로 저장한다. 새 글상자와 돋움·바탕 10.5pt 프리셋은 130%, 바탕 11.5pt 프리셋은 150%**다. 프리셋을 선택하면 그 프리셋에 저장된 비율을 적용하고, 글자 크기만 변형하면 현재 비율을 유지한다. 비율은 실제 기준선 간격이며, 130%인 돋움 9pt는 11.7pt다. 사용자가 지정한 비율이나 기존 문서의 명시 서식을 보존하며, 원본별 고정 pt 행간을 새 제작 기본으로 복사하지 않는다.
- 장평·자간은 선택한 앱 프리셋을 측정과 생성에 동일하게 적용한다. **글꼴 모양과 역할별 선택은 2028 예시문항을 우선하고, 여기에 없는 유형만 과거 기출을 보완 근거로 쓴다.** 행간에는 위 사용자 지정 비율을 우선한다. 문항 폭 약108mm를 기준으로 실제 크기를 판단하며, 예전 8pt 정규화 결과를 근거로 삼지 않는다. PDF 직접 추출값과 이미지에서 추정한 값은 구분한다. 제작값은 10pt·10.5pt·11.5pt처럼 쓰기 편하게 정리하고, 장평·자간·행간도 불필요하게 세분화하지 않는다. 소수점 둘째 자리까지 맞추거나 작은 측정 차이마다 새 스타일을 만들 필요는 없다. 반올림한 결과를 실제 인쇄 크기로 대조하며, 줄별 양끝 조판 값과 글꼴 모양 차이를 기본 자간·크기로 오인하지 않는다.
- 앱 catalog가 스타일 ID와 수치의 기준이다. 스킬에 수치 목록을 복제하거나 ID 이름으로 실제 크기를 추론하지 않는다. 적절한 등록 스타일이 없으면 근거 있는 명시 서식을 전달하며, 없는 ID를 만들어 호출하지 않는다. 반복되는 실제 역할 차이가 확인된 경우에만 새 기본 스타일을 제안한다.
- Regular·Bold·Italic·BoldItalic은 선택한 UND v3.1 계열의 실제 설치 면을 사용한다. 누락된 면은 안내하고 임의 폰트 대체나 합성 굵게/기울임으로 숨기지 않는다.
- 측정과 생성에 **선택한 문자 역할의 같은 장평**을 적용한다. 글자 속성을 사용하며 그룹의 가로 Scale로 대신하지 않는다. 설치 앱이 아직 새 면·장평을 지원하지 않으면 차이를 밝히고 구형 결과를 새 폰트 검증으로 보고하지 않는다. 기존 문서의 명시적 서식은 요청 없이 소급 변경하지 않는다.

## 필수 보존과 조건부 조판

원문을 전달했다는 사실만으로 문자 코드·공백까지 고정한 요청으로 해석하지 않는다. 문구와 기호의 뜻은 유지하면서 아래의 목록표 선택·반칸·부분 서식 규칙을 적용한다. “문자 코드와 공백을 그대로 보존”처럼 명시한 경우에만 해당 조판의 예외로 둔다.

- 기간 표기 `t+1기`, `t+2기`의 `+1`, `+2`는 지수가 아니다. 같은 기준선·본문 크기의 일반 문자로 두고 이항 연산자 반칸 규칙을 적용한다. 원문에 없는 위첨자 유니코드나 `script:super`를 추가하지 않는다. 실제 거듭제곱·각주 등 명시된 위첨자는 보존한다.

- **알파벳이 대상을 가리키는 이름표이고 뒤에 종류·명사가 이어지면 사이에 Vectora Alt+Space 반칸 `U+2002` 하나를 둔다:** `A 지역`, `B 지역`, `A 펀드`, `B 주식`. 제목·본문·발언·표·그래프·지도 라벨 모두 측정 전에 적용한다. 기존 일반 공백은 반칸으로 바꾸되 중복하지 않고, `A에서는` 같은 조사 결합이나 영어 단어·고유명 내부·코드·수식 변수 사이를 임의로 띄우지 않는다. 문자 코드/공백 보존을 명시한 요청은 예외이며, 허용된 삽입 뒤 부분 서식 범위는 최종 문자열 기준으로 다시 계산한다.

- **돋움 문맥의 기호는 UND v3.1, 바탕 문맥의 기호는 UND v3.1 Batang에서 2028 원본에 가까운 모양을 쓴다.** 마침표·쉼표·콜론·따옴표를 두 서체 모두 한쪽으로 통일하지 않는다. 예시문항에 없는 기호도 **돋움 기본·돋움 본문용·바탕** 중 해당 역할을 유지하고, 그 안에서 가장 가까운 검증 계열(문장부호·괄호/인용·수학·주석·도형 기호)을 따른다. 짝 기호와 반복 기호의 획·크기·기준선을 함께 확인하며, 낯선 기호 하나만 다른 계열로 바꾸지 않는다. 실제 원본 확인과 같은 계열에 따른 기본 선택은 구분한다. 원문자·도형 표식·수학 연산자는 본문에 등장하더라도 의미에 맞는 고유 모양을 보존하고, 같은 기호가 아닌 물결·동치·범위 표시를 눈대중으로 치환하지 않는다. 최신 수동 설치용 8개 면에 반영된 보정을 우선하고 제작 중 임의 폰트 이식·전체 문자 치환은 하지 않는다. 두 후보 모두 원본과 다른 모양이면 일치한다고 주장하거나 왜곡해 맞추지 말고 차이를 알린다. 차트의 회색 표식·패턴·비례 원은 글꼴 기호로 대체하지 않는다.
- **문단 목록표를 제외한 일러스트의 표시 문자(본문·발언·제목·자료명·매체명 등)에서 `○`, `△`, `□`, `☆` 뒤에 설명이나 이름이 이어지면**, 반복 기호는 `○○`·`△△`·`□□`·`☆☆`처럼 사이를 띄우지 않고 한 덩어리로 유지하고, 덩어리 뒤에만 Vectora Alt+Space 반칸 `U+2002` 하나를 둔다. 반칸은 일반 공백 폭의 절반으로 고정되며 인접 자간에서 제외된다. 원문을 제공했거나 따옴표로 표시했다는 사실만으로 이 반칸 규칙의 예외가 되지 않으며, 문자 코드/공백을 그대로 보존하라고 명시한 경우에만 예외로 둔다. 원 기호 코드와 기존 사용자 지정 문자·공백 예외를 보존하며, 차트·도식 표식과 수식의 문자 그대로 표기에는 강제하지 않는다.
- 제목·자료명의 좁은 꺾쇠와 수학의 넓은 부등호를 구별한다. 원문이 ASCII `< >`인 제목은 지원 앱의 **평가원 제목 괄호** 서식을 해당 괄호에만 적용하고 원문 코드는 보존한다. 이 서식은 돋움·바탕과 각 실제 굵기/기울임에서 같은 계열의 제목 글리프를 선택한다. 수식 `< >`, URL·코드에는 적용하지 않는다. 기본 글꼴과 본문용 숫자·기호는 실제 자료 역할로 구별하고, 눈대중으로 전각 문자·다른 기호·별도 글상자로 원문을 바꾸지 않는다. 그래프·지도·표의 수치와 축·범례·짧은 라벨은 기본 모양을 사용한다. 긴 줄글의 본문용 선택은 `prose` 지침을 따른다.
- 문단 머리의 **작은 빈 원 목록표는 `￮`(U+FFEE)**를 사용한다. 돋움·바탕 모두 현재 문단 서체·크기를 유지하며 같은 글상자에 넣는다. 큰 도형 기호 `○`(U+25CB)는 글자 높이에 가까워 목록표를 대신하면 과도하게 커진다. `◦`(U+25E6)·수학 합성 기호 `∘`로 임의 대체하거나 별도 글상자로 작게 만들지 않는다. 채운 목록 점을 요청하면 `•`(U+2022)를 사용한다. 인명·기관의 빈칸 `○○`, 정오 판단이나 도형 자체를 뜻하는 `○`는 그대로 유지하고, 문자 코드 보존을 명시한 원문에는 이 기본 선택을 강제하지 않는다. 목록표 뒤에는 해당 문단의 정상 간격 하나를 쓰며 반복 공백으로 본문 시작을 맞추지 않는다.

- 선택한 스타일의 실제 pt를 유지한다. 사용자 명시 서식, 원본 재현에서 확인한 부분 서식, 선택 지침에서 허용한 **비정보성 장식 문자**의 크기 예외는 해당 범위에만 적용한다. 본문·수치의 선택 규격을 공간 부족 때문에 축소하지 않는다. 제목·장식 크기는 역할과 위계에 맞게 설계하고, 결정한 서식을 폭 변경·재열기 후에도 보존한다.

- 요청된 전체·부분 굵은 글씨는 native 문자 서식과 선택한 UND 계열의 실제 Bold/BoldItalic 면으로 유지하고, 자동 Regular 기본값으로 덮어쓰지 않는다. 저장된 style provenance가 `explicit`인지 확인하고 결과의 실제 face를 검수한다. KICE audit의 자동 결과와 명시 서식은 별도로 대조한다.

- 폰트 바이너리는 그림·스킬에 임베드하지 않는다. 검증된 전용 글리프 변환 외에는 폰트·면을 조용히 대체하지 않는다. 기존 문서의 서체·자간은 요청 없이 바꾸지 않는다.

- ⓪가 필요하면 원문자 상용구 단축키를 사용할 수 있다. 일반 수치 0을 자동으로 치환하지 않으며 실제 출력 문자의 지원 여부를 현재 설치 면에서 확인한다. 예전 폰트의 누락 목록을 새 폰트의 지원 여부로 단정하지 않는다.

- **한 텍스트 덩어리는 반드시 하나의 편집 가능한 글상자**로 만든다. 발언·본문·셀·라벨의 자동 줄바꿈/명시 개행과 글꼴·강조·밑줄 범위 서식을 그 안에 유지한다. 줄별 글상자나 이를 묶은 그룹으로 대체하지 않는다. 제목/본문·서로 다른 발언/셀 등 독립된 내용만 나눈다.

- 제공된 전체 본문은 생략하지 않는다. 전사한 시각적 행 끝은 엔터로 고정하지 말고 지정 폭에서 자연 줄바꿈한다. 실제 문단·목록·명시 개행은 보존한다. 어절 중간 분리나 짧은 끝줄을 자동으로 오류 판정하지 말고 아래 줄별 실측 조판 규칙으로 해결한다.

**줄별 실측·자간 조판:** 새 조판 또는 조판 수정에서는 한 텍스트 프레임 안의 각 실제 렌더링 줄을 지정 폭, 실제 글꼴·범위 서식, 선택한 문자 프로필의 실제 pt·장평·자간에서 측정한다. 어절 경계가 어색하거나 끝 음절이 홀로 남으면 앞선 줄들의 자간을 서로 다르게 소폭 압축·확장해 자연스러운 어절 경계를 찾을 수 있다. 다만 ‘보자.’처럼 짧더라도 완결된 마지막 어절은 허용하며, 그것만 짧다는 이유로 앞선 줄의 자간을 조정하지 않는다. 한 프레임 안에서 줄마다 자간이 달라도 되며, 자간을 고정된 일률 값으로 강제하지 않는다. 마지막 줄 자체를 채우도록 벌리지 않고, 실제 짧은 문단과 자연스러운 끝줄의 오른쪽 여백은 보존한다. 폭이나 본문이 바뀌면 다시 측정·조판되는 편집 가능한 경로를 사용한다.

이 조정은 별도 글상자, 강제 엔터, 가짜 공백, 글자 크기 축소, 말풍선 폭 축소로 대신하지 않는다. 숫자 범위와 native `inlinebox`는 분리 불가 단위로 유지한다. 원문 내용·의미·문단·기호 코드는 보존하되, 이 문서에 명시된 조판 공백 규칙을 적용한다. 사용자가 문자 코드 또는 원문 공백을 그대로 보존하라고 명시한 경우와 URL·코드는 예외이며, 전역 Unicode 정규화는 하지 않는다. 허용된 공백 조정으로 문자열 위치가 바뀌면 스타일 run·밑줄·native `inlinebox` 인덱스를 최종 문자열의 grapheme 기준으로 다시 계산한다. 산문이 들어간 표 셀에도 같은 규칙을 적용한다. 정상적인 자간 조정으로도 긴 비분리 단어가 들어가지 않으면 과도한 자간이나 글자 겹침으로 강제하지 말고 안전한 기존 줄바꿈 처리를 유지한다.

**원문자가 뒤의 밑줄 본문을 지칭하는 표지일 때, 원문자 뒤 밑줄 앞은 Vectora Alt+Space 반칸** `U+2002` 한 개로 `㉠ 본문`처럼 저장한다. MCP도 같은 실제 문자를 넣는다. 앱이 일반 공백 폭의 절반으로 고정하고 양쪽 자간을 배제하므로 폰트 em 폭으로 추정하거나 일반/전각/중복 공백·별도 글상자로 대체하지 않는다. 이 경우 원문자와 반칸은 밑줄 범위에서 제외한다. **원문자가 답란 가운데 들어가는 밑줄 빈칸은 별개**이며, 양옆 같은 수의 공백과 원문자를 한 줄에 넣고 전체에 밑줄을 적용한다. 삽입 뒤 실제 문자열로 textRange/underlines 위치를 다시 계산하고 재조판·재열기에서 공백과 범위를 확인한다.

일반 문구의 “원문 유지”는 아래의 조판 공백을 생략하라는 뜻이 아니다. 공백·문자 코드까지 그대로 보존하라는 명시 요청이나 URL·코드의 구문만 예외로 둔다.

**자료 아래 각주:** 원문 뜻을 유지하면서 각주 순서에 따라 ASCII `*`, `**`, `***`를 쓰고, 표지 뒤에 Vectora Alt+Space 반칸 `U+2002` 하나를 둔다. 각주 N개 중 i번째(1부터)는 표지 앞에 반칸을 `3 × (N−i)`개 넣는다. 1개이면 0개, 2개이면 3·0개, 3개이면 6·3·0개다. 실제 줄바꿈 수가 아니라 **각주 항목 수**를 센다. 한 편집 가능한 글상자 안에서 항목별 문단으로 만들며, 긴 각주의 자동 다음 줄은 본문 시작 열에 맞춘다. 지정한 반칸 개수는 유지하고, 서체의 별표 폭 때문에 미세하게 어긋나면 접두부를 실측한 공통 본문 열(`paragraphLayouts.prefix`)로 맞춘다. 이 각주용 반칸은 반복 공백 정렬 금지의 예외다. 자료 출처 행은 각주와 구분하며 요청되지 않은 각주 내용을 덧붙이지 않는다.

**표시용 콜론 `:`은 설명·라벨에서 앞에 Alt+Space 반칸 `U+2002`, 뒤에 일반 한 칸 `U+0020`을 둔다:** `주제 : 비교 우위`. **시간·비율의 콜론은 양쪽 모두 반칸**으로 `12 : 30`, `1 : 2`처럼 쓴다. 기존 주변 공백은 중복하지 않으며 URL·코드 구문은 바꾸지 않는다. 중첩 자료의 표시 문자열까지 측정 전에 간격을 확정하고 최종 문자열 기준으로 부분 서식 범위를 계산한다.

**표시용 이항 연산자 곱하기 `×`, 더하기 `+`, 등호 `=`, 빼기 `−`(원문이 `-`이면 그 코드 유지)의 좌우에는 각각 Alt+Space 반칸 `U+2002` 한 개를 둔다:** `A + B = C`, `수익률 × 100`, `10 − 3`. 본문·수식·표 셀·그래프 주석에도 적용하며 일반/전각/중복 공백으로 대신하지 않는다. 음수·양수의 부호(`−5`, `+3`), 날짜·범위·식별자의 하이픈, URL·코드는 연산자와 구별한다. 복합 기호나 다른 연산자를 쪼개거나 바꾸지 않는다. 원문 공백·코드의 정확 보존을 명시한 경우는 예외이며, 나머지는 측정 전에 간격을 확정하고 최종 문자열로 부분 서식 인덱스를 다시 계산한다.

자료 식별 `(가)`~`(하)`는 두 서체 모두 원문 그대로 입력·저장한다. **UND v3.1 Main에서만 문맥에 따른 전용 고정 글리프 표시를 사용하고, Batang에서는 괄호·한글·괄호의 세 문자 그대로 표시한다.** 이 명시된 Main의 자동 표시 경로는 임의 글꼴 대체 금지의 예외이며, 제작자가 느낌표·골뱅이·샵·달러·PUA로 원문을 치환하지 않는다. 누락 글리프는 실제 지원과 렌더러 표시 경로를 확인하고, 위의 검증된 글리프 대치 원칙을 적용한다. 여전히 미지원이면 원문 코드를 보존한 채 차이를 기록하고, 사용자 요청 없는 유사 문자 치환으로 숨기지 않는다. 원문이 요구하는 괄호를 폰트로 표시할 수 없는 경우에는 괄호만 벡터 선으로 두고 안 문자는 편집 가능하게 유지한다.

괄호는 저장할 **문자 코드부터** 확인한다. 일반 입력·이미지 전사의 보통 괄호는 ASCII `() [] {} <>`를 쓰며, 모양만 보고 `（ ）〔 〕〈 〉` 같은 전각/CJK 괄호로 바꾸지 않는다. 명시된 원문 코드와 책명/인용의 `「」『』`는 보존한다. 틈이 이상하면 문자 코드·숨은 공백·서체/범위와 글리프 자체의 폭·좌우 여백을 구분해 확인하고 같은 조건의 일반 입력과 비교한다. 전체 Unicode 정규화·공백 삭제·문장 분리·문단 전체 자간 축소로 숨기지 않는다.
